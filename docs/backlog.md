# BlogGenius Backlog

## 제안 우선순위 (0.2.0 이후)

1. **개발 기반 정비** — 완료 (2026-08-22)
   - backlog와 active plan을 현재 구현 상태에 맞춘다.
   - 새 `*.test.js`가 릴리스 검증에 자동 포함되도록 테스트 실행 구조를 정리한다.
   - 완료된 설계는 archive/canonical 문서로 이동한다.
2. **오늘의 성과·이어서 하기**
   - activity/memory event에서 오늘의 성과와 미완료 작업을 파생한다.
   - 이미 완료된 단계와 안전하게 재개할 수 있는 다음 행동을 구분한다.
3. **발행 준비 상태 점검**
   - 로그인, 시트, AI 모델, 필수 설정과 발행 대상을 한 번에 진단한다.
   - 경고에서 끝내지 않고 해결 화면이나 capability로 연결한다.
4. **Internal API 통합**
   - Telegram legacy 등록·발행 분기를 canonical request/capability 경로로 통합한다.
   - UI, MCP와 Telegram이 같은 preview/confirmation/result 계약을 사용하게 한다.
5. **UI 모듈 분리**
   - `ui/app.js`를 quick discovery, settings, publishing, SNS 등 기능 controller로 분리한다.
   - 기존 `ui-runtime` 경계를 유지하고 전면 재작성은 피한다.
6. **Remote MCP 고도화**
   - 내부 실행 계약 정리 후 인증, 재연결, confirmation 복구와 tool surface를 확장한다.
7. **구독·결제 기반**
   - 수익화 우선순위가 확정되면 provider-neutral subscription/entitlement 경계를 구현한다.

## 0.2.0에서 완료되거나 대체된 항목

- 기본 실행을 Electron UI로 전환하고 CLI 웹 UI도 브라우저 자동 열기와 `--no-open`을 지원했다.
- `LISTEN_HOST`/`LISTEN_PORT`를 설정 UI와 실행 인자에서 지원했다. 포트 충돌 자동 대체 UX는 남아 있다.
- Trends/Topics/Shopping 목록에 limit/offset 기반 페이지 이동을 적용했다.
- 개인화 글감 추천, 근거 표시, 저장·선택·발행 outcome 학습과 네이버 트렌드 결합을 출시했다.

## P1 (다음 스프린트 우선)

1. 블로그 테이블 텍스트 컬럼 inline edit 고도화
- 현재 inline edit 안정화
- 저장/실패 메시지 미세 조정
- 진행 중(row runtime log 존재) 편집 잠금 유지

2. 실행 로그/최근 실행 표시 UX 정리
- 새 배치 시작 시 이전 runtime 상태 초기화(적용됨)
- 결과 요약 카드 유지 방식(필요 시 이력 탭으로 이전)

3. 최초 설치 UX 다듬기
- Dashboard 라이선스 오류 시 전체 패널이 동시에 오류처럼 보이지 않도록 부분 상태 표시 강화
- 테스트 플랜 소진/재사용 불가 메시지에 다음 행동(라이선스 화면 업그레이드) 안내를 명확히 표시
- 설정 화면 초기값(sample placeholder)로 인한 버튼 오동작(구글 시트 열기) 방지
- 설정 화면에서 Gemini API 키 발급 경로를 즉시 확인할 수 있는 도움 링크 제공

4. UI 포트 충돌 복구
- 설정한 포트가 사용 중이면 원인과 현재 점유 상태를 안내한다.
- 사용자가 확인할 수 있는 대체 포트 재시도 흐름을 제공한다.

## P2 (중기)

1. 모바일 UI 최적화
- 테이블/액션바 터치 UX 개선
- 화면 폭이 좁을 때 컬럼 축약/카드형 전환 검토

2. 네트워크 바인딩 확장
- 기본 `127.0.0.1` 유지
- 옵션으로 `0.0.0.0` 지원(로컬 네트워크 접근)
- 보안 안내(토큰/방화벽) 문서화

3. 설정 UI (환경설정)
- `config.json` 전체 노출 대신 “주요 항목”만 입력하는 설정 화면 제공
- 고급 항목은 “고급 설정” 섹션으로 분리
- 저장 시 유효성 검사(필수값/URL/숫자 범위) 적용

4. 네이버 로그인 UX
- UI에서 `로그인 시작` 버튼 제공
- 로그인 진행 상태/완료 상태를 UI에 명확히 표시
- 세션 만료 시 재로그인 유도 메시지 표준화

5. 쇼핑 이미지 소스 입력 UX
- FTC/CTA 이미지를 `https://` URL 뿐 아니라 로컬 파일도 지원
- UI에서 이미지 업로드/선택 후 `config/` 하위에 저장해서 재사용
- 설정값은 URL/로컬 경로 모두 허용(하위 로직에서 자동 판별)

6. UI 팝업 통일
- `alert` 기반 팝업을 앱 내부 모달 컴포넌트로 교체
- 에러/안내/확인 팝업 스타일 및 동작(닫기/확인)을 일관화
- 모바일 화면에서도 가독성/터치 UX가 유지되도록 반응형 적용
- 네이버 로그인 시작 시 현재 차단형 팝업(`alert`) 제거/개선
- 상태 영역 내 비차단 안내(토스트/인라인 배너) 우선 적용 검토

7. 블로그 탭 검색 고도화
- Trends/Keywords/Topics에 공통 검색 UX 통일 (상태 + 자유검색)
- Enter 검색/필터 변경 즉시 반영 동작 표준화
- 검색 조건 유지(탭 이동 후 복귀 시 상태 복원) 적용 검토

8. Trends 날짜 선택 UX 개선
- 현재 텍스트 입력 방식(`YYYYMMDD`, `YYYY-MM-DD`, `-1d`)을 달력 UI 중심으로 개선
- 달력에서 날짜 직접 선택 + `어제` 빠른 선택 제공
- 사용자 확인 팝업 문구와 선택 날짜 표시를 UI/UX 관점에서 일관화
- 기본 기능 안정화 이후(후순위) 적용

9. 쇼핑 빠른발행 미리보기 재도입(재설계)
- 현재는 spec-out 상태 유지(자동 미리보기 호출 제거)
- 재도입 시 자동 blur 트리거 대신 `미리보기` 수동 버튼 방식으로 제한
- 내부 해석은 headless 기반으로만 수행(사용자 브라우저 팝업/포커스 영향 없음)
- 미리보기 실패는 비치명 처리(발행 흐름 차단 금지)
- 결과는 썸네일 중심 카드형(직사각형)으로 간결하게 표시

10. 오늘의 성과와 이어서 하기
- 오늘 저장·발행·등록한 작업을 짧게 요약
- 중단된 작업이 있으면 사용자가 마지막 상태에서 바로 이어갈 수 있는 진입점 제공

11. 발행 준비 상태 점검
- 로그인, 시트 연결, 필수 설정, 발행 대상 상태를 한 번에 확인
- 문제를 단순 경고로 끝내지 않고 사용자가 바로 해결할 수 있는 다음 행동과 연결

12. 실패·미완료 작업 구조화
- 최근 실패·중단 작업을 원인과 함께 모아 재시도 가능하게 제공
- 단순 로그 복제가 아니라 재시도 가능한 조건과 이미 완료된 단계를 구분

13. 통합 명령 팔레트
- 메뉴 탐색 없이 주요 화면 이동과 자주 쓰는 작업을 검색·실행
- 기존 capability와 안전한 UI action만 노출하고 별도 실행 로직을 중복 구현하지 않음

## P3 (후순위)

1. 자체 데스크톱 셸 검토
- 웹 UI 유지 + 로컬 셸(Tauri/Electron) 래핑 가능성 검토
- 배포/업데이트/보안 비용 비교 후 결정

2. 글쓰기 스트릭
- 연속 활동일을 가볍게 보여주되 점수·배지 중심의 과도한 게임화는 피함
- 저장 또는 발행처럼 의미 있는 완료 이벤트만 집계

3. 계절·시간대 분위기 확장
- 기존 시계·타이머와 연결되는 소규모 시각 변화로 한정
- 전체 테마 편집기나 무거운 커스터마이징 시스템으로 확장하지 않음
