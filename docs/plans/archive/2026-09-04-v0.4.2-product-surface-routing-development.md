## 사용자 필요와 목표

새 대시보드의 `새로운 발견`에서 소재를 적용할 때 기존 블로그가 아니라 새 블로그로 이동하도록 고친다. 릴리즈 전 기존 블로그 메뉴는 숨기고 새 대시보드와 새 블로그를 정식 사용자 화면으로 표시한다.

## 범위

- `blog.quick` 추천 presentation을 `view-blog-next` quick 입력 화면으로 연결
- 추천 소재를 `blog-next-subject` 입력란에 전달
- 기존 블로그 사이드바 메뉴 숨김과 접근성 탐색 제외
- 새 블로그 사용자 노출 명칭을 `블로그`로 변경하고 `new` 표시 유지
- 현재 대시보드에 `new` 표시 추가
- 모바일 기본 블로그 진입을 새 블로그로 전환
- 관련 사용자 노출 문구와 자동 UI 회귀 테스트 정리
- 대시보드 시각 계층 개선
- Electron 파일 메뉴의 `새 글 작성` 진입 추가

## 명시적 비범위

- legacy 블로그 DOM·스크립트 삭제
- 내부 view ID 또는 파일명 변경
- 새 블로그에 없는 legacy 하위 탭의 대규모 재설계
- 버전 변경과 릴리즈 배포
- 전역 키보드 단축키와 Electron runtime 업그레이드

## 설계와 경계

- UI route `blog-next`를 정식 블로그 화면의 내부 식별자로 계속 사용한다.
- 기존 `blog` view는 참조용 코드로 남겨 두되 사이드바와 모바일 기본 동선에서는 접근시키지 않는다.
- 추천 action의 저장 계약인 `blog.quick`을 깨지 않고 presentation adapter에서 새 화면으로 해석한다.
- `new` 표시는 기존 badge 컴포넌트를 재사용한다.

## 구현 단계

1. 현재 모든 사용자 블로그 진입 지점을 분류한다.
2. 메뉴와 사용자 노출 명칭을 승격한다.
3. 추천 적용 및 모바일 진입을 새 블로그로 연결한다.
4. contract test와 browser smoke로 회귀를 검증한다.
5. 대시보드의 첫 행동과 카드 시각 계층을 보강하고 Electron 메뉴에서 같은 빠른 생성 action을 재사용한다.

## 사용자와 결정한 사항

- 기존 블로그는 UI에서만 숨기며 코드는 삭제하지 않는다.
- 새 대시보드와 새 블로그에 `new` 표시를 둔다.
- Blog Beta는 사용자에게 `블로그`로 표시한다.
- UI 확인은 사용자가 수행한다.
- 단축키와 Electron 업그레이드는 이번 단계에서 제외하고 backlog에서 별도 작업한다.
- 대시보드 상단 `바로 생성`은 배치가 자연스럽지 않아 사용자 확인 후 제거하고 후속 기획으로 돌렸다.

## 현재 결과와 검증

- Dashboard `새로운 발견`의 `blog.quick` presentation이 `blog-next` quick 화면으로 이동하고 추천 query를 `blog-next-subject`에 입력하도록 교정했다.
- legacy 블로그 사이드바 메뉴를 `hidden`, `aria-hidden`, `tabindex=-1`로 사용자 탐색에서 제외했으며 화면과 구현 코드는 보존했다.
- 새 블로그의 메뉴·화면 제목·탭 접근성 명칭과 사용자 오류 문구에서 Beta 표현을 제거했다.
- 현재 대시보드와 새 블로그 메뉴에 동일한 접근 가능한 `new` badge를 표시했다.
- 모바일 quick mode에서 legacy 블로그 대신 새 블로그 quick 화면이 기본 진입점이 되며, 새 블로그 메뉴는 숨기지 않도록 수정했다.
- canonical 연속 발행 문서의 정식 사용자 명칭과 legacy 보존 방침을 현행화했다.
- focused UI·service contract tests 75건 통과.
- browser UI smoke test 통과(190 fixture requests). 추천 소재 전달, 메뉴 숨김·명칭·badge, 모바일 새 블로그 진입을 검증했다.
- 실제 앱의 시각적 배치와 클릭 감각은 사용자 UI 확인 대상으로 남겼다.
- 대시보드 제목 영역을 절제된 hero 카드로 정리하고 연결 상태·성과 카드의 색상 대비와 그림자를 보강해 정보 계층을 분명히 했다.
- 대시보드 상단 `바로 생성`은 실제 배치 확인 결과 제거했으며, 별도 진입 UX를 추후 다시 기획한다.
- Electron 파일 메뉴에 단축키 없는 `새 글 작성`을 추가했으며 새 블로그 quick tab의 AI 입력 모드 및 주제 입력 초점까지 한 번에 연결한다.
- 전역 단축키와 Electron runtime 업그레이드를 `docs/backlog.md`의 별도 P1 작업으로 기록했다.
- CTA 제거 후 focused UI contract tests 20건 통과.
- CTA 제거 후 browser UI smoke test 통과(191 fixture requests). native 메뉴가 사용하는 공용 새 글 작성 action의 화면·입력 모드·초점 전환을 검증했다.
- parent 병합 전 전체 단위 테스트는 1,314건 중 1,313건이 통과했다. 실패 1건은 base와 동일한 `ui/styles/features/continuous-publishing.css` 905줄에 대한 기존 모듈 길이 제한이며 이 sub-FB는 해당 파일을 변경하지 않았다.

## 남은 위험 및 후속 작업

- 구 화면을 직접 호출하는 개발자용 또는 legacy 내부 경로는 코드 보존 목적상 남을 수 있다.
- 저장된 추천 계약의 `blog.quick` 명칭은 호환성을 위해 유지하며 UI presentation 단계에서 새 블로그로 해석한다.
- Electron native 메뉴의 실제 macOS 표시와 대시보드 시각 균형은 사용자 수동 UI 확인이 필요하다.
- 사용자가 대시보드 시각 개선을 확인했고, 상단 `바로 생성`은 자연스럽지 않다는 판단에 따라 제거했다.
- 최초 설치 준비 안내 고도화는 별도 2단계 sub-FB로 분리한다.
