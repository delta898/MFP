# v0.4.3 Card News Stage 12 Ledger UI

## Branch

- Branch: `codex/feat/v0.4.3-card-news-12-ledger-ui`
- Base/parent: `codex/feat/v0.4.3-card-news-main`
- Start date: 2026-09-05
- Status: complete

## User Need

Users need to distinguish unprocessed, created, and published Card News items; avoid repeatedly seeing already-published source articles in the creation list; revisit locally generated originals; and open published channel links.

## Goal and Scope

- Separate the existing creation flow from a compact management view within Card News using `새 카드뉴스` and `만든 카드뉴스` tabs.
- Show only rows with a `generation_id` in the management view.
- Default the creation source list to items that have not completed publishing.
- Show clear workflow and publishing badges from the ledger.
- Allow a managed row to reopen a locally available generation result.
- Expose recorded public channel links for published rows.
- Keep direct URL and direct-text items visible after their first successful composition.

## Explicit Non-goals

- No background scheduler or automatic publication.
- No ZIP import.
- No remote image archive or Google Drive browser.
- No migration of historical development-only Card News results.

## Decisions Made with the User

- Keep the existing RSS selection and creation path under `새 카드뉴스`; the management view must not duplicate unstarted RSS candidates.
- Use four user-facing management states: `작업 중`, `발행 대기`, `발행 완료`, and `확인 필요`.
- Hide fully published RSS items from the creation list by default and provide a small `발행 완료 포함` option.
- Reopen a local generation for image completion, download, and publishing. Composition regeneration is hidden on this re-entry path because the original full source snapshot is not retained in the public generation manifest.
- When a Sheet row remains but the local generation folder is absent, preserve the row and external links and show `로컬 결과 없음`.

## Implementation Result

- Added ledger-backed management listing and individual generation reload API boundaries.
- Decorated configured RSS articles with their existing ledger state without overwriting Sheet-managed rows.
- Kept same-session source annotations current after composition, image, and publishing updates while retaining the one-time RSS registration optimization.
- Added creation/management tabs, compact status filters, safe original/public link actions, and local-result availability handling.
- Split oversized Card News JavaScript and CSS into bounded source/management/result modules.
