# v0.4.3 Card News Stage 15 Google Drive Publishing Transport

## Branch

- Branch: `codex/feat/v0.4.3-card-news-15-drive-publishing`
- Base/parent branch: `codex/feat/v0.4.3-card-news-main`
- Start date: 2026-09-05
- Status: complete; ready for parent integration

## User Need

Card News SNS publication currently depends on a configured WordPress site because WordPress temporary media provides the public image URLs consumed by Buffer. Users who do not use WordPress should still be able to publish completed Card News sets through their existing Google connection.

## Goal

Replace the Card News-specific WordPress temporary-media transport with Google Drive files created and controlled by BlogGenius, while preserving ordered multi-image Buffer publication, terminal result confirmation, and safe cleanup.

## Scope

- Reuse the existing Google OAuth `drive.file` authorization boundary.
- Upload every completed Card News image to Google Drive in card order.
- Grant anonymous read-only access and resolve a direct HTTPS content URL for Buffer.
- Keep the files available until Buffer reaches a terminal publication result.
- Remove temporary Drive files after terminal success or failure using best-effort cleanup.
- Preserve channel preflight, caption editing, per-channel result links, and ledger synchronization.
- Report missing Google authorization separately from Buffer or publication failures.

## Explicit Non-goals

- Changing the existing general SNS local-image path; that is the next independently reviewable stage.
- Adding multi-image selection to the existing general SNS UI.
- Scheduling or automatic publication.
- Permanent Drive archival or a user-facing Drive file browser.
- Falling back silently to WordPress when Drive is unavailable.
- Running another live SNS publication without explicit user approval.

## Evidence and Decisions

- Stage 08 already verified the complete transport hypothesis in Development: a real PNG was uploaded with the existing `drive.file` scope, shared as `anyone:reader`, fetched anonymously as `image/png`, accepted by Buffer, and published successfully to Threads.
- The temporary Drive file was deleted after Buffer reported the terminal `sent` state.
- The earlier failure with a synthetic 100×100 image was isolated to the test asset or its media characteristics rather than Google Drive or the Threads channel.
- This stage therefore implements the already-proven transport rather than repeating the live proof.

## Proposed Design

1. Introduce a narrow, provider-neutral public-media transport contract for ordered local assets.
2. Implement a Google Drive transport using the existing OAuth client and least-privilege `drive.file` scope.
3. Have Card News publishing request public assets from that transport instead of calling WordPress media APIs.
4. Preserve the returned cleanup handles separately from public URLs.
5. Run cleanup only after Buffer returns terminal outcomes; cleanup failure is logged and does not erase a successful publication result.
6. Keep the last valid local Card News generation and ledger state if Drive or Buffer fails.
