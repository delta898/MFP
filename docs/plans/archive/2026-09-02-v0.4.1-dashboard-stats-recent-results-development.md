## 사용자 필요와 목표

Dashboard Beta에서 단순 대기열 상태뿐 아니라 사용자가 BlogGenius로 실제로 처리한 양과 공개 발행한 양을 구분해 확인한다. 오늘과 이번 주의 플랫폼별 성공 결과를 신뢰할 수 있는 이벤트에서 집계하고, 최근 성공 결과를 간결하게 보여줘 작업 결과를 다시 확인할 수 있게 한다.

## 범위

- 로컬 앱 시간대를 기준으로 오늘과 이번 주(월요일 시작) 기간 경계 계산
- 플랫폼별 성공 이벤트에서 `처리 완료`와 `공개 발행` 집계
- Dashboard Overview와 분리된 bounded 통계 read model/API
- 최근 성공 결과의 제목, 플랫폼, 처리 방식, 시각, 결과 링크 반환
- Dashboard Beta 통계 및 최근 결과 UI
- 독립 로딩·빈 상태·실패 상태와 focused/browser 검증

## 명시적 비범위

- 최근 30일 통계와 추이 차트
- 과거 Sheet 행을 이용한 이벤트 backfill
- 플랫폼에서 사용자가 나중에 직접 공개한 상태의 추정
- 조회수, 방문자, 검색 순위 등 외부 분석 통계
- 제작자 콘텐츠와 기존 Dashboard 정리
- release, version, push 또는 배포

## 제안 설계

- 집계 원본은 owner-scoped `activity.lifecycle.blog.*` 성공 이벤트로 한정한다.
- `drafted`, `scheduled`, `published`는 모두 처리 완료이며 `published`만 공개 발행이다.
- 동일 evidence id는 저장 단계에서 멱등 처리되므로 통계에서 재시도를 별도 건으로 세지 않는다.
- 기간 경계는 실행 중인 앱의 로컬 시간대를 사용해 사용자가 보는 날짜와 맞춘다.
- 통계 API는 오늘·이번 주 집계와 최근 결과의 작은 allowlist만 반환한다.
- 최근 결과는 최대 5건으로 제한하고 결과 URL이 있을 때만 외부 이동을 제공한다.
- 계정 연결 조회나 운영 Overview 실패가 통계 영역까지 막지 않도록 독립 조회·표시한다.

## 사용자와 결정한 사항

- `처리 완료`와 `공개 발행`을 함께 제공한다.
- 두 통계는 글감 행이 아니라 성공한 플랫폼 결과를 센다.
- 네이버와 WordPress가 모두 성공하면 2건이다.
- 기간은 오늘과 이번 주를 먼저 제공하고 최근 30일은 후속 단계로 둔다.

## 구현 단계

1. 기간 경계와 통계 projection 계약
2. owner-scoped 이벤트 조회 서비스와 read-only API
3. Dashboard Beta 통계·최근 결과 UI
4. focused contract와 browser smoke 검증
5. 사용자 UI 확인 후 완료 기록 및 parent merge 준비
