## User Need

Every Card News item must remain manageable regardless of whether its source is RSS, a directly entered URL, or directly entered text. New RSS articles should be added automatically without resetting an existing row, and generation/publishing outcomes should be reflected in the same ledger row.

## Goal

Connect the current Card News workflow to the stage 10 ledger store while keeping Google Sheets failures isolated from successful local generation and SNS publishing.

## Scope

- Register newly discovered RSS articles idempotently as `후보 / 미발행`.
- Register direct URLs by normalized URL when their first card composition succeeds.
- Give directly entered text an internal, UI-hidden management ID and retain it through regeneration.
- Record generation ID, card count, workflow status, publishing status, channel summary, public post links, processing time, and final error summaries.
- Preserve existing ledger rows when RSS rediscovery occurs.
- Keep local generation and confirmed SNS publishing successful even when ledger synchronization temporarily fails.

## Explicit Non-goals

- No ledger list/filter UI.
- No background polling scheduler.
- No scheduled publishing or ZIP import.
- No durable retry outbox for failed Sheet synchronization in this stage.

## Decisions

- The three source paths—RSS, direct URL, and direct text—are all managed.
- RSS GUID/item key is the stable identity for feed items; normalized URL is used for direct URLs.
- Direct text receives an internal ID at preview confirmation. A new input session gets a new ID; regeneration in the same session keeps the ID.
- A completed card composition without all images is `제작 중`; a complete image set is `제작 완료`.
- Re-reading RSS adds only new rows and never resets an existing user-managed row.
- Google Sheets readiness is checked once per successful app-session gateway lifetime rather than before every read and write.
- One logical row mutation performs one fresh ledger read and at most one batched values write; unchanged values produce no write request.
- An unchanged RSS source set is synchronized only once per app session; a newly observed feed item changes the signature and triggers the next ledger read.
