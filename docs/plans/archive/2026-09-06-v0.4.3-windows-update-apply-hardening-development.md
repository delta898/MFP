# v0.4.3 Windows self-update apply hardening

- Branch: `codex/fix/v043-windows-update-apply`
- Base/parent: `release/v0.4.3`
- Started: 2026-09-06
- Status: Implementation complete; Windows package validation remains

## User need and goal

Windows x64에서 `v0.4.3-dev4`가 `v0.4.3-dev5`를 내려받은 뒤 창은 다시 보이지만 실제 파일은 교체되지 않아 이전 버전이 유지된다. 릴리스 전에 Windows self-update의 helper 실행과 적용 완료 여부를 신뢰할 수 있게 만든다.

## Scope

- PowerShell helper의 다중 명령행 인자 전달을 제거하고 인접 JSON 작업 명세를 읽게 한다.
- helper 시작, 준비, 파일 교체, 재실행, 실패를 진단 가능한 로그와 표식으로 남긴다.
- helper 내부 실패가 성공 종료 코드로 숨겨지지 않게 한다.
- Node 측은 helper가 실제로 준비됐을 때만 현재 앱을 종료한다.
- Windows updater 집중 단위/계약 테스트를 보강한다.

## Non-goals

- macOS 업데이트 경로 변경
- 업데이트 UI 개편
- 새 배포 플랫폼 추가
- 실제 Windows 원격 발행 또는 전체 테스트 실행

## Design and tradeoffs

현재 방식은 `powershell.exe -File` 뒤에 여러 경로와 PID를 전달한다. Windows 현장 로그에서는 PowerShell이 두 후보 경로에서 실행됐지만 readiness 파일을 만들기 전에 `code=0`으로 끝났다. 인자 바인딩과 스크립트 초기화 구간을 단순화하기 위해 helper와 같은 폴더에 JSON 작업 명세를 기록하고, PowerShell에는 스크립트 경로만 전달한다.

JSON에는 경로, 대기 PID, 목표 버전을 기록한다. helper는 준비 표식을 먼저 기록하고 앱 종료를 기다린 뒤 파일을 교체한다. 성공 표식은 교체가 끝난 뒤 기록하며, 치명적 오류는 로그를 남기고 명시적으로 비정상 종료한다.

## Progress and verification

- Windows 현장 로그 확인: 두 PowerShell 후보 모두 readiness 이전 `code=0` 종료, `pwsh.exe`는 미설치.
- Implementation: PowerShell에는 helper 파일 경로만 전달하고, 작업 경로·PID·목표 버전은 인접한 UTF-8 JSON 명세에서 읽도록 변경했다.
- Implementation: helper 스크립트를 ASCII 문자만으로 생성하고 `-NonInteractive`로 실행해 Windows PowerShell 5.1의 인코딩 및 입력 대기 변수를 제거했다.
- Implementation: 입력 경로·실행 파일·PID를 적용 전에 검증하고, 앱 종료 대기 시간 초과 시 파일 교체를 시작하지 않는다.
- Implementation: readiness와 별도로 completed/failed 표식을 남기며, 치명적 오류는 `exit 1`로 반환한다. 앱 종료 뒤 적용에 실패한 경우 기존 실행 파일 재시작을 시도한다.
- Focused tests: `node --test src/updater.test.js` (9 passed)
- Full unit suite: `npm run test:unit` (1462 passed)
- Static check: `git diff --check` passed
- Manual Windows check required: `dev4 -> next dev build` update, process restart, displayed version, update banner disappearance, helper logs/markers.

## Remaining risks

- macOS 환경에서는 실제 Windows 파일 잠금과 PowerShell 5.1 실행을 재현할 수 없다.
- 최종 승인은 Windows 패키지에서의 실제 self-update 확인이 필요하다.
