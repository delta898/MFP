## User need and goal

macOS와 Windows에서 self-update가 실제로 적용된 뒤 새 앱이 실행되면, 적용된 버전을 폭죽 효과와 함께 한 번만 명확하게 알린다. 단순 재시작과 수동 재설치에는 표시하지 않고, 동일 버전 강제 업데이트는 성공한 self-update이므로 표시한다.

## Scope

- 두 OS가 공통 사용자 영구 영역에 동일한 완료 영수증을 기록한다.
- Windows는 helper의 파일 교체 완료 뒤, macOS는 동기화 완료 뒤 영수증을 기록한다.
- 현재 앱 버전과 영수증 목표 버전이 일치할 때만 pending 완료 상태를 제공한다.
- 기존 공통 축하 효과를 재사용해 적용 버전을 보여준다.
- 화면 표시가 실행된 뒤 acknowledgment로 영수증을 한 번만 소비한다.
- focused updater/API/UI 계약 테스트를 추가한다.

## Non-goals

- 업데이트 진행 UI 변경
- 릴리스 노트 상세보기 변경
- 수동 설치·일반 재시작 축하
- 버전 판올림, 태그, push 또는 패키징

## Design

`BLOG_GENIUS_USER_DATA`가 있으면 그 위치, 아니면 앱 루트 아래에 작은 JSON 영수증 하나를 둔다. 영수증은 임의 operation id, 목표 버전, 완료 시각을 포함한다. 조회는 삭제하지 않으며 UI가 축하 효과를 실제 호출한 뒤 같은 operation id로 acknowledgment해야 삭제한다. 따라서 UI가 준비되기 전에 앱이 종료되어도 다음 실행에서 다시 확인할 수 있다.

## Progress and verification

- Implementation: updater가 `BLOG_GENIUS_USER_DATA/update-state/completion.json`을 공통 영수증으로 사용한다. GUI userData가 없는 실행에서는 앱 루트로 안전하게 fallback한다.
- Implementation: macOS는 동기화와 임시 폴더 정리 뒤 Node에서, Windows는 앱 종료와 파일 교체 뒤 PowerShell helper에서 같은 필드의 영수증을 원자적으로 기록한다.
- Implementation: 현재 버전과 목표 버전이 일치하는 영수증만 API로 제공하며, UI가 공통 폭죽 효과를 호출한 뒤 operation id acknowledgment가 성공하면 영수증을 삭제한다.
- Implementation: 단순 재시작과 수동 설치에는 영수증이 없으므로 표시하지 않는다. 동일 버전 강제 업데이트는 새 operation 영수증이 생기므로 표시한다.
- Focused tests: `node --test src/updater.test.js scripts/ui-dashboard-shell-structure.test.js` (18 passed)
- Browser verification: `npm run test:ui-browser` passed (203 fixture requests)
- Full unit suite: `npm run test:unit` passed (1466 tests)
- Static check: `git diff --check` passed
- Manual validation: 공통 영수증 생성 기능이 포함된 버전에서 그 다음 버전으로 macOS와 Windows self-update 후 한 번 표시되는지 확인한다.

## Risks

- 이미 배포된 dev6의 Windows 임시 완료 표식은 공통 영수증이 아니므로 dev7 UI의 공통 경로에서는 사용하지 않는다. 두 OS의 동일한 검증은 이 기능이 포함된 버전에서 다음 버전으로 올릴 때 가능하다.
- 실제 OS별 파일 교체와 재실행은 패키지 self-update로 최종 확인해야 한다.
