## User Need

Users may already have a completed card-news image set outside BlogGenius. They should be able to bring an ordered ZIP into the Card News workflow and prepare it for manual publication without recreating the cards.

## Goal

Define and implement the smallest safe flow for importing a ZIP of card images, creating or attaching a local card-news generation, and handing it to the existing manual SNS publication flow and management ledger.

## Proposed Scope

- Select a local ZIP from the Card News surface.
- Validate that the archive contains supported image files and a deterministic order.
- Show a preview or validation summary before importing.
- Import the images into the local Card News workspace with a generated identifier.
- Attach the imported result to a new or explicitly selected management-ledger item.
- Reuse existing download, source metadata, and manual SNS publication boundaries where possible.

## Explicit Non-goals

- Automatic image generation or OCR/text extraction.
- Automatic publishing or scheduling.
- General archive formats beyond the agreed ZIP flow.
- Uploading the ZIP or images to Google Drive or application-owned cloud storage.
- Silently matching an archive to an RSS item without user confirmation.

## Agreed User Flow

1. Enter `만든 카드뉴스` and choose `ZIP 가져오기` from its header.
2. Select a local ZIP and validate it before changing local or Sheet state.
3. Show the ordered image thumbnails, supported-image count, and any actionable validation issue.
4. Let the user confirm a title (defaulted from the ZIP filename) and optionally provide the original article URL.
5. If the exact URL identifies an existing ledger row, explicitly offer to attach to that item; otherwise create a direct-import ledger item.
6. Copy the images into a new local Card News generation, synchronize its `제작 완료` state to the ledger, open the existing result view, and allow manual SNS publication.

## Agreed Import Rules

- Support PNG, JPEG, and WebP images, with at most 10 cards.
- Flatten supported images from nested folders and ignore common archive metadata files/directories.
- Sort cards by natural filename order so `1`, `2`, and `10` remain intuitive.
- Imported generations may have no AI prompt and must not pretend to be AI-generated work.
- Reuse the existing card image replacement, export, and manual SNS publication flow.
- Do not add manual reordering, duplicate fingerprint management, automatic publication, scheduling, or cloud archival in this stage.

## Verification Plan

- Unit tests for archive validation, ordering, unsupported files, traversal protection, size/card-count limits, and deterministic import metadata.
- UI contract tests for the import entry point, validation state, and confirmation flow.
- Browser smoke coverage for selecting a fixture ZIP, previewing its cards, cancelling, and completing an import without publishing.
- Manual check by the user for the final import-to-manual-publish handoff.
