# v0.4.3 SNS Multi-Image Grid

## Branch

- Branch: `codex/feat/v0.4.3-sns-multi-image-grid`
- Base/parent branch: `codex/feat/v0.4.3-card-news-main`
- Start date: 2026-09-05
- Status: complete; user approved parent integration

## User Need

The general SNS composer currently accepts one image through a wide uploader. Users need a familiar, space-efficient way to select multiple local images for a future multi-image publishing flow.

## Goal

Introduce the first independently reviewable slice: a square image grid with multiple local-file selection and in-place previews, while preserving the existing single-image flow and URL option.

## Scope

- Make local image selection the default input mode.
- Keep image URL as an explicit secondary option.
- Allow selecting multiple local image files in one action.
- Render selected images in a responsive square grid with ordering and removal controls appropriate for the existing UI style.
- Show empty slots with a plus affordance and preserve the existing file-type/size validation rules.
- Keep the current single-image transport and Buffer request behavior unchanged until later stages.

## Explicit Non-goals

- Drag-and-drop and grid reordering (follow-up slice).
- Google Drive multi-file upload changes.
- Buffer multi-image payloads or channel-specific publish limits.
- Scheduling, automatic publishing, or new SNS providers.
- Live SNS publication during development.

## Proposed Design

The composer will maintain an ordered local selection list and render it as a responsive 2–3 column square grid. Each tile shows a thumbnail, sequence number, and remove action; an empty add tile opens the native file picker. URL mode remains available without changing its existing semantics. The UI will expose the future multi-image capability without invoking transport changes until the next stage.

## Verification Plan

- Existing single-image SNS service tests remain green.
- Browser smoke test remains fixture-only; no live publication.
