## User Need
After selecting and confirming content, users need a short, understandable path to configure and create a Card News set. The internal project/recovery concept must remain invisible in the normal flow.

## Agreed Goal
Extend the current source-selection screen into:

`내용 선택 → 내용 확인 → 카드 설정 → 만들기 → 결과 확인`

The first implementation slice should make the generation contract and failure behavior reliable before adding publishing or automation.

## Agreed Scope
- Add essential generation settings inline after a content selection is confirmed.
- Preserve the most recently used manual settings locally for convenience; do not add a separate Card News settings page yet.
- Define a provider-neutral generation request and result contract.
- Generate a bounded set of slide content and image assets using the configured AI model.
- Save generated assets locally in an exportable folder with stable ordering and metadata.
- Show progress, prevent duplicate starts, preserve the last valid result on failure, and leave cancellation as an explicit backlog item unless the user brings it into this stage.

## Decisions Made with the User
- Keep the normal path simple and do not expose an intermediate `프로젝트` or `작업` step.
- Reveal generation settings only after content has been confirmed, then continue on the same page into the result.
- Expose only four settings in this stage:
  - card count
  - aspect ratio
  - style
  - Korean text inside generated images
- Default style is `AI 추천`; optional presets are `정보형`, `매거진형`, `감성형`, and `임팩트형`.
- Generate a new variation seed for each set. The AI uses the source, selected preset, and seed to choose a distinct color direction, composition, image treatment, information density, and emphasis.
- Keep every slide within one set visually coherent even though separate sets should vary.
- Do not expose a color, font, or template editor in the initial version.
- Leave `같은 스타일로 다시 만들기` and `새 스타일로 다시 만들기` as natural result actions/follow-up behavior rather than adding complex settings.
- Let the configured image AI compose any in-image Korean text. Application-side font rendering remains a later optional capability.

## Explicit Non-goals for the Initial Slice
- No SNS or Buffer publishing.
- No automatic generation after blog publication or RSS-triggered automation.
- No user-facing project/history management screen.
- No application-side text rendering into images; AI-generated image composition remains the default, with deterministic rendering deferred as an optional future stage.
- No broad Google Drive archive workflow unless local export proves insufficient.

## Remaining Product Decisions
- Whether a later stage should add one-click archive download or an open-folder action in addition to per-card downloads.
- Whether generated-set history should become a user-facing feature after the simple creation path is validated.

## Proposed Technical Boundaries
- Keep source snapshots and generation state behind the existing Card News service boundary.
- Represent generation as explicit capability requests rather than UI-specific config mutation.
- Keep assets provider-neutral (`slide index`, `mime type`, `local path`, optional public URL) so later Buffer/SNS adapters can be added without changing the core result.
- Reuse the current last-valid-state and request-order protections for long-running AI work.

## Remaining Risks
- Image generation cost and provider rate limits may require strict slide-count caps and retry policy.
- Long-running generation will need cancellation semantics before it is safe to expose as a fully unattended action.
- Local-only output is useful immediately but may need a later archive/distribution decision for multi-device workflows.
- Separate image calls can only enforce within-set consistency through their shared art direction prompt; exact character or object continuity may vary by image model.
