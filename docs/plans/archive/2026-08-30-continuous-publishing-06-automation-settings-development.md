## 사용자 필요와 목표

사용자가 연속 발행을 어느 기기에서, 어느 시간대에, 어느 간격으로 실행할지 이해하기 쉬운
설정으로 관리한다. 이번 단계에서는 자동 실행 정책과 화면·저장 계약을 먼저 확정하며,
여러 PC에서 같은 글감을 중복 처리할 수 있는 실제 주기 timer는 아직 활성화하지 않는다.

## 승인된 범위

- 이 기기의 연속 발행 켜기·끄기
- 발행 허용 시작·종료 시간
- 글 사이 최소 간격
- 현재 정책 상태와 다음 실행 예정 시각 표시
- 기본값은 비활성화
- Local·Development의 자동 발행 차단 유지
- `대기`와 Queue 건수 라벨을 사용자 관점에서 정리
- Queue 수정·제거 후 Queue 문맥을 유지
- 완성 원고 직접 실행과 Queue 글감의 차이를 명확히 표시

## 비목표

- 실제 주기 timer 시작
- 여러 PC distributed claim·lease
- Trends·RSS의 자동 Queue 승격
- 자동 재시도와 실패 알림 정책
- 기존 `블로그` 메뉴 교체
- Production 자동 발행 활성화

## 설계 원칙

- 전역 자동화 설정은 언제 실행할지만 소유하며 글감별 발행 대상을 덮어쓰지 않는다.
- 기기별 활성화 설정과 사용자 공통 실행 정책을 구분할 수 있는 구조를 선택한다.
- 환경이 자동 발행을 허용하지 않으면 UI 설정과 무관하게 실행 경계에서 차단한다.
- 다음 실행 시각은 설정을 설명하는 preview이며 이번 단계에서 외부 변경을 예약하지 않는다.
- 실제 timer 도입 전 여러 PC 중복 claim 계약을 별도 Stage에서 해결한다.

## 완료 결과

- 전역 자동화가 소유하는 값은 활성화, 시간대, 간격, 알림으로 제한했다.
- 새 설정은 기존 자동 포스팅 설정과 분리된 기기별 로컬 파일에 원자적으로 저장한다.
- Local·Development에서는 설정을 저장할 수 있지만 실제 자동 발행은 환경 정책으로 차단된다.
- Production에서도 현재는 예상 다음 실행만 보여주며 실제 timer는 시작하지 않는다.
- Queue 라벨과 수정 완료 후 화면 문맥을 사용자 관점에 맞게 정리했다.
