## 사용자 필요와 목표

기존 포스팅 완료 시 제공하던 축하 효과를 현재 정식 사용 화면인 Blog Beta에서도 다시 제공한다. 실행 방식과 무관하게 BlogGenius가 포스팅을 성공적으로 완료했다는 하나의 사건을 기준으로 동작한다.

## 범위

- Blog Beta `바로 포스팅` 실행 성공
- 발행 대기열 `지금 실행` 및 연속 자동 발행 성공
- 원고 폴더 및 원고 붙여넣기의 직접 포스팅 성공
- 공개 발행 및 임시 저장 완료 효과
- 새로 관찰한 성공 완료를 한 번만 표시하는 공통 규칙
- 관련 UI 계약 및 browser smoke 회귀 검증

## 명시적 비범위

- 예약 발행 등록 완료 효과
- 축하 효과의 시각 디자인 변경
- 버전 변경, release, push 또는 배포

## 사용자와 결정한 사항

- 완료 효과는 복원한다.
- 초기에는 자동 연속 발행을 제외하기로 했으나, 조건과 분기가 오히려 결함 가능성을 높인다는 사용자 판단에 따라 자동·수동을 구분하지 않는다.
- 공개 발행 또는 임시 저장이 성공했다는 동일한 완료 사건을 기준으로 효과를 표시한다.

## 설계와 트레이드오프

- 앱 전체에서 조회하는 발행 상태의 `last_completion_at`이 새 값으로 바뀐 성공 상태만 한 번 표시한다. 자동·수동 source, row index 또는 별도 요청 토큰을 완료 효과 조건에 사용하지 않는다.
- 직접 원고 포스팅은 runner polling을 거치지 않으므로 성공 응답 직후 같은 공통 완료 효과를 호출한다.
- 기존 효과의 공개 발행·임시 저장 허용 규칙을 재사용하고 예약 발행은 제외한다.
- 앱 시작 시 이미 남아 있던 과거 완료 상태는 초기 기준값으로만 저장해 다시 표시하지 않는다.

## 진행 및 변경 기록

- 2026-09-04: 기존 효과 구현과 legacy 호출 경로를 확인하고, Blog Beta 경로에 연결되지 않은 것이 사라진 것처럼 보인 원인임을 확인했다.
- 2026-09-04: 최초에 `dev` 작업 트리에서 구현했으나 브랜치 원칙을 재확인한 뒤, 커밋 전 변경 전체를 이 feature branch로 옮겼다.
- 2026-09-04: 수동 runner 완료 및 직접 원고 포스팅 성공 경로에 공통 효과를 연결했다.
- 2026-09-04: 자동 연속 발행 상태 조회는 pending 상태를 만들지 않도록 분리했다.
- 2026-09-04: 실제 임시 저장 점검에서 효과가 보이지 않는 사례를 확인했다. 로그상 네이버 브라우저를 화면에 열어둔 실행이어서 완료 후 외부 브라우저를 닫는 시점까지 runner가 유지됐으며, macOS에서 BlogGenius 창의 `focus` 이벤트와 `document.hasFocus()` 갱신 순서가 엇갈리면 보류 효과가 해제되지 않는 경로를 확인했다.
- 2026-09-04: 명시적인 BlogGenius 창 `focus` 이벤트는 포커스 복귀 증거로 사용해 보류된 효과를 해제하도록 보정했다. 단순 visibility 복귀에서는 기존 실제 포커스 확인을 유지한다.
- 2026-09-04: 실제 재확인에서도 효과가 보이지 않아 renderer의 완료 효과 요청·대기·표시 단계를 터미널 및 파일 로그에 남기는 제한된 UI 이벤트 기록 경로를 추가했다. 임의 메시지는 받지 않고 수동 포스팅 완료 효과의 허용된 단계와 `publish`·`draft` 상태만 기록한다.
- 2026-09-04: 두 번째 실제 임시 저장 로그에서도 포스팅은 완료됐지만 완료 효과 요청 로그가 전혀 생성되지 않았다. 시각 효과나 창 포커스 문제가 아니라 runner 완료와 renderer의 수동 pending 상태 연결이 끊긴 것으로 진단했다.
- 2026-09-04: 수동 실행마다 일회성 완료 효과 토큰을 요청에 포함하고 서버 runner 상태가 완료까지 그대로 반환하도록 보강했다. renderer는 자신이 발급한 토큰이 포함된 성공 완료만 한 번 소비하며, 자동 연속 발행에는 토큰이 생성되지 않는다.
- 2026-09-04: 사용자가 실행한 정확한 동선은 글감 관리의 제목을 눌러 `발행 계획 수정` 화면을 연 뒤 그 안의 `발행` 버튼을 누르는 흐름임을 확인했다. 이 버튼도 빠른 작성과 같은 `publish-now` runner를 사용하므로 해당 요청 토큰이 서버 완료까지 유지되는지 browser fixture와 서비스 계약에 포함했다.
- 2026-09-04: 자동·수동을 구분하는 조건이 완료 효과에 비해 과도하고 결함 가능성을 높인다는 사용자 의견에 따라 설계를 단순화했다. 요청 토큰과 수동 pending을 제거하고 새 `finishedAt`을 가진 성공 완료라면 실행 출처와 무관하게 공통 효과를 표시한다.
- 2026-09-04: 자동 발행은 Blog Beta 탭이 열려 있지 않아도 끝날 수 있으므로 완료 감지를 탭 내부 polling에서 앱 공통 발행 상태 polling으로 옮겼다. 이를 통해 Dashboard 등 다른 화면에 있어도 같은 단일 완료 규칙이 적용된다.
- 2026-09-04: 사용자가 글감 관리 편집 화면의 임시 저장 포스팅으로 완료 효과가 정상 표시되는 것을 최종 확인했다.
