# v0.4.1 Dashboard Overview 운영 현황 계약 개발 기록

## Branch

- Branch: `codex/feature/v0.4.1-dashboard-overview-contract`
- Base/parent branch: `codex/feature/v0.4.1-dashboard-upgrade`
- Start date: 2026-09-02
- Status: 완료

## 사용자 필요와 목표

Dashboard UI를 재설계하기 전에 Blog Beta의 현재 실행 상태, 연속 발행 일정, 대기열과 보관 글감 정보를 하나의 안정적인 읽기 계약으로 제공한다. 이후 UI와 통계가 내부 Sheet 행 구조나 실행기 구현에 직접 의존하지 않게 한다.

## 범위

- 현재 runner 상태와 실행 중 글감 요약
- 연속 발행 활성·실효 상태와 다음 처리 시각
- 발행 대기, 보관, 실행 중 글감 개수
- 현재 대기열 순서에 따른 다음 글감 최대 3개와 예상 처리 시각
- 한 번의 Topics snapshot으로 운영 현황을 계산하는 계약
- 전용 API route/controller와 자동 테스트

## 명시적 비범위

- Dashboard HTML/CSS 변경
- 오늘·이번 주·최근 30일 통계
- 플랫폼별 발행 결과 이벤트 저장
- 기존 Dashboard 카드나 외부 피드 제거
- 실제 Google Sheet, 네이버 또는 WordPress 접속 테스트
- commit, parent merge, push 및 배포

## 설계

- 연속 발행 서비스가 이미 소유한 scheduler, runner, queue snapshot을 재사용한다.
- 순수 read-model mapper가 내부 객체에서 Dashboard에 필요한 필드만 allowlist한다.
- Dashboard Overview 호출 한 번에서 Topics 전체 조회는 한 번만 수행한다.
- 실행 중 항목은 대기 건수와 별도 집계하고, 다음 항목은 현재 물리적 대기열 순서를 유지한다.
- 인증정보, 세부 글쓰기 지시, 참고 URL, 내부 런타임 객체는 응답에 포함하지 않는다.
- 통계 기간과 플랫폼별 성공 기준은 parent 기록에 고정하고 후속 단계에서 구현한다.

## 사용자와 결정한 사항

- 쉬운 운영 현황 데이터 계약부터 진행하고 역사 통계는 후속 단계로 미룬다.
- 처리 완료와 공개 발행은 모두 필요하며 성공한 플랫폼 결과 단위로 집계한다.
- 기간은 오늘, 이번 주(월요일 시작), 최종적으로 최근 30일을 제공한다.
- 이 단계는 UI가 없으므로 사용자의 시각 검증은 요구하지 않는다.

## 구현 단계

1. read-model 계약과 mapper 테스트
2. 연속 발행 서비스의 단일 snapshot 조합
3. route/controller 계약
4. focused unit/structure 검증

## 진행 및 변경 기록

- 2026-09-02: Dashboard parent에서 첫 sub-feature branch와 개발 기록을 생성했다.
- 2026-09-02: 기존 대기열 snapshot을 재사용해 runner, 자동화, 대기·보관·실행 중 개수와 다음 글감 최대 3개를 한 계약으로 조합했다.
- 2026-09-02: 제목, 발행 대상, 발행 방식, 예상 시각만 노출하고 글쓰기 지시사항, 참고 URL, 원본 options 등은 응답에서 제외하는 allowlist mapper를 추가했다.
- 2026-09-02: runner가 시작됐지만 Sheet 상태가 아직 갱신되기 전인 구간에도 같은 항목이 `대기`와 `실행 중`에 중복 집계되지 않도록 보정했다.
- 2026-09-02: `GET /api/v1/continuous-publishing/dashboard-overview` route/controller를 추가했다.

- 호출 한 번당 Topics snapshot 조회는 한 번이다.
- focused test 33개 통과:
  - read-model allowlist와 정규화
  - service 단일 조회와 compact projection
  - route/controller GET 및 method 제한
  - 기존 연속 발행 service 회귀
- Blog Beta shell contract test 17개 통과.
- parent 병합 전 전체 단위 테스트 1,259개 통과.
- `git diff --check` 통과.
- 이 단계는 UI를 변경하지 않아 별도 수동 UI 확인 사항은 없다.
- 구현과 검증을 완료했으며 Dashboard parent 병합 대상으로 확정했다.
