## User Need
After preparing every card image, the user should be able to take the complete ordered set out of BlogGenius in one action. The flow should remain useful without Google Drive, Buffer, or any other remote storage dependency.

## Goal
Add a small local-export completion step that validates image readiness, exports the ordered card set together, and lets the user locate the saved result without exposing internal workspace concepts.

## Scope
- Validate that every card has a usable stored image before complete-set export.
- Export all card images in stable card order with predictable filenames.
- Provide one clear UI action for complete-set download/export.
- Provide an optional way to reveal the locally saved output when supported by the desktop runtime.
- Preserve the generation workspace and existing valid images when export fails.

## Explicit Non-goals
- Google Drive upload or archive.
- Buffer or SNS publishing.
- Public asset hosting or temporary public URLs.
- Generated-set history, retention policy, or workspace cleanup.
- Re-rendering or regenerating card images during export.

## Proposed Design
- Keep the current generation folder as the source of truth.
- Build export output from manifest card order rather than filesystem order.
- Keep internal paths server-side; return only a safe download response and minimal result metadata.
- Block complete export when any image slot is empty and direct the user to fill the missing cards.
- Keep per-card downloads available alongside the new set-level action.

## Affected Boundaries
- `src/card-news/`: export validation and ordered bundle creation.
- `src/ui-api/`: local export endpoint and error mapping.
- `src/ui-runtime/`: safe response streaming or desktop folder reveal boundary if needed.
- `ui/scripts/features/card-news/`: state-aware complete export action.
- Focused contract, service, route, and UI tests.

## Implementation Stages
1. Inspect existing asset-serving and desktop runtime boundaries.
2. Add ordered complete-set export with readiness validation.
3. Connect the smallest state-aware UI action.
4. Run focused automated verification and hand off visual checks to the user.

## Decisions and Tradeoffs
- 2026-09-05: Google Drive archive was removed from this stage. Local export is the complete product outcome; any remote transport should be selected later as part of seamless Buffer/SNS delivery.
- 2026-09-05: A future Buffer stage must not assume Drive is a public asset transport until its actual platform compatibility is verified.
