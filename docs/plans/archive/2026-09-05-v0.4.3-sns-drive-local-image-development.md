# v0.4.3 SNS Google Drive Local Image Transport

## Branch

- Branch: `codex/feat/v0.4.3-sns-drive-local-image`
- Base/parent branch: `codex/feat/v0.4.3-card-news-main`
- Start date: 2026-09-05
- Status: complete; ready for parent integration

## User Need

The existing general SNS publishing flow requires WordPress when a user selects a local image. Card News already uses the verified Google Drive temporary public-media path, so general SNS users should be able to publish a local image without configuring WordPress.

## Goal

Replace only the general SNS local-image transport with the existing Google Drive public-media contract while preserving the current single-image behavior, channel validation, text limits, result recovery, and safe cleanup.

## Scope

- Reuse the existing Google OAuth `drive.file` boundary and Google Drive public-media transport.
- Upload one selected local image to Google Drive and pass its public HTTPS URL to Buffer.
- Delete the temporary Drive file after a terminal Buffer result.
- Preserve the existing remote-image URL path unchanged.
- Preserve timeout safety: retain the temporary file when Buffer publication status is ambiguous.
- Update user-facing guidance from WordPress to Google Drive where local-image setup is required.
- Add focused unit, service, and UI contract tests.

## Explicit Non-goals

- Changing general SNS from one image to multiple images; that is a separate follow-up stage.
- Changing Card News publishing, which already uses this transport.
- Adding scheduling, automatic publishing, or a Drive file browser.
- Running a real SNS publication without separate user approval.
- Adding Bitly URL shortening in this stage.

## Proposed Design

1. Inject the existing provider-neutral public-media transport into the general SNS service.
2. For a local image, read the validated file, upload it once, and use the returned public HTTPS URL for the existing Buffer request.
3. Keep the uploaded media handle separate from the URL so cleanup is independent of Buffer payload normalization.
4. Clean up after terminal success or definite failure; retain on `BUFFER_REQUEST_TIMEOUT`.
5. Report a missing Google connection as a targeted setup error without requiring WordPress settings.
