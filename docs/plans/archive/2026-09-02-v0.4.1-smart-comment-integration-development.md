## 사용자 필요와 목표

기존 블로그의 네이버 스마트 댓글 기능은 기능적으로 유용하지만 설정과 결과가 한 화면에서 경쟁하고, 실행 상태가 원시 로그처럼 보여 복잡하고 조잡하게 느껴진다. 새 블로그에서는 필요한 설정만 간결하게 노출하고, rate-limit이나 일부 실패가 발생해도 사용자가 성공 결과와 다음 행동을 명확히 이해하도록 개선한다.

## 범위

- 새 블로그에 `스마트 댓글` 탭과 독립 모듈 추가
- 기존 스마트 댓글 API·수집기·생성기 재사용
- 실행 전 설정과 실행 후 결과의 시각적 계층 재설계
- 진행 상태를 새 블로그의 상태 배너/요약 패턴에 맞게 표현
- rate-limit을 고려한 기본 후보 수와 생성 흐름 개선
- 실행 중 중복 요청 방지, 마지막 유효 결과 보존
- 설정 변경 감지와 저장 UX 정리
- 새 UI에 대한 focused contract/UI/browser 검증

## 명시적 비범위

- 댓글 자동 등록 또는 좋아요 자동 실행
- 후보 수집 방식의 전면 재작성

## 제안 설계

### 1. 단순한 기본 화면

- 핵심 설정은 `후보 글 수`, `댓글 길이`로 제한한다.
- 사용자가 톤을 먼저 고르게 하지 않고, 각 후보에 공감형·친근형·담백형을 하나씩 보여줘 결과를 보고 선택하게 한다.
- AI 선택은 현재 정책과 호환되게 제공하되 보조 설정 영역으로 낮춘다.
- production에서는 `보이지 않게 실행` 선택을 노출하지 않고 안전한 기본 실행 정책을 사용한다. 개발 환경에서만 진단 목적으로 노출할 수 있다.
- 저장과 실행의 역할을 구분하고, 저장할 변경이 있을 때만 저장 버튼을 활성화한다.

### 2. rate-limit에 강한 실행

- 후보 수 상한 10은 유지하되 기본값은 5보다 작은 보수적 값으로 검토한다.
- 대량 후보를 한 번에 성공/실패로 판단하지 않고 작은 batch의 성공 결과를 즉시 누적한다.
- rate-limit 발생 시 이미 생성된 결과를 유지하고 `일부 완료`로 명확히 표현한다.
- 자동 재시도와 대기 상태는 사용자가 이해할 수 있는 문구로 보여주며 원시 로그는 노출하지 않는다.

### 3. 산뜻한 상태 표현

- 상단에 현재 단계 한 줄과 진행 수치만 표시한다.
- 상태는 `후보 찾는 중`, `댓글 작성 중 n/N`, `잠시 기다리는 중`, `완료`, `일부 완료`, `실패`로 제한한다.
- 완료 후에는 성공/실패 개수 요약과 재시도 가능한 행동을 결과 영역에 배치한다.
- 마지막 유효 결과는 새 실행 또는 재생성 실패 시에도 유지한다.

### 4. 결과 카드

- 후보 글 정보와 댓글 초안을 한 카드 안에서 명확히 분리한다.
- 각 초안에 톤 라벨을 붙여 비교 비용을 줄인다.
- 기본 행동은 댓글 복사와 `네이버에서 댓글 쓰기`며, 전체 초안을 바꾸는 `이 글의 댓글 다시 만들기`는 보조 행동으로 둔다.
- 실패한 후보는 성공 카드와 같은 무게로 크게 표시하지 않고 간결한 재시도 상태로 표현한다.

## 대안과 tradeoff

- 후보 수를 10에서 강제로 낮추면 사용자의 선택권이 줄어든다. 상한은 유지하되 안정적인 기본값과 예상 AI 요청량 안내를 제공한다.
- production에서 headless 선택을 완전히 제거하면 문제 진단 선택권이 줄지만 일반 사용자에게 브라우저 자동화 구현 세부를 노출하지 않는 이점이 더 크다.
- 모든 설정을 숨기면 단순하지만 결과 품질 조절이 어렵다. 자주 쓰는 설정만 기본 노출하고 AI 선택은 보조 설정으로 둔다.
- 톤 선택을 유지하면 생성 전 사용자 제어는 높지만, 결과를 비교하려면 같은 글에 여러 번 실행해야 한다. 세 톤을 한 모델 응답에서 함께 받아 호출 횟수를 늘리지 않고 선택을 결과 단계로 옮기는 쪽을 택했다.

## 구현 단계

1. 기존 API·진행 상태·설정 계약 확인 및 필요한 최소 계약 보강
2. 새 블로그 탭, 설정 패널, 상태 요약, 결과 카드 구현
3. 독립 event binding과 실행 lifecycle 구현
4. rate-limit·부분 성공·실패 보존 동작 검증
5. focused tests 및 browser smoke 실행
6. 사용자 UI 확인 후 parent merge 준비

## 사용자와 결정한 사항

- 기존 스마트 댓글 UI를 그대로 이전하지 않고 새로 설계한다.
- rate-limit에 자주 걸리는 현실을 정상적인 부분 성공 흐름으로 다룬다.
- production에서는 `보이지 않게 실행`을 사용자 설정으로 노출할 필요가 낮다.
- 실행 상태는 기존 로그 박스가 아니라 블로그 Beta의 간결한 진행 상태 패턴을 따른다.
