## 사용자 필요와 목표

`블로그 Beta`의 원고 생성·발행은 오래 걸리지만 상태 패널이 화면 상단에 떨어져 있고 `상태 보기` 링크는 발견하기 어렵다. 발행에는 같은 이동 수단이 없으며 실패 메시지는 상단·폼 결과·미리보기 검증 영역에 중복된다. 시작한 작업의 진행과 결과를 한 곳에서 쉽게 보고, 원래 작업 위치로 돌아갈 수 있어야 한다.

## 범위와 비범위

- `블로그 Beta`의 AI 원고 생성·재생성과 현재 미리보기 원고 발행에서, 실제 작업 시작 뒤 상단 상태 패널로 한 번 이동하고 원래 실행 버튼 위치로 돌아가는 명확한 동작을 제공한다.
- 상단 패널을 실행 상태·결과의 단일 소유자로 두고 중복 오류 문구를 정리한다. 입력값 검증 오류는 입력 가까이에 둔다.
- 진행·취소·완료·실패의 짧은 사용자 메시지를 정리하고, 취소의 이용료·KIE 원격 작업 가능성은 접근 가능한 부가 도움말로 분리한다.
- 집중 UI/계약 검사와 완료된 사용자 흐름의 브라우저 smoke를 수행한다.
- 기존 `블로그`, 쇼핑커넥트, 카드뉴스와 공통 상태 프레임워크 전면 도입은 비범위다. 검증된 패턴의 확장은 별도 단계다.
- AI transport·과금 정책 자체, 발행 설정 유지 버그, 개발 환경 원문 로그는 이번 단계에서 변경하지 않는다.

## 설계와 결정

- 생성 요청 수락과 발행 확인 뒤에만 자동 스크롤한다. polling이나 상태 갱신, 탭 복귀에는 자동 이동하지 않는다.
- 상단의 이동 버튼은 `↓ 원고 보기`로 표시하고 해당 실행 위치로 이동한다. 종결 상태에서도 사용자가 선택해 돌아갈 수 있게 한다. 원래 버튼 영역이 결과 전환으로 숨겨지면 원고 영역으로 이동한다.
- 원고 실행 실패의 전체 오류는 상단 패널 한 곳에 표시하고, 필드 오류와 미리보기 내용 검증만 인라인에 남긴다. 성공·취소도 불필요한 하단 반복을 제거한다.
- 취소 자체의 메시지는 모델과 무관하게 짧게 유지한다. 비용 정보는 취소 전후에 확인할 수 있는 보조 도움말로 제공하되, 취소가 과금 면제를 보장한다고 말하지 않는다.

## 진행 기록

- 2026-09-24: 사용자가 상단 상태 패널 자동 이동, 되돌아가기 버튼, 생성·발행 공통 흐름, 중복 메시지 제거에 동의했다. parent의 기존 미커밋 문서 변경은 건드리지 않고 별도 sub-feature 브랜치를 시작했다.
- 2026-09-24: 생성 접수 및 발행 확인 뒤 상단 상태 패널로 한 번만 이동하고 포커스를 옮기는 동작을 구현했다. 돌아가기 버튼은 입력 방식과 원래 작업 영역을 복원한다.
- 2026-09-24: 원고 생성의 성공·실패·취소 메시지를 상단 상태 패널로 모았고, 발행 결과의 중복 토스트/검증 문구를 제거했다. 입력·연결 사전 검증 문구는 필드 근처에 유지했다. 취소 비용 설명은 `?` 도움말로 옮겼다.
- 2026-09-24: 기존 계약 검사에서 오래된 AI 생성 API 경로 기대값을 발견해 현재 작업 API에 맞게 수정했다. 브라우저 smoke에 생성 실패·KIE 취소 도움말·발행 실패 후 재시도·돌아가기 검사를 추가하고, 빠른 모의 응답에서 진행 상태를 놓치던 시간 의존 검사도 안정화했다.
- 2026-09-24: 사용자 피드백에 따라 직접 발행 확인창에서 내부 처리 설명과 `Queue` 문구를 제거했다. 플랫폼·임시 저장/즉시 발행/예약 발행 시각만 기본으로 표시하고, 실제 자동 이미지 생성이 있을 때만 한 줄로 알린다. 문구별 계약 검사와 임시 저장 확인창 브라우저 검사를 추가했다.
- 2026-09-24: 네이버의 보이지 않게 실행에서는 `원고 입력 중`이 길게 이어져 사용자가 멈춤으로 오해할 수 있다는 실제 로그를 검토했다. 중간 안전 저장은 완료가 아니며, 제목·URL·파일명을 노출하지 않고 본문 구간/이미지/링크의 확인된 개수와 큰 작업 지점만 전달하기로 했다.
- 2026-09-24: 네이버 브라우저 자동화의 구조화된 진행 이벤트를 직접 발행 실행 lease와 공통 상태 조회에 연결했다. AI 이미지 자동 완성 중에도 대상 slot 진행을 표시한다. WordPress와 기존 블로그 UI는 변경하지 않았다.
- 2026-09-24: 사용자가 실제 네이버 임시 저장을 확인한 뒤 완료 상태에서 같은 저장 버튼이 다시 활성화되고, 아래로 돌아가기가 화면 맨 아래를 보여주는 문제를 제기했다. 상단 완료 상태에 `다음 글`을 두고, 완료한 원고의 재실행 버튼을 잠그며, 돌아가기는 미리보기로 이동하도록 정했다. 단축키도 동일한 확인·초기화 동작으로 연결한다.
- 2026-09-24: 후속 사용자 검토로 `내용 지우기` 및 그 전용 되돌리기 UI를 제거하고, 다음 글 흐름에 입력 초기화를 집중하기로 했다. 발행 중 포스팅 설정·이미지 변경은 화면과 API 경계에서 막고, 완료된 Draft는 설정·이미지 수정으로 재발행 가능한 상태로 되돌아가지 않게 했다. 완료 상태 버튼을 줄이고 AI 취소 비용 도움말은 hover·키보드 포커스·클릭으로 열리게 했다.
- 2026-09-24: full suite에서 이전 확인창 문구를 기대하는 baseline 계약 테스트를 발견해 현재 확인창 계약으로 고쳤다. 로컬 서버 바인딩이 제한된 샌드박스에서 Trends API 테스트 2개가 `EPERM`으로 실패했으나, 동일 suite를 바인딩이 허용된 환경에서 재실행해 통과했다.

## 결과·검증·남은 위험

- 결과: Blog Beta 빠른 글 작성의 원고 생성·재생성·직접 발행 상태가 같은 상단 패널에 모이고, 하단 `상태 보기` 링크 없이 위/아래 이동할 수 있다. 원고 생성 실패 메시지와 발행 결과 메시지의 중복 표시를 정리했다. 네이버 발행은 AI 이미지 생성, 에디터 연결, 본문 구간, 이미지/링크 추가, 발행 설정·제출·결과 확인을 구분한다. 성공한 원고는 재실행을 막고 상단에서 다음 글로 넘어갈 수 있다. 포스팅 중 변경 가능한 설정·이미지 제어를 잠그고 완료 상태의 보조 버튼을 축소했다.
- 자동 검증: 네이버 진행 상태 관련 집중 검사 128개 및 AI 이미지 준비 상태 전달 집중 검사 14개 통과. 후속 UX 및 완료 Draft 변경 차단 집중 검사 91개 통과. Blog Beta 브라우저 smoke 통과(455개 모의 요청): 발행 중 설정·이미지 잠금, 완료 후 새 원고 시작, hover/키보드 도움말, 폴더·붙여넣기의 새 Draft 경로를 포함했다. 전체 unit suite는 사용자 승인 후 재실행해 1,932개 통과·1개 건너뜀·실패 0개를 확인했다.
- 수동 확인 필요: 실제 네이버 비표시 발행에서 본문 구간·이미지·링크·설정·제출 상태 전환, 성공 후 돌아가기/다음 글 작성 흐름, 좁은 화면·키보드 동작. 실제 발행은 외부 포스팅을 수반하므로 자동 검사에서 실행하지 않았다.
- 남은 위험: KIE 원격 작업 종료와 청구 여부는 앱에서 확정할 수 없다. 네이버 실제 브라우저 자동화의 긴 실행은 사용자의 수동 확인이 필요하다. 대기열 실행 및 Blog Beta 밖의 표면은 별도 UX 확장 범위다.
