# v0.4.3 SNS Multi-Image Google Drive Transport

## Branch

- Branch: `codex/feat/v0.4.3-sns-multi-image-drive`
- Base/parent branch: `codex/feat/v0.4.3-card-news-main`
- Start date: 2026-09-05
- Status: complete; user approved parent integration

## User Need

The composer can now select, preview, and order several local images, but publication is intentionally limited to one image. The selected ordered set must be uploaded through the shared Google Drive temporary-media transport before Buffer multi-image payload work can begin.

## Goal

Extend the general SNS request and service boundary to accept and validate an ordered local-image collection, upload each item through the existing shared Google Drive transport, and manage cleanup safely as one publication media set.

## Scope

- Accept an ordered local-image array while retaining the existing single-image request shape during transition.
- Validate type, size, count, and decoded payload before external upload.
- Upload images sequentially through the shared Google Drive public-media transport to preserve order and reduce API burst pressure.
- Return ordered public URLs to the publishing boundary.
- Clean up every uploaded temporary item on terminal success or definite failure.
- Retain uploaded items when delivery status is ambiguous, consistent with the single-image timeout policy.
- Add focused tests for partial upload failure and cleanup behavior.

## Explicit Non-goals

- Parallel Drive uploads, scheduling, or live SNS publication.

## Proposed Design

Normalize `localImages[]` at the service boundary and adapt legacy `localImage` into a one-item list. Upload the validated files sequentially and retain the ordered media handles. Investigation confirmed that the shared Buffer client already accepts ordered `imageUrls[]` because Card News uses the same gateway, so this stage connects the uploaded URL set end to end rather than creating an artificial extra stage.

## Verification Plan

- Unit tests for ordered uploads, legacy compatibility, validation before upload, partial-upload cleanup, definite failure cleanup, and ambiguous timeout retention.
- Existing manual SNS tests remain green.
- No real Google Drive mutation or SNS publication; use injected fakes.
