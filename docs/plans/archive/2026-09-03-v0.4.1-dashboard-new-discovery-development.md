# v0.4.1 Dashboard 새로운 발견 복원 개발 기록

## Branch

- Branch: `codex/feature/v0.4.1-dashboard-new-discovery`
- Base/parent branch: `codex/feature/v0.4.1-dashboard-upgrade-02-main`
- Start date: 2026-09-03
- Status: 완료

## 사용자 필요와 목표

새 Dashboard에서 누락된 `새로운 발견`을 복원한다. 뉴스, 트렌드, 사용자의 기존 글에서 확장한 소재를 운영 현황과 구분해 보여주고, 사용자가 발견한 소재를 바로 글쓰기로 이어가거나 관심 없는 소재를 교체할 수 있게 한다.

## 범위

- 기존 recommendation center 조회·상호작용 계약 재사용
- 새 Dashboard에 최대 3개의 serendipity 추천 표시
- 출처 힌트, 추천 근거, 소재 적용, 관심 없음 동작 유지
- 핵심 Dashboard 요청과 독립적인 비동기 로딩 및 실패 격리
- 새 Dashboard로 이동하는 toast와 presentation 목적지 정합화
- focused UI contract 및 browser smoke 검증

## 명시적 비범위

- 추천 생성·순위·Memory·Knowledge 계약 변경
- 도움말·가이드 화면 및 후원 teaser 구현
- 레거시 Dashboard 구현 삭제
- release, push 또는 배포

## 설계

- 기존 DOM ID를 중복 생성하지 않고 recommendation center 렌더러가 활성 Dashboard의 전용 mount를 선택하도록 한다.
- 추천 카드의 데이터·행동 계약은 공유하되 새 Dashboard에서는 더 컴팩트한 표현을 사용한다.
- 새 Dashboard 초기 운영 정보 로딩과 추천 로딩을 서로 기다리지 않게 한다.
- 추천 조회 실패 시 운영 정보는 그대로 유지하고 추천 영역만 안전한 안내 또는 마지막 정상 결과를 유지한다.
- 추천 행동이 `dashboard.recommendations`를 가리키면 현재 기본 Dashboard의 새로운 발견 영역으로 이동한다.

## 진행 및 변경 기록

- 2026-09-03: Dashboard 2차 고도화 parent에서 첫 sub-feature를 시작했다.
- 2026-09-03: 새 Dashboard에 최대 세 건의 `새로운 발견`을 표시하는 공유 recommendation center mount를 추가했다.
- 2026-09-03: 기존 Dashboard와 새 Dashboard가 같은 추천 데이터·행동 계약을 공유하되, 활성 화면에만 카드를 렌더링하도록 렌더러를 일반화했다.
- 2026-09-03: 추천 toast와 `dashboard.recommendations` presentation 목적지를 현재 기본 화면인 새 Dashboard로 변경했다.
- 2026-09-03: 최초 앱 세션에서는 기존처럼 저장된 추천 조회 후 새 소재 발견을 한 번 수행하고, 이후 두 Dashboard 사이를 이동할 때는 캐시된 마지막 정상 결과를 활성 화면에 즉시 다시 그리도록 했다.
- 2026-09-03: 최초 브라우저 회귀 테스트에서 새 Dashboard에서 기존 Dashboard로 이동한 뒤 카드가 활성 mount로 옮겨지지 않는 실패를 확인했다. 세션 내 추천 캐시를 활성 mount에 다시 렌더링하도록 수정해 재조회로 인한 불필요한 교체와 빈 화면을 함께 방지했다.
- 2026-09-03: 사용자 UI 확인에서 `새로운 발견`이 정상 동작함을 확인했다. 이어서 발행 흐름 카드의 이동 버튼을 카드 우측 하단에 정렬해 상태 정보와 후속 행동의 계층을 분리하고, 좁은 화면에서는 좌측 정렬로 복귀하도록 했다.
- 2026-09-03: Dashboard 카드의 eyebrow 문법을 검토한 뒤 작은 분류 라벨은 유지하되 모두 `eyebrow → 제목`의 두 줄 계층을 따르기로 했다. 한 줄로 합쳐져 있던 `글감 / 새로운 발견`도 동일한 구조로 정리했다.
- 2026-09-03: 상단 운영 카드의 정보 밀도를 재검토했다. 실행 상태 카드와 연속 발행 카드를 같은 폭으로 조정하고, 유휴 상태에서는 목록을 중복 노출하지 않고 발행 대기 건수만 요약한다. 연속 발행 설정 행동은 해당 카드로 이동해 상태에 따라 `연속 발행 설정`·`설정 보기`·`설정 확인`으로 안내하며, 통계 설명은 `실제 공개된 글`로 축약했다.
