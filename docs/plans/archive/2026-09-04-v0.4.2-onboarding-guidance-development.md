# v0.4.2 최초 설정 안내 개발 기록

## Branch

- Branch: `codex/feat/v0.4.2-onboarding-guidance`
- Base/parent branch: `codex/feat/v0.4.2-product-surface-main`
- Start date: 2026-09-04
- Status: 완료 — v0.4.2 구현 후 v0.4.3 첫 실행 회귀까지 검증

## 사용자 필요와 목표

새 Dashboard를 기본 화면으로 사용하는 최초 설치 또는 필수 설정 미완료 상태에서, 사용자가 무엇을 준비해야 하는지와 다음에 어디로 이동해야 하는지를 친절하고 간결하게 안내한다.

## 범위

- 새 Dashboard에 필수 준비 상태 기반 온보딩 안내 제공
- AI 모델, Google 계정·Spreadsheet, 발행 채널을 서로 구분해 표시
- 네이버 또는 WordPress 중 하나가 준비되면 발행 채널 단계를 완료로 판단
- 미완료 항목의 정확한 설정 탭과 필드로 이동
- 모든 필수 준비가 끝나면 안내 자동 숨김
- 기존 Dashboard 연결 상태와 중복 조회하지 않는 read model 재사용

## 명시적 비범위

- `config.json` 자동 생성 정책 변경
- 네이버·Google 인증 파일 삭제 또는 초기화
- 설정 wizard 또는 별도 top-level 화면 추가
- 기존 legacy Dashboard 안내 개선
- 버전 변경, push, 배포

## 제안 설계

- 설정 파일의 존재가 아니라 실제 capability 준비 상태를 기준으로 안내한다.
- 한 번에 모든 설명을 펼치기보다 세 단계의 완료 여부와 가장 먼저 필요한 다음 행동을 보여준다.
- 인증 sidecar가 남아 있으면 해당 연결 결과를 존중하고 다시 설정하도록 강요하지 않는다.
- 미완료 상태에서는 영구 닫기를 제공하지 않는다. 사용자의 작업을 방해하지 않는 inline card로 표시하고 준비 완료 시 자동으로 사라진다.
- 새 Dashboard가 이미 요청하는 account/config 상태를 확장해 초기 로드 비용을 늘리지 않는다.

## 구현 단계

1. 현재 Dashboard read model과 설정 탭 이동 계약에서 재사용 가능한 준비 정보를 확정한다.
2. 서버 DTO에 필요한 최소 준비 상태만 추가한다.
3. 새 Dashboard inline onboarding card와 다음 행동을 구현한다.
4. 설정 저장·연결 상태 갱신 후 자동 숨김을 확인한다.
5. focused contract와 browser smoke를 실행하고 사용자 UI 확인으로 인계한다.

## 사용자와 결정한 사항

- 기존 안내의 취지는 유지하되 새 Dashboard 디자인과 동선에 맞게 다시 만든다.
- 수동 `config.json` 삭제는 일반적인 사용자 흐름은 아니지만 실제 최초 설치와 같은 빈 설정 상태를 발견하는 진단 수단으로 본다.
- AI, Google Spreadsheet, 블로그 채널의 준비 상태를 각각 이해할 수 있어야 한다.
- UI 최종 확인은 사용자가 수행한다.

## 현재 파악한 문제

- `config.json`이 없으면 sample이 즉시 복사되어 파일 자체는 준비된 것으로 표시된다.
- 기존 첫 설정 안내 DOM은 숨겨진 legacy Dashboard에만 있어 새 Dashboard에서는 보이지 않는다.
- 기존 안내의 닫힘 상태는 `localStorage`에 남아 `config.json` 삭제와 함께 초기화되지 않는다.
- 네이버는 `config/naver_auth.json`, Google은 기본 `config/google_oauth_tokens.json` sidecar를 별도로 사용하므로 `config.json` 삭제만으로 완전한 최초 설치 상태가 되지는 않는다.

## 구현 진행

- 계정 개요 read model에 AI, Google 계정·Spreadsheet, 발행 채널의 최소 준비 상태를 추가했다.
- Google OAuth는 외부 접속 없이 저장된 refresh token 존재만 확인하는 read-only 상태 조회를 제공한다.
- 새 Dashboard에 3단계 inline 안내와 완료 수, 가장 먼저 필요한 다음 행동을 추가했다.
- 다음 행동은 기존 설정 이동 계약을 재사용해 해당 탭과 설정 영역을 강조한다.
- 모든 단계가 준비되면 안내는 자동으로 숨고, 별도의 닫기 상태는 저장하지 않는다.

## 검증 및 남은 위험

- JS syntax와 account/Dashboard/UI 구조 focused test 37건이 통과했다.
- Google OAuth 설정 및 소비자 focused test 5건이 통과했다.
- 브라우저 smoke test가 189개 fixture 요청으로 통과했으며, 준비 완료 시 숨김과 미완료 시 Google 설정 영역 이동을 확인했다.
- JS 구조 test는 통과했다. CSS 구조 test는 이 단계와 무관하게 base부터 905줄이었던 `continuous-publishing.css`의 기존 900줄 경계 초과 1건으로 실패했다. 새로 확장한 `dashboard-beta.css`는 893줄이다.
- 외부 연결을 실제로 호출하는 수동 검증은 사용자 확인 범위로 둔다. 빈 설정, 일부 완료, 전체 완료 상태에서 안내와 다음 설정 이동을 확인해야 한다.

## 최종 인계

온보딩 안내는 v0.4.2에 통합됐고, v0.4.3에서는 계정·라이선스 조회가 실패해도 최초 설정 안내가
독립적으로 표시되도록 보완됐다. stable v0.4.3 릴리스에 포함됐으므로 이 기록을 완료 처리한다.
