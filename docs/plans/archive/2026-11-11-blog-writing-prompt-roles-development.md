# 블로그 작성 프롬프트 역할 분리

## 브랜치 정보

- branch: `prompt/blog-writing-roles`
- 시작일: 2026-11-11
- base/parent branch: `dev`
- 상태: `dev`에 병합. 기능 브랜치는 삭제한다.

## 사용자 필요

글 작성 프롬프트가 품질, 사용자 설정 준수, 토큰을 동시에 만족해야 한다. 검색 전략의 도입·키워드 횟수가 프로필 설정을 덮고, 같은 규칙이 여러 파일에 반복된다.

## 목표

- 출력 계약에 우선순위를 한 번만 둔다.
- 도입 형식은 프로필, 제목 형태와 키워드 배치는 전략이 맡는다.
- 검색 키워드 반복 할당량을 위치와 상한으로 바꾼다.
- 글자 수 정의와 이미지 문법은 계약에만 두고, 인물 규칙은 이미지가 있을 때만 붙인다.

## 범위

- `src/applications/blog/writing/prompts/`의 contract, search, discovery, common
- 프로필·문체·이미지 계획 프롬프트와 해당 테스트

## 명시적 비목표

- 생성 후 글자 수, H2 수, 종결 어미 검사와 재생성
- 원고 품질 A/B 비교
- 쇼핑 원고 프롬프트
- 발행 글이 더 좋아진다는 보장

## 결정

Grok 4.7, Grok 4.6, DeepSeek V4.1 Flash 분석을 합쳤다. 도입에서 무조건 먼저 답하라는 문장은 계약에 넣지 않는다. 장면형·공감형 도입을 다시 덮기 때문이다. Muse Spark 분석은 학습 데이터 제한으로 결과가 없다.

## 검증

- `node --test`로 블로그 프롬프트, 이미지 계획, 프로필 프롬프트, 문체, 미리보기 테스트 34개 통과
- 전체 유닛 스위트: 2,631개 중 2,630개 통과, 0개 실패, 1개 건너뜀. `npm audit --audit-level=high`는 moderate 39건을 보고했고 스위트를 막지 않았다.
- 첫 스위트는 `supabase/inventory.json`에 GPT 카탈로그 순서 SQL 두 파일이 없어 1건 실패했다. 인벤토리에 등록한 뒤 다시 통과했다. 그 차이는 프롬프트 변경이 아니라 부모 `dev`의 모델 순서 커밋에서 왔다.
- 기본 검색 조립 프롬프트는 5,882자에서 5,390자로 줄었다. 발견 글은 5,147자에서 5,188자로 늘었다.
- 같은 주제 원고 비교는 하지 않았다.

## 남은 위험

설정 준수와 문장 품질은 여전히 모델 출력에 달려 있다. 길이·H2·종결 어미의 생성 후 검사는 없다.
