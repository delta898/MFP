# v0.4.3 Issue 8 SNS Publish Busy State Development Record

## Branch
- Branch: `codex/fix/v0.4.3-issue-8-sns-publish-busy-state`

- Start date: 2026-09-05
- Status: complete; approved for merge

## User Need
When a manual SNS publish uses local images, the UI must clearly show that publishing is in progress and must prevent duplicate actions while Google Drive upload and Buffer publishing are running.

## Goal
Fix GitHub issue #8 by adding one reliable manual SNS publishing busy state that disables conflicting controls and keeps visible progress until the publish request settles.

## Scope
- Add an explicit in-flight state for manual SNS publishing.
- Keep the publish button disabled while local image reading, Google Drive upload, and Buffer publication are running.
- Disable channel, text optimization, image source, local image add/remove, and drag/drop changes during publication.
- Preserve existing validation and result rendering.

## Non-goals
- No changes to Buffer API behavior.
- No live SNS publishing tests.
- No unrelated SNS layout polish.

## Implementation
- Added `manualSnsPublishingInFlight` as the single manual SNS publish busy state.
- The publish handler now sets the busy state before local file reading, Google Drive upload, and Buffer publication, then clears it only after the request settles.
- Composer sync now disables the publish button, AI optimization, text input, channel selection, image source controls, file picker, URL input, image removal, and drag reordering while publishing is in flight.
- Added a small loading spinner style to the manual SNS publish button.
- Corrected the spinner to use a locally defined keyframe and added an explicit disabled appearance so the busy lock is visible as well as functional.
- The composer now remembers the last fully successful publish signature. An unchanged composition shows `발행 완료` and stays disabled; changing text, channels, image source, local images, or image order enables publication again.
- Partial and failed results remain retryable.

## Follow-up Decision
- The same state contract should eventually apply to every BlogGenius publish action, not only manual SNS publishing.
- That cross-surface standardization is recorded separately in `docs/backlog.md` as `공통 발행 버튼 상태 계약`; it is intentionally outside this issue branch.
