## 사용자 필요와 목표

원고 텍스트가 준비된 뒤에도 이미지 생성은 오래 걸릴 수 있다. 이때 취소하면 현재 이미지 HTTP 요청, 재시도 대기, KIE 비동기 작업의 로컬 폴링·다운로드를 멈추고 다음 이미지를 만들지 않아야 한다. 취소 전에 생성된 원고 파일·일부 이미지는 해당 작업의 임시 산출물로만 정리하고 이전 유효 원고는 유지한다.

## 범위

- Blog Beta AI 원고 생성의 이미지 모델 설정 snapshot과 signal 전달
- Gemini·OpenAI 이미지 요청·결과 다운로드·재시도 대기 중단, 취소 후 파일 쓰기 방지
- KIE Market 이미지의 제출·폴링·다운로드 단계 취소 및 작업 저널에 로컬 취소 기록
- 제출 중 취소가 들어오면 응답 또는 기존 제출 제한시간까지 기다려 작업 ID를 확보하고, 이후 로컬 폴링·다운로드를 멈춤
- 작업별 임시 생성 폴더의 소유권과 취소·실패 시 안전한 정리
- 모의 HTTP·파일 시스템·생성 흐름 집중 테스트

## 비범위

- KIE가 공식적으로 제공하지 않는 원격 작업 강제 종료나 크레딧 환급 보장
- UI 취소 버튼·진행 안내(다음 sub-feature)
- 기존 Blog 화면, 발행·댓글·discovery의 취소
- 유료 모델을 실제 호출하는 검사

## 제안 설계와 영향 경계

공통 `signal`을 이미지 transport까지 전달하고, `AI_GENERATION_CANCELED`가 일반 이미지 실패 catch에 흡수되지 않게 한다. KIE 제출 응답 전에는 원격 접수 여부가 불확실해 제출 요청을 무조건 끊지 않는다. 성공 응답에 작업 ID가 있으면 기록한 뒤 중단하고, 시간 초과라면 원격 상태 미확정으로 남긴다.

원고 생성용 작업 디렉터리를 미리보기 등록 전부터 고유하게 추적한다. 취소·실패 시 이 작업이 소유한 경로만 정리한다. 성공 시 기존 Draft 반입/preview 정리 흐름을 보존한다.

## 결정과 트레이드오프

- 취소는 로컬 결과 반영을 막는 계약이고, KIE의 원격 계산 종료를 뜻하지 않는다.
- KIE 제출 중에는 최대 기존 제한시간까지 `cancel_requested`로 남을 수 있다. ID 확보를 우선해 추적 불가능한 원격 작업을 줄인다.
- 경로 정리는 공용 workspace나 이전 Draft를 대상으로 하지 않는다. 작업 ID/디렉터리 소유권 확인이 필수다.

- 2026-09-23: Blog Beta AI 원고 작업 시작 시 이미지 모델 설정을 snapshot으로 고정하고, 생성 서비스→Core→Gemini/OpenAI/KIE image transport로 signal을 전달했다. 일반 이미지 실패는 기존처럼 프롬프트를 유지하지만, 취소는 즉시 상위 작업으로 전파한다.
- 2026-09-23: KIE 제출은 기존 30초 제한 내에서 응답을 기다린다. ID 수신 후 취소면 `locally_canceled`를 journal에 기록하고 로컬 폴링·다운로드를 멈춘다. 제출 오류가 먼저 나면 원격 접수 미확정 정보를 취소 오류에 남긴다. 원격 작업 종료나 환급은 주장하지 않는다.
- 2026-09-23: AI 원고마다 고유 임시 디렉터리를 미리 할당·표시하고, 실패·취소·Draft 반입 완료 시 이 경로만 정리한다. 이전 Draft 폴더는 보존한다. 구현 과정에서 취소 오류의 `remoteStatusUnknown` 속성이 상위로 전파되도록 보완했다.
- 2026-09-23: 관련 집중 검사 63개와 diff 검사를 통과했다. 사용자 요청에 따라 parent에 병합하고 sub-feature 브랜치를 정리한다.

## 결과와 검증

- 구현 결과: 이미지 HTTP 요청, 재시도 대기, KIE 폴링·다운로드 취소와 작업별 임시 파일 정리를 연결했다. 사용자에게 보이는 취소 버튼은 다음 UI 단계 범위다.
- 자동 검증: 이미지·KIE·서비스 관련 5개 테스트 파일 58개와 Core·임시 작업공간 관련 2개 파일 5개, 총 63개 통과. `git diff --check` 통과. 실제 유료 API 호출은 하지 않았다. UI 변경이 없으므로 이 단계에서 browser smoke는 불필요.
- 수동 확인: 최종 UI 연결 후 실제 이미지 생성 취소와 KIE 과금 안내를 사용자가 확인한다.
- 남은 위험: KIE 제출 응답이 시간 초과되면 원격 접수 여부를 알 수 없을 수 있다.
