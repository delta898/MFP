# v0.4.1 Dashboard 제작자 콘텐츠·정식 전환 개발 기록

## Branch

- Branch: `codex/feature/v0.4.1-dashboard-content-productization`
- Base/parent branch: `codex/feature/v0.4.1-dashboard-upgrade`
- Start date: 2026-09-03
- Status: 완료, parent 병합 준비

## 사용자 필요와 목표

기존 Dashboard에 고정되어 있던 개발자의 블로그·YouTube·Instagram 노출을 사용자 계정이나 운영 통계처럼 보이지 않게 정리한다. 이미 운영 가능한 Supabase surface content를 이용해 선별된 제작자 콘텐츠를 `BlogGenius 활용 팁`으로 한 건씩 순환 제공하고, 검증을 마친 Dashboard Beta를 실제 기본 Dashboard로 정식 전환한다.

## 범위

- Dashboard surface의 `recommendations` 후보 중 30분마다 한 건을 새 Dashboard에 순환 표시
- 제작자 콘텐츠를 사용자 발행 채널과 명확히 분리한 제목·설명·외부 이동
- 원격 콘텐츠가 없거나 잘못됐거나 조회에 실패하면 영역 전체를 숨기는 안전한 빈 상태
- 기존 Dashboard 메뉴 숨김 및 새 Dashboard의 Beta/new 표기 제거
- 기존 Dashboard 구현과 내부 식별자는 삭제하지 않고 유지
- focused UI contract 및 browser smoke 검증
- Supabase 플랜 정책을 기준으로 플랜명, 사용량, 잔여량을 함께 표시
- Ultra도 성공한 콘텐츠 작업을 월간 `usage_count`에 집계하되 quota 제한은 적용하지 않음
- 오늘·이번 주·최근 30일 선택이 통계, 추이, 최근 결과 목록 전체에 일관되게 적용
- 직접 결과 URL이 없을 때 설정된 플랫폼 블로그 홈으로 이동하는 안전한 fallback

## 명시적 비범위

- YouTube·Instagram·블로그 피드의 앱 내 직접 수집
- 광고 성과·클릭 추적·개인화 추천
- 기존 Blog Beta의 정식 메뉴 전환
- release, version, push 또는 배포

## 제안 설계

- 기존 `dashboard.recommendations / compact_card` 계약을 재사용한다.
- 설치별 시작 위치를 달리하되 30분 슬롯마다 다음 후보로 순환한다. Dashboard가 보이는 동안 슬롯 경계를 감지하고, 재진입·포커스·새로고침에서도 현재 슬롯을 재계산한다.
- 카드가 없으면 별도 로딩 실패 문구를 남기지 않고 섹션을 숨긴다.
- 새 Dashboard의 내부 `dashboard-beta` 식별자는 이번 단계에서 유지해 광범위한 호환 변경을 피하고, 사용자에게 보이는 이름만 `대시보드`로 정식화한다.
- 레거시 Dashboard의 메뉴만 숨기며 view와 구현은 비교·복구를 위해 남긴다.

## 사용자와 결정한 사항

- 개발자 채널은 제거하지 않고 유용한 `BlogGenius 활용 팁`으로 활용한다.
- 상세 피드 대신 한 번에 한 건만 표시하고 30분마다 다음 후보로 순환한다.
- 사용자 데이터 및 설정된 발행 채널과 제작자 콘텐츠를 같은 의미로 표현하지 않는다.
- Dashboard는 기존 구현을 유지한 상태에서 새 화면을 기본 진입점으로 사용한다.
- 플랜과 quota 값은 앱의 하드코딩이 아니라 Supabase 라이선스 상태 RPC를 단일 기준으로 사용한다.
- `usage_count`는 플랜 제한 차감 여부와 무관하게 성공 확정된 콘텐츠 작업 수를 뜻한다. Ultra는 월간 사용량을 집계하지만 `remaining=-1`을 유지한다.
- 성과 기간 탭은 숫자뿐 아니라 추이와 결과 목록도 함께 변경한다.
- 결과 URL이 없으면 게시물 URL을 추측하지 않고 설정된 네이버·WordPress 블로그 홈으로 이동한다.

## 구현 단계

1. 독립적인 Dashboard surface 렌더 상태와 새 영역 연결
2. 새 Dashboard의 사용자 노출 명칭 정식화 및 레거시 메뉴 숨김
3. Ultra 월간 사용량 집계와 라이선스 상태 RPC 보정
4. 플랜·사용량 표시와 기간별 통계·추이·결과 링크 개선
5. 30분 콘텐츠 순환과 공식 가이드 후보 풀 정리
6. Development 검증 후 동일 migration의 Production 적용 및 확인
7. 사용자 UI 확인 후 완료 기록 및 parent merge 준비

## 진행 및 변경 기록

- 2026-09-03: Dashboard parent에서 제작자 콘텐츠·정식 전환 sub-feature를 시작했다.
- 2026-09-03: 새 Dashboard 메뉴의 Beta/new 표기를 제거하고 `대시보드`로 정식화했으며, 레거시 Dashboard 메뉴는 접근성 트리와 키보드 탐색에서도 숨겼다.
- 2026-09-03: 기존 `dashboard.recommendations` 후보를 설치별 순환 시작점과 절대 30분 슬롯에 따라 한 건 선택해 `BlogGenius 활용 팁`으로 표시한다.
- 2026-09-03: Dashboard surface를 레거시 화면과 새 화면이 각각 렌더링해도 캐시 서명이 충돌하지 않도록 surface와 대상 region 조합별 UI 상태로 분리했다.
- 2026-09-03: 원격 후보가 없으면 활용 팁 섹션을 숨기고, 기존 정상 콘텐츠가 있는 상태의 일시적 조회 실패는 마지막 정상 화면을 유지한다.
- 2026-09-03: focused Dashboard UI contract 10개와 browser smoke 176 fixture requests를 통과했다. 전체 단위 테스트는 이번 단계에서 실행하지 않았다.
- 2026-09-03: 사용자가 제공한 설치·연동·글쓰기·SEO 가이드 8건을 모든 유효 플랜의 Dashboard 일일 추천 후보로 등록하는 재실행 가능한 운영 SQL을 추가했다. 현재 CLI 연결 대상이 production이고 개발 앱 대상과 달라 원격 적용 전 환경을 분리해 확인한다.
- 2026-09-03: 로그인된 Supabase 관리 화면에서 `BlogGenius Development` 프로젝트를 명시적으로 확인한 뒤 운영 SQL을 적용했다. 결과 집계에서 가이드 8건 모두 active content, published/all-plans campaign, active compact-card placement임을 확인했다. Production에는 적용하지 않았다.
- 2026-09-03: 사용자는 일일 고정 대신 30분 순환, 플랜명과 사용·잔여량 동시 표시, 기간별 성과 목록·추이 동기화, 결과 URL 부재 시 블로그 홈 이동을 요청했다.
- 2026-09-03: Pro는 제한형이고 Ultra가 무제한임을 재확인했다. Ultra 적용 사례가 없는 현재 시점에 `usage_count`를 모든 플랜의 성공 콘텐츠 작업 수로 통일하고, 차감·차단 여부는 `quota_units`와 `quota_mode`로 분리하기로 결정했다.
- 2026-09-03: DB 변경은 순서가 있는 migration으로 관리하고 Development 검증 후 동일 migration을 Production에도 적용하기로 사용자와 합의했다.
- 2026-09-03: Ultra의 성공 확정 작업을 월간 사용량에 한 번만 집계하고, 중복 확정은 재집계하지 않으며, 만료된 집계 주기는 0회로 보고하는 DB 계약을 local pgTAP과 Development·Production 롤백 트랜잭션에서 확인했다.
- 2026-09-03: Development와 Production에 동일한 Ultra 사용량 migration을 적용했다. Production의 Supabase CLI migration 이력이 기존 실제 스키마와 동기화되지 않아 과거 migration 전체를 재실행하는 `db push`는 중단하고, 이번 SQL만 명시적으로 적용·검증했다. 기존 migration 이력 정합화는 별도 운영 안전 작업으로 남긴다.
- 2026-09-03: 공식 가이드 8건과 노출 정책을 Development와 Production에 적용했다. 두 환경 모두 공식 가이드 8건이 published/all-plans/active이며, Production에 실제 존재하던 이전 제한 노출 캠페인 3건은 삭제하지 않고 paused/inactive로 전환했다.
- 2026-09-03: 기간별 통계 read model은 오늘·이번 주·최근 30일마다 별도의 집계, 추이, 최근 결과를 제공하도록 변경했다. 직접 결과 URL이 없으면 안전성이 확인된 설정 블로그 홈만 fallback으로 제공한다.
- 2026-09-03: 최종 focused 계약 58개, browser smoke 183 fixture requests, 전체 단위 테스트 1,284개를 통과했다.
