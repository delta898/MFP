## 사용자 필요와 목표

네이버 블로그와 WordPress 연결 확인을 마친 뒤 앱을 재시작하면 대시보드가 두 채널을 다시 `확인 필요`로 표시한다. 저장된 인증 정보가 유효한 경우 사용자가 설정 화면을 다시 방문하거나 접속 확인 버튼을 누르지 않아도 대시보드가 현재 연결 상태를 스스로 확인해 보여줘야 한다.

## 현재 원인

- 네이버 인증 파일은 디스크에 남지만, 대시보드는 현재 프로세스에서 수행한 세션 검사 결과만 조회한다. 앱 재시작 직후에는 상태가 `not_checked`이므로 `확인 필요`가 표시된다.
- WordPress 설정은 남지만, 마지막 검증 결과는 프로세스 메모리의 서명별 Map에만 저장된다. 앱 재시작 시 Map이 비어 있어 `확인 필요`가 표시된다.
- 설정 화면은 별도 접속 확인 API를 호출해 메모리 상태를 갱신하므로, 설정을 방문한 뒤에야 대시보드 표시가 바뀐다.

## 범위

1. 저장된 네이버 세션과 WordPress 설정이 있으면 대시보드 조회 흐름에서 현재 연결 상태를 자동 검증한다.
2. 네이버와 WordPress 검증 결과를 설정 화면과 대시보드가 동일한 런타임 상태에서 읽도록 한다.
3. 같은 검증이 동시에 여러 번 실행되지 않도록 in-flight 요청을 공유한다.
4. 최근 성공 검증은 짧은 TTL 동안 재사용해 화면 이동이나 대시보드 폴링이 외부 접속을 반복하지 않게 한다.
5. 연결 실패·미설정·검증 중 상태를 구분하고, 검증 실패가 전체 대시보드 로딩을 막지 않게 한다.

## 명시적 비범위

- 네이버 인증 방식을 OAuth 2.0으로 교체하는 작업
- WordPress 비밀번호나 네이버 세션 내용을 새 저장소에 복제하는 작업
- 사용자의 계정으로 실제 발행을 수행하는 테스트
- 대시보드 전체 UI 재설계
- 버전 변경, 커밋, parent merge, push 및 배포

## 제안 설계

- 연결 상태의 단일 소유자를 런타임 서비스 경계에 둔다.
- 대시보드 계정 개요가 연결 상태를 요청할 때, 캐시가 없거나 만료되었으면 네이버와 WordPress를 병렬로 검증한다.
- 네이버는 기존 인증 파일을 사용하는 비대화형 세션 검사만 수행한다. 유효하지 않으면 로그인 필요 상태로 정규화한다.
- WordPress는 저장된 URL·사용자·앱 비밀번호로 권한을 읽기 전용 검증하고, 기존 서명 기반 상태 저장소에 결과를 기록한다.
- 검증 promise를 공유해 앱 시작 시 여러 UI 요청이 겹쳐도 채널별 외부 확인은 한 번만 실행한다.
- 설정 변경 또는 사용자의 강제 접속 확인은 캐시를 우회하고 최신 결과를 기록한다.

## 구현 단계

1. 재시작 직후 상태가 `unverified`가 되는 계약을 테스트로 재현한다.
2. 공통 연결 readiness 검증 흐름과 TTL/in-flight 중복 방지를 구현한다.
3. 계정 개요와 설정 API가 동일한 상태를 사용하도록 연결한다.
4. 대시보드 focused contract/browser fixture를 보강한다.
5. 관련 단위·UI 자동 검증을 수행하고 사용자의 실제 앱 재시작 확인 항목을 정리한다.

## 사용자와 결정한 사항

- v0.4.1 parent에서 별도 sub-feature branch로 진행한다.
- 앱을 다시 켤 때 사용자가 설정 화면을 먼저 방문하지 않아도 연결 상태가 자동으로 복원되어야 한다.
- 단순히 과거 성공 표시를 영구 보존하지 않고, 저장된 인증 정보로 현재 유효성을 다시 확인한다.

## 진행 및 변경 기록

- 2026-09-02: parent branch에서 sub-feature branch와 개발 기록을 생성했다.
- 2026-09-02: 네이버는 인증 파일과 검사 결과가 분리되어 있고, WordPress 검증 결과는 프로세스 메모리에만 존재해 재시작 후 두 채널 모두 `unverified`가 되는 원인을 확인했다.
- 2026-09-02: 공통 connection readiness 서비스를 추가했다. 계정 개요 요청 시 저장된 네이버 세션과 WordPress 설정을 병렬 검증하며, WordPress는 최근 결과를 2분간 재사용하고 동시 요청은 같은 Promise를 공유한다.
- 2026-09-02: WordPress 중복 요청 식별에는 설정 원문 대신 SHA-256 서명을 사용해 앱 비밀번호가 추가 상태값으로 남지 않게 했다.
- 2026-09-02: 대시보드의 계정 개요가 단순 메모리 peek보다 공통 readiness 결과를 우선 사용하도록 연결했다. 설정 화면의 수동 확인 결과도 기존 공통 상태 저장소에 기록되므로 이후 대시보드 조회와 같은 판정을 사용한다.
- 2026-09-02: 사용자가 실제 앱을 종료·재실행한 뒤 설정 화면을 방문하지 않고 대시보드에서 네이버와 WordPress가 모두 `확인됨`으로 복원되는 것을 확인했다. 최초 실제 검증에 걸리는 시간은 체감상 다소 길지만 정확성을 우선하는 현재 범위에서는 수용했다.
