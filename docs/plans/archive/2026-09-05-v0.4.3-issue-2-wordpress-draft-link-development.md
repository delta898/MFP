## User Need
Dashboard results must not label or open a WordPress draft as a public post. WordPress draft permalinks can return 404 to a normal browser session.

## Goal
Route draft completion results to a usable WordPress destination while preserving direct post links for public publications.

## Scope
- Trace the canonical draft/public result metadata into the Dashboard read model.
- For WordPress drafts, use the configured WordPress site home as the navigation fallback and label it as a blog destination.
- Preserve public and scheduled result-link behavior unless their existing contract is demonstrably incorrect.
- Add focused regression coverage and UI browser coverage where fixtures expose this result.

## Non-goals
- No WordPress authentication or publishing changes.
- No redesign of the Dashboard result card.
- No attempt to expose a private WordPress editor URL.

## Proposed Design
Navigation semantics belong in the Dashboard result read model: draft status takes precedence over a stored result reference, because the reference is not guaranteed to be publicly accessible. Platform-home resolution remains the safe fallback.

## Implementation Progress
- Confirmed that the Dashboard read model selected any stored `result_ref` before considering `post_status`, so a WordPress draft permalink was exposed as a public `글 보기` destination.
- Draft result references are now excluded from the public result URL contract. Dashboard navigation falls back to the configured platform home and therefore renders `블로그 열기`.
- Public result URLs retain their existing direct navigation behavior. Scheduled results are unchanged in this issue.
