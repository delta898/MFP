# 포스팅 진행 안내와 완료 링크 개발 기록

## Branch

- Branch: `codex/feat/publishing-progress-links`
- Base/parent branch: `dev`
- Start date: 2026-09-04
- Status: 완료 및 `dev` 병합 준비

## 사용자 필요와 목표

Blog Beta에서 포스팅 중이라는 한 문장만 보여주는 대신 현재 어떤 단계가 진행 중인지 사용자가 이해할 수 있게 안내한다. 포스팅이 끝나면 결과를 다시 찾지 않아도 완료 상태에서 바로 해당 채널로 이동할 수 있게 한다.

## 범위

- Blog Beta 상단 공통 발행 상태의 사용자용 진행 단계 구체화
- 기존 progress callback과 runner 상태 계약을 활용한 단계별 문구
- 임시 저장 완료 시 해당 블로그 홈으로 이동하는 링크
- 공개 발행 완료 시 가능한 경우 실제 게시물로 이동하는 링크
- Naver와 WordPress의 플랫폼별 결과 링크를 손실 없이 전달하는 공통 결과 계약
- 관련 서비스·UI 계약 및 browser smoke 회귀 검증

## 명시적 비범위

- 개발자용 상세 로그를 UI에 그대로 노출
- 포스팅 엔진의 발행 절차 자체 변경
- 예약 등록 결과 링크
- 과거 발행 이력 전체에 대한 링크 복구
- 버전 변경, release, push 또는 배포

## 제안 설계

- 진행 문구는 사용자가 이해할 수 있는 소수의 단계로 정규화한다. 내부 selector, 재시도 횟수, 브라우저 자동화 구현 세부사항은 노출하지 않는다.
- 완료 링크는 추측해서 만들지 않는다. 임시 저장은 설정된 채널의 안전한 홈 URL을 사용하고, 공개 발행은 발행 결과가 실제 게시물 URL을 제공한 경우에만 노출한다.
- 복수 채널은 성공한 채널별 결과를 배열로 전달해 일부 성공과 링크 유무를 독립적으로 표현한다.
- 기존 상단 상태 패널을 유지하고 성공 완료 상태에만 간결한 이동 액션을 추가한다.

## 구현 단계

1. 현재 progress callback과 Naver·WordPress 발행 결과 URL의 생성·소비 경로를 조사한다.
2. 사용자용 진행 단계와 플랫폼 결과 링크 계약을 정의한다.
3. 서비스와 Blog Beta 상태 UI를 연결한다.
4. focused test와 browser smoke를 실행하고 사용자 UI 확인 항목을 정리한다.

## 사용자와 결정한 사항

- 진행 상태는 로그 수준의 세부 정보가 아니라 사용자 안내 수준으로 구체화한다.
- 임시 저장은 블로그 자체로, 공개 발행은 해당 글 링크로 이동한다.
- 별도 feature branch에서 구현한다.
- 사용자 UI 확인을 완료했으며, 기능 마무리와 `dev` 병합을 승인했다.

## 현재 결과와 검증

- 내부 progress 메시지를 `준비 중`, `글 작성 중`, `이미지 준비 중`, `발행 준비 중`, `임시 저장/공개 발행 중`, `마무리 중`의 사용자용 단계로 정규화했다.
- 연속 발행과 Blog Beta의 직접 원고 발행이 같은 완료 링크 계약을 사용하도록 연결했다.
- 임시 저장 성공 시 성공한 채널의 블로그 홈 링크를, 공개 발행 성공 시 응답에 포함된 실제 게시물 링크를 표시한다. 예약 등록, 실패 채널, 비 HTTP(S) URL에는 링크를 표시하지 않는다.
- 완료 링크는 새 탭에서 열고 `noopener noreferrer`를 적용하며, 복수 채널 성공 시 최대 두 개까지 표시한다.
- focused service, presentation, UI shell tests 61건 통과.
- browser UI smoke test 통과(183 fixture requests). 진행 제목 변경과 임시 저장 완료 링크 렌더링·목적지를 확인했다.
- 실제 네이버/WordPress 발행 및 유료 AI 호출은 자동 검증 범위에서 제외했다.

## 남은 위험 및 후속 작업

- Naver 임시 저장 결과에서 초안 자체의 안정적인 URL을 얻을 수 없으면 블로그 홈 링크만 제공한다.
- 플랫폼별 공개 발행 응답이 실제 게시물 URL을 일관되게 반환하는지는 사용자 환경에서 확인이 필요하다. URL이 없으면 잘못된 목적지를 추측하지 않고 링크를 생략한다.
- 복수 채널 일부 성공 시 상태 문구와 액션 수가 복잡해지지 않도록 최소 UI를 유지한다.
