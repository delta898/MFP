- Base/parent branch: `codex/feature/v0.4.1-dashboard-upgrade-02-main`
- Start date: 2026-09-03
- Status: 자동 검증 완료, 사용자 UI 확인 대기

## 사용자 필요와 목표

Dashboard를 운영 정보 중심으로 유지하면서도 개발자 후원이나 관련 콘텐츠를 매번 강요하지 않고 가끔 발견할 수 있는 작은 teaser로 제공한다. 고정 광고나 팝업이 아니라 활용 팁 사이에 드물게 만나는 새로운 카드처럼 느껴져야 한다.

## 범위

- `app_surface_contents` 기반 후원 teaser 전용 surface region
- Dashboard 하단의 독립적이고 비차단적인 카드
- 낮은 노출 빈도와 로컬 마지막 노출 시각 기반 간격 제어
- 운영상 확인이 필요한 상태나 글 발행 중에는 노출 억제
- 명시적인 외부 CTA
- focused contract 및 browser smoke 검증

## 명시적 비범위

- 내부 도움말·가이드 화면 구현
- 결제·후원 처리 또는 사용자 계정과 후원 상태 연동
- Supabase 운영 콘텐츠의 실제 문구·URL 확정 또는 production 데이터 변경
- release, push 또는 배포

## 사용자와 결정한 사항

- 후원 teaser는 Dashboard에 항상 나타나지 않고 간헐적으로만 노출한다.
- 활용 팁의 30분 순환과는 별도 정책을 사용한다.
- 사용자는 dismiss가 작은 teaser에 불필요한 제어와 정책을 추가할 수 있다고 판단했다.
- 첫 구현은 모든 플랜에 같은 후원 콘텐츠를 드물게 노출하되 닫기 기능은 두지 않는 단순한 MVP로 확정했다.

## 제안 설계

- 원격 콘텐츠는 기존 surface-content 조회·정규화·안전한 링크 렌더링 계약을 재사용한다.
- teaser가 없어도 Dashboard의 연결 상태·운영 정보·성과·추천·활용 팁은 정상 동작한다.
- 발행 중이거나 연결 상태에 확인이 필요한 경우에는 teaser를 숨겨 사용자의 우선 조치를 방해하지 않는다.
- 노출 여부는 개인정보나 임의 추적 식별자 없이 로컬 마지막 노출 시각만으로 결정한다.
- 후원은 유료 플랜과 다른 자발적 행동이므로 현재 teaser는 플랜으로 제외하지 않는다. 향후 유료화 안내는 별도 캠페인과 내부 이동 행동으로 설계한다.

## 진행 및 변경 기록

- 2026-09-03: Dashboard 2차 고도화 parent에서 두 번째 sub-feature를 시작했다.
- 2026-09-03: 기존 `dashboard.supporting` placement에 이미 등록된 `support` 종류만 선별해 재사용하기로 했다. 신규 table이나 production migration은 필요하지 않다.
- 2026-09-03: 첫 노출 또는 마지막 노출로부터 3일이 지난 앱 실행에서만 teaser를 열고, 같은 앱 실행 중에는 유지한다.
- 2026-09-03: 네이버·WordPress 연결 확인이 필요하거나 발행이 실행·실패·중단 상태일 때는 teaser를 숨겨 우선 조치를 방해하지 않도록 했다.
- 2026-09-03: 첫 UI 검토 전에 사용자와 다시 논의해 `오늘은 그만 보기`와 dismiss 상태를 제거했다. 작은 비차단 카드에는 낮은 노출 빈도만으로 충분하며, 불필요한 제어를 없애는 편이 제품 방향에 맞는다고 결정했다.

## 최종 결과 및 검증

- Dashboard가 정상 운영 상태이고 정규 노출 간격이 지난 경우에만 원격 `support` 콘텐츠 한 건을 작은 teaser로 표시한다.
- 같은 앱 실행 중에는 카드가 유지되고 별도 닫기 제어는 제공하지 않는다.
- 발행 중·실패·중단 또는 네이버·WordPress 연결 확인 필요 상태에서는 teaser를 표시하지 않는다.
- 원격 콘텐츠 누락·조회 실패·로컬 저장소 접근 실패가 Dashboard 핵심 정보에 영향을 주지 않는다.
- focused UI/script/style contract: `node --test scripts/dashboard-beta-shell-contract.test.js scripts/ui-style-structure.test.js scripts/ui-script-structure.test.js` 통과 (14 tests)
- browser smoke: 닫기 제거 후 `npm run test:ui-browser` 재실행 통과 (176 fixture requests)
- diff validation: `git diff --check` 통과
- 전체 unit suite는 사용자 UI 확인 뒤 parent 병합 후보가 될 때 수행한다.
- 사용자 확인 필요: teaser의 실제 크기와 위치, `가끔 만나는 이야기` 문구와 CTA 동선.
