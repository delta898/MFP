# 네이버 스마트 댓글 개선 계획

## 1. 목적

`블로그 > 스마트 댓글(네이버)`이 로그인 사용자의 이웃새글을 안정적으로 찾고, 이웃새글 카드에 표시된 제목과 본문 일부의 맥락을 반영한 자연스러운 한국어 댓글 초안 3개를 제안하도록 개선한다.

현재 기능의 안전한 역할은 유지한다.

- BlogGenius는 댓글 초안만 생성한다.
- 사용자가 초안을 검토하고 복사한 뒤 네이버에서 직접 댓글을 등록한다.
- 자동 공감, 자동 댓글 등록, 대량 반복 실행은 이번 범위에 포함하지 않는다.

## 2. 확인된 문제

### 2.1 후보 수집

- 저장된 네이버 로그인 세션을 후보 수집 브라우저에 적용하지 않는다.
- `https://blog.naver.com`의 광범위한 `article, li, div`를 탐색해 이웃새글이 아닌 핫토픽과 상위 UI 요소까지 후보로 오인한다.
- 실제 글 제목 대신 `핫토픽` 같은 섹션 제목이 수집될 수 있다.
- 현재 네이버 DOM에서는 기존 공감 상태 및 댓글 링크 selector가 발견되지 않는다.
- 고정 2.5초 대기만 사용하며 명시적인 화면 준비 조건과 제한된 추가 로딩 절차가 없다.

### 2.2 이웃새글 카드와 AI 입력

- 후보 카드 경계를 정확히 찾지 못해 실제 글 제목 대신 섹션 제목이 AI에 전달될 수 있다.
- 본문 일부를 기계적으로 자르면 문장 중간에서 끊겨 프롬프트 품질이 낮아질 수 있다.
- 모델별 JSON 준수 차이를 흡수할 구조화 출력 계약이 약하다.

### 2.3 품질 검증

- 영어 조각, 지나치게 짧은 답변, 미완성 문장도 댓글 후보로 허용한다.
- JSON 파싱 실패 시 응답의 임의 따옴표 문자열을 댓글로 채택한다.
- 정확히 3개인지, 서로 충분히 다른지, 본문과 관련되는지를 검증하지 않는다.

### 2.4 실행 상태와 운영성

- 후보 0건과 AI 전체 실패도 전체 작업 완료처럼 보일 수 있다.
- 후보별 AI 호출이 순차 실행되며 최대 대기시간이 지나치게 길어질 수 있다.
- 실행 중 버튼 잠금과 중복 실행 방지가 없다.
- 후보 수집 전에 단계 로그가 없어 브라우저·세션·DOM 실패를 진단하기 어렵다.
- 스마트 댓글 전용 수집기 및 서비스 테스트가 없다.

## 3. 목표 구조

```text
Smart Comment Orchestrator
├─ Naver Session Guard
├─ Neighbor Feed Collector
├─ Comment Context Builder
├─ Comment Draft Generator
├─ Draft Quality Validator
└─ Result/Progress Mapper
```

UI API 서비스가 Playwright DOM 세부사항과 AI 응답 복구 규칙을 직접 소유하지 않도록 각 책임을 분리한다.

## 4. 단계별 구현

### Phase 1. 기준선과 계약

- 기존 UI/API 요청 형식과 저장 설정의 하위 호환 범위를 정리한다.
- 후보, 본문, 댓글 초안, 단계별 결과의 내부 계약을 정의한다.
- 실패 상태를 다음처럼 구분한다.
  - `session_required`
  - `candidate_collection_failed`
  - `no_candidates`
  - `candidate_context_invalid`
  - `draft_generation_failed`
  - `partial_success`
  - `success`
- 전체 본문과 AI 원문 응답은 일반 로그에 기록하지 않는다.

### Phase 2. 로그인 기반 이웃새글 수집기

- 실행 전에 저장된 네이버 인증 파일과 로그인 세션을 확인한다.
- 새 browser context에 `storageState`를 적용한다.
- 변경 가능성이 낮은 `https://blog.naver.com`을 진입점으로 사용하고 네이버의 리디렉션을 그대로 따른다.
- 최종 URL 경로와 쿼리를 제품 코드에 고정하지 않고, 최종 화면의 `이웃새글` 영역을 기준으로 수집한다.
- 상단 핫토픽 영역은 제외하고 `이웃새글` 제목 아래에 배치된 글 카드만 후보로 수집한다.
- 페이지 준비는 고정 sleep 대신 핵심 컨테이너/후보 카드 조건으로 확인한다.
- 후보 카드에 한정된 selector로 작성자, 실제 제목, URL, 썸네일을 추출한다.
- 자기 블로그, 잘못된 URL, 중복 URL을 제외한다.
- 공감 상태는 신뢰할 수 있을 때만 사용하고, 알 수 없으면 필터 조건으로 단정하지 않는다.
- 제한된 스크롤 또는 추가 로딩만 허용하며 요청한 후보 수에 도달하면 중단한다.

### Phase 3. AI 입력 context 구성

- 1차 범위에서는 후보 글 URL을 다시 열어 전체 본문을 읽지 않는다.
- 로그인된 이웃새글 카드에 실제로 표시된 작성자, 정확한 제목, 본문 일부만 사용한다.
- 메뉴, 섹션 제목, 프로필 문구, 댓글 수와 광고 문구가 context에 섞이지 않도록 후보 카드 내부에서만 추출한다.
- 본문 일부는 문장 경계를 우선해 정규화하고 최대 약 300~400자로 제한한다.
- 별도 AI 요약 호출을 사용하지 않아 후보별 비용과 실행 시간을 예측 가능하게 유지한다.
- 제목 또는 본문 일부가 비어 있거나 카드 경계를 신뢰할 수 없으면 AI 호출 없이 해당 후보를 제외한다.
- 전체 본문이 필요한 정밀 생성 모드는 실제 사용 결과를 본 뒤 별도 후속 기능으로 검토한다.

### Phase 4. 프롬프트와 구조화 출력

- 프롬프트에 다음을 명시한다.
  - 글의 구체적인 소재 또는 경험을 하나 이상 자연스럽게 언급
  - 본문에 없는 사실, 방문 경험, 구매 경험을 지어내지 않음
  - 단순 감탄만으로 끝내지 않음
  - 질문형은 본문에서 답이 이미 나온 질문을 반복하지 않음
  - 자연스러운 존댓말과 완결된 한국어 문장 사용
  - 서로 관점이 다른 후보 3개 생성
- 모델 transport가 지원하면 JSON 응답 형식을 요청하고, 그렇지 않아도 동일한 응답 계약을 검증한다.
- 프롬프트 버전을 코드 상수로 관리해 결과와 회귀 테스트의 기준을 남긴다.

### Phase 5. 댓글 품질 검증과 제한적 재생성

- 다음 기준을 모두 만족한 초안만 허용한다.
  - 정확히 3개
  - 설정된 최대 글자 수 이내
  - 합리적인 최소 길이 이상
  - 한국어 중심의 완결된 문장
  - `No`, `fine)` 같은 조각이나 JSON/메타 문구 제외
  - 세 초안 간 과도한 중복 제외
  - 제목 또는 본문 핵심어와 최소한의 연관성 확보
- 임의의 따옴표 문자열을 수집하는 기존 fallback을 제거한다.
- 품질 실패 시 실패 이유를 포함해 후보별 최대 1회만 재생성한다.
- 네트워크 재시도와 품질 재생성을 별도 예산으로 관리해 무제한 지연을 막는다.

### Phase 6. 실행 상태와 UI

- `세션 확인 → 이웃새글 수집 → 댓글 생성 → 완료` 단계를 표시한다.
- 실행 중 저장/실행 버튼을 잠그고 동일 작업 중복 실행을 막는다.
- 성공 후보 수와 실패 후보 수를 별도로 표시한다.
- 후보가 없을 때는 성공 완료가 아니라 원인별 안내를 제공한다.
- 카드에는 실제 제목, 본문 기반 요약, 후보별 오류를 명확히 표시한다.
- 기존 복사, 다시 생성, 글로 이동 동작은 유지한다.

### Phase 7. 테스트와 실제 검증

- DOM fixture 기반 후보 수집 테스트
- 로그인 없음/만료/정상 세션 분기 테스트
- 이웃새글 카드의 실제 제목·본문 일부 정규화 테스트
- 정상 JSON, 코드블록 JSON, 불완전 JSON, 영어 조각 응답 테스트
- 품질 검증 및 1회 재생성 테스트
- 후보 0건, 일부 성공, 전체 실패 API/UI 테스트
- 실제 네이버 계정에서는 후보 1개, 보이는 브라우저 모드로 먼저 검증한다.
- 실제 검증 중 댓글 등록이나 공감 클릭은 수행하지 않는다.

## 5. Sub-feature branch 분리 기준

기본 작업 branch는 `codex/feature/naver-smart-comment`이다. 다음 중 하나에 해당하면 현재 branch에서 sub-feature branch를 만든다.

- 네이버 후보/본문 수집기 변경이 독립적으로 리뷰·실제 검증 가능할 때
- AI 프롬프트·품질 검증 변경이 수집기와 독립적으로 테스트 가능할 때
- 한 단계의 변경이 리뷰 가능한 범위를 넘어설 때
- 네이버 DOM 실험 코드와 제품 코드를 분리해야 할 때

예상 sub-feature branch:

- `codex/feature/naver-smart-comment-collector`
- `codex/feature/naver-smart-comment-quality`
- `codex/feature/naver-smart-comment-status`

각 sub-feature branch는 검증 후 `codex/feature/naver-smart-comment`에 먼저 병합하고, 전체 기능 검증이 끝난 뒤 `dev`로 병합한다.

## 6. 완료 조건

- 로그인된 이웃새글에서 요청 수만큼 유효한 후보를 수집한다.
- 카드에 보이는 제목·본문 일부와 AI에 전달되는 context가 일치한다.
- AI가 실제 본문의 구체적인 내용을 반영한 댓글 후보 3개를 생성한다.
- 영어 조각, 미완성 문장, 빈 후보가 UI에 정상 댓글처럼 표시되지 않는다.
- 후보 0건, 부분 실패, 전체 실패가 서로 다른 상태로 전달된다.
- 실행 중 중복 요청이 발생하지 않는다.
- 수집기, 본문 reader, 품질 validator, orchestrator의 자동 테스트가 통과한다.
- 전체 본문이나 민감한 인증 정보가 로그에 남지 않는다.

## 7. 구현 전 확인할 결정

1. 후보의 기준 화면은 네이버의 로그인된 `이웃새글`로 고정한다.
2. 1차 범위에서는 글을 별도로 열지 않고 이웃새글 카드에 보이는 제목과 본문 일부 최대 약 300~400자만 댓글 모델에 전달한다.
3. 품질 미달 시 후보별 재생성은 최대 1회로 제한한다.
4. 이번 개선에서도 자동 댓글 등록과 자동 공감은 지원하지 않는다.

## 8. 구현 결과

- 기존 네이버 인증 상태를 실행 전에 확인하고 저장된 `storageState`로 이웃새글 수집 context를 생성한다.
- `blog.naver.com`에서 리디렉션된 공식 화면의 `이웃새글` 영역과 글 링크 중심의 카드 경계 탐색을 사용하며, 상단 핫토픽·자기 글·이미 공감한 것으로 확인된 글·잘못된 글을 제외한다.
- AI에는 카드에 공개된 제목과 최대 400자의 본문 일부만 전달한다.
- 댓글 생성과 품질 검증을 별도 모듈로 분리하고, 임의 문자열 복구 fallback을 제거했다.
- 정확히 3개, 최대/최소 길이, 한국어 중심, 완결성, 중복 여부를 검사하고 실패 사유를 반영해 최대 한 번만 다시 생성한다.
- 후보 없음, 전체 생성 실패, 부분 성공, 전체 성공을 API 결과에서 구분한다.
- 실행 중 저장/실행 및 후보별 다시 생성 버튼을 잠가 중복 요청을 막는다.
- 실제 네이버 UI 검증은 사용자 검증 단계로 남기고, 자동화 범위에서는 수집기·세션·프롬프트·품질·요약 상태 단위 테스트를 수행한다.
