# Card News Image Model Selection Development

## User need and goal

Let users choose a configured image provider/model from the Card News workflow without navigating to global Settings, while keeping the page compact and making the chosen model persist across app restarts.

## Scope

- Add an optional image-generation override local to the Card News page.
- Offer only image providers with a saved API key and a current successful image-provider connection check, then show that provider's selectable image models from the shared model catalog.
- Do not edit credentials, trigger connection checks, or mutate global AI settings from Card News.
- Inherit the global image model when no local override exists; persist an explicit override locally across restarts.
- Never silently switch away from a selected model when it becomes unusable; explain the issue and preserve the selection so the user can resolve it.
- Keep the provider/model controls compact and consistent with the existing Settings two-dropdown pattern, without an overlay obscuring other Card News fields.
- Reveal model controls progressively: show the active model in a compact disclosure and expose Provider/Model selectors only when opened. Card Settings and existing-result workspaces each have a selector in their stable layout position; both are synchronized to one persisted page-wide choice.
- Add focused contract/behavior tests and the relevant browser regression coverage.

## Non-goals

- Changing Blog image-generation behavior.
- Adding providers, credentials, or model configurations from Card News.
- Silently falling back from an explicit page choice to the global model.
- Changing model defaults or credentials in Settings.
- Release/version changes, commit, merge to `dev`, or branch deletion without a separate user request.

## Design and decisions

- The global image model is the default/inherited selection.
- A user override is a page-level preference persisted in local storage; it survives app restarts and does not alter global Settings.
- The override applies to subsequent Card News image-generation requests, not already-generated images.
- Provider and model selection are a local task choice; credentials and connection checks remain exclusively in Settings. A provider is eligible when its saved image profile has a key and a trusted successful connection verification.
- Once an eligible provider is selected, its selectable image models come from the shared image model catalog, rather than limiting the user to the one model code saved in that provider's profile. The chosen model is resolved server-side with the provider's saved credentials; invalid or rejected models return an explanation without silently switching models.
- The UI uses adjacent Provider and Model dropdowns in a compact row within Card News generation settings. This follows the existing Settings interaction and avoids the prior floating popover covering the additional-request field. The global selection remains the default state.
- On user review, the always-expanded row was judged visually dense and poorly discoverable in existing work, where users may bypass Card Settings. The control is collapsed by default and shows the active model summary. The later stable-placement revision renders one selector in Card Settings and one in the results toolbar; both synchronize immediately and persist to the same page-level preference. This intentionally trades duplicate controls for stable placement and removes DOM reparenting across workflow states. No separate text-model selector is added.
- The latest result-toolbar layout groups settings in the left column and actions in the right: signature upper-left, intentionally blank upper-right, image model lower-left, and workflow buttons lower-right. Signature and model controls share a 360px maximum width. While initial composition is running, the two next-step actions remain visible but disabled; they become actionable after composition. Model dropdown inputs use the shared select-shell affordance and are dismissed by outside pointer interaction or Escape.
- The Korean-text option is a negative checkbox by default (“do not use Korean”). Its UI value is inverted at the boundary to preserve the existing positive `include_korean_text` generation/ZIP setting; existing local preferences are inverted when restored so prior intent is preserved. When Korean is excluded, both composition and image prompts prohibit Hangul only, allow short non-Korean text when contextually appropriate, and continue to prohibit generated logos/watermarks.
- Effective endpoint identity is derived from the shared transport definition. A fixed endpoint is canonicalized even when the saved profile omits its redundant Base URL; configurable endpoints remain part of model-level verification identity. Provider-scoped verification is expressed as transport capability rather than a provider-name special case.
- Verification-state reset is memory-only unless a caller explicitly supplies the isolated state file it owns. Tests configure their temporary file before any reset, preventing accidental writes to project or user runtime state.

## Implementation stages

1. Inspect current image-model config, connection verification records, and Card News generation request boundaries.
2. Implement a shared/explicit selection contract and a read-only API for available verified image configurations if needed.
3. Add Settings-like provider/model dropdowns in Card News and local persistence; thread the selection through all relevant image-generation paths.
4. Add focused tests and browser regression coverage; document outcome and remaining manual checks.
5. Harden test-state reset isolation and make endpoint identity consistent across connection checks, generation requests, and Card News eligibility.
