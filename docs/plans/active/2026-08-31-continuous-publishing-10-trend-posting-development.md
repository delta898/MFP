# 연속 발행 Stage 10: Blog Beta 트렌드 포스팅

## 브랜치 정보

- branch: `feature/continuous-publishing-10-trend-posting`
- 시작일: 2026-08-31
- base/parent branch: `feature/continuous-publishing-main`
- 상태: 자동 검증 완료, 사용자 확인 대기

## 사용자 필요

완전 자동 글감 생성은 지원하지 않되, 이미 수집된 트렌드 키워드를 사용자가 직접 검색하고 선택해
Blog Beta의 빠른 글 작성에서 구체화한 뒤 바로 포스팅하거나 발행 대기열에 추가할 수 있어야 한다.

## 목표

- 기존 `블로그 > 트렌드 포스팅`의 검색 경험을 Blog Beta에 제공한다.
- 트렌드 검색 결과에서 한 키워드를 명시적으로 선택한다.
- 선택한 키워드와 출처 정보를 Blog Beta 빠른 글 작성 폼으로 전달한다.
- 전달 후에는 기존 빠른 글 작성의 직접 처리·글감 보관·발행 대기열 추가 흐름을 그대로 사용한다.
- 기존 `블로그` 메뉴의 트렌드 포스팅과 자동 글감 기능을 변경하지 않는다.

## 명시적 비목표

- Trends/RSS가 자동으로 Topics 행을 만들거나 `발행 준비 완료`로 바꾸지 않는다.
- 선택과 동시에 AI 생성, 라이선스 사용량 차감, 원격 발행 또는 Queue 등록을 실행하지 않는다.
- 기존 `블로그` 메뉴를 숨기거나 제거하지 않는다.
- RSS 탐색 UI를 Blog Beta에 추가하지 않는다.
- 트렌드 API·collector·인증 인프라를 변경하지 않는다.

## 합의된 흐름

1. 사용자가 트렌드 포스팅 화면에서 검색 조건을 정하고 조회한다.
2. 결과에서 키워드 하나를 선택한다.
3. Blog Beta 빠른 글 작성으로 이동하며 선택 키워드를 주제·키워드 출처로 전달한다.
4. 또는 결과 행에서 `글감 보관`을 눌러 키워드와 출처만 보관한다.
5. 빠른 글 작성을 선택한 경우 사용자가 제목·지시사항·발행 계획을 보완한다.
6. 사용자가 직접 바로 포스팅하거나 발행 대기열에 추가한다.

## 제안 설계

- 기존 Trends 조회 service/API를 재사용한다.
- 기존 블로그 DOM·controller를 Blog Beta가 직접 참조하지 않도록 Beta 전용 view/controller를 둔다.
- 빠른 글 작성 전달 값은 화면 전용 상태로 정규화하고 기존 topic capture payload 경계를 재사용한다.
- 선택 동작은 로컬 폼 전환만 수행하고 외부 부작용을 만들지 않는다.

## 구현 단계

1. 기존 트렌드 검색 UI·API와 Blog Beta 빠른 글 작성 입력 경계 조사
2. 최소 트렌드 검색·선택 UI 추가
3. 선택 결과를 빠른 글 작성에 전달하고 편집 가능하게 유지
4. 단위·UI 계약·브라우저 회귀 검증
5. 사용자 수동 확인 후 문서 현행화

## 검증 계획

- 검색 조건과 결과 렌더링이 기존 Trends API 계약을 사용한다.
- 키워드 선택만으로 AI·저장·발행 API가 호출되지 않는다.
- 선택 후 빠른 글 작성의 주제·키워드가 채워지고 편집할 수 있다.
- 기존 바로 포스팅·글감 보관·발행 대기열 추가 동작이 유지된다.
- 기존 `블로그` 트렌드 포스팅과 자동 포스팅 회귀가 유지된다.

- 2026-09-01: 빠른 글 작성의 동작 순서를 `바로 포스팅 → 발행 대기열에 추가 → 글감 보관 → 내용 지우기`로 정리하고 직접 실행을 기본 동작으로 강조했다.
- 2026-09-01: 발행 계획 수정 팝업에서는 `저장 → 바로 포스팅 → 취소` 순서를 유지하며, 바로 포스팅 시 새 행을 만들지 않고 수정한 기존 행을 저장한 뒤 실행하도록 했다.
- 2026-09-01: 작은 UI 변경마다 전체 단위 테스트를 반복하지 않도록 구현 중 집중 테스트, UI 단위 완료 시 브라우저 smoke, 병합·릴리스 및 광범위 경계 변경 시 전체 단위 테스트를 수행하는 기준을 `AGENTS.md`에 명문화했다.
- 2026-09-01: 트렌드 결과의 `빠른 글 작성` 옆에 `글감 보관`을 추가했다. 이 동작은 AI나 발행을 시작하지 않고 기존 트렌드 글감 저장 경계를 통해 Topics Sheet에 `대기` 상태로 저장한다.
- 2026-09-01: 글감 보관 성공은 별도 toast 없이 해당 버튼을 `보관 완료`로 바꾸고 비활성화해 표시한다. 이 표시는 현재 조회 결과에서만 유지되며 새 트렌드 조회가 성공하면 초기화한다.
- 2026-09-01: 보관한 글감 수정 팝업의 동작 문구를 다른 화면과 일치하도록 `저장 → 발행 대기열에 추가 → 취소`로 통일했다.

## 결과

- Blog Beta에 기존 메뉴와 분리된 `트렌드 포스팅` 탭을 추가했다.
- 카테고리 최대 5개, 최신·7일·직접 지정 기간, 결과 내 키워드·변화 필터를 제공한다.
- 결과 행에서 `빠른 글 작성` 또는 `글감 보관`을 선택할 수 있으며, 어느 동작도 자동 발행 대기열 등록은 하지 않는다.
- 선택 후 사용자는 빠른 글 작성에서 자유롭게 수정하고 글감 보관·대기열 추가·바로 포스팅을 선택할 수 있다.
- 기존 `블로그` 메뉴의 트렌드 포스팅·자동 글감 경로는 변경하지 않았다.
