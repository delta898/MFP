# v0.4.1 Dashboard 2차 고도화 개발 기록

- Start date: 2026-09-03
- Status: 진행 중

## 사용자 필요와 목표

1차 Dashboard의 운영 관제 역할은 유지하면서, 기존 Dashboard에만 남아 있던 개인화 `새로운 발견`을 복원하고 공식 가이드로 이동할 수 있는 작은 연결점을 제공한다. 블로그·전자책·후원 등 가이드성 콘텐츠의 본체는 Dashboard 탭으로 확장하지 않고 후속 `도움말·가이드` 화면으로 분리한다.

## 범위

1. 새 Dashboard에 뉴스·트렌드·사용자 글 기록 기반 `새로운 발견` 복원
2. 추천 조회가 연결 상태·발행 흐름·성과·대기열 로딩을 막지 않는 독립 경계
3. 기존 추천 행동인 소재 적용, 관심 없음, 추천 근거 재사용
4. Dashboard 하단 공식 활용 팁에서 후속 도움말·가이드로 이동할 수 있는 정보 구조 준비
5. 장기적으로 가끔 노출되는 개발자 후원 teaser를 위한 독립적인 cameo 정책 설계

## 명시적 비범위

- 도움말·가이드 화면 본체 구현
- 전자책·개발자 블로그·후원 콘텐츠의 상시 Dashboard 나열
- 추천 생성기, Memory 또는 Knowledge provider 구조 재설계
- 버전 변경, release, push 또는 배포

## 사용자와 결정한 사항

- 장기 parent branch 이름은 목적 뒤에 `-main`을 붙인다.
- Dashboard는 탭으로 운영 정보와 가이드 정보를 나누지 않고 운영 중심 화면으로 유지한다.
- 가이드 콘텐츠 본체는 별도 도움말·가이드 화면으로 분리한다.
- Dashboard에는 공식 활용 팁 한 건과 전체 가이드 이동 연결만 가볍게 둔다.
- 개발자 후원 teaser는 팝업이나 알림이 아니라 Dashboard 하단에 드물게 나타나는 작은 카드로 검토한다.
- 후원 teaser는 활용 팁 30분 순환 풀과 분리하고, 오류·확인 필요 상태에서는 노출하지 않으며 dismiss cooldown을 둔다.
- 첫 단계는 `새로운 발견` 복원이다.

## 제안 설계와 단계

### 1. 새로운 발견 복원

- 기존 recommendation center API와 lifecycle을 재사용한다.
- 새 Dashboard 전용 DOM을 연결하되 기존 Dashboard 호환 구현은 보존한다.
- 최대 세 건을 컴팩트하게 표시하고 각 추천의 출처·핵심 소재·행동을 구분한다.
- 추천 조회 실패는 Dashboard 운영 정보에 영향을 주지 않으며 마지막 정상 결과를 가능한 한 유지한다.

### 2. 도움말·가이드 연결 준비

- Dashboard 활용 팁에 `전체 가이드 보기` 행동을 제공할 수 있는 탐색 계약을 정의한다.
- 실제 가이드 화면 구현은 별도 Help 고도화 parent에서 진행한다.

### 3. 간헐적 후원 teaser

- 별도 surface region과 로컬 노출 이력으로 빈도를 제어한다.
- Help 지원 영역에서는 항상 찾을 수 있고 Dashboard에서는 드물게만 노출한다.
- Help 목적지가 준비된 뒤 마지막 통합 단계로 구현한다.
