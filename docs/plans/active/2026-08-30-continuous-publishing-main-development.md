## 사용자 필요

떠오르는 여러 글감을 잊기 전에 빠르게 등록하고, 각 글감에 확정한 발행 계획을 기준으로
BlogGenius가 설정된 간격과 시간대에 한 건씩 원고를 생성하고 발행하게 한다.
기존 `빠른 포스팅`, `일괄 포스팅`, `자동 포스팅 설정`은 발행 대상과 실행 정책의
소유권이 섞여 이해하기 어려우므로 기존 `블로그` 메뉴는 안정 버전으로 유지하고
새 `블로그 Beta` 메뉴에서 독립적으로 재설계한다.

## 목표

- 모든 글감은 개인별 Google Spreadsheet의 Topics Sheet에 모은다.
- `발행 준비 완료`를 원고 생성 완료가 아니라 자동 처리에 필요한 글감·발행 계획이 확정된 상태로 정의한다.
- 발행 대상, 대상별 카테고리, 글쓰기 전략, 이미지 처리, 외부 참고와 공개·임시 저장·예약 등록 방식은 글감이 소유한다.
- 연속 발행 설정은 켜기, 허용 시간대, 발행 간격과 알림만 소유하며 글감의 발행 계획을 덮어쓰지 않는다.
- Queue는 별도 저장소가 아니라 Topics Sheet 상태 기반 보기로 제공한다.
- Queue 등록 시 AI를 호출하지 않고, 연속 발행기가 한 번에 한 건씩 생성·발행한다.
- 기존 블로그 UI와 실행 흐름을 깨뜨리지 않은 상태에서 새 흐름을 검증한다.

## 명시적 비목표

- 초기 단계에서 기존 `블로그` 메뉴를 교체하거나 제거하지 않는다.
- Supabase를 개인별 발행 Queue 저장소로 사용하지 않는다.
- 여러 발행 프로필이나 복잡한 자동화 규칙을 첫 범위에 도입하지 않는다.
- 초기 단계에서 Trends/RSS 글감을 무조건 자동 승격하지 않는다.
- Stage 1에서는 실제 원고 생성, 발행이나 원격 데이터 변경을 수행하지 않는다.

## 승인된 핵심 결정

1. 사용자 화면에는 임시로 `블로그 Beta` 메뉴를 추가한다.
2. 새 UI·상태 관리·orchestration은 독립 코드로 작성한다.
3. AI 생성, preview, Naver/WordPress 발행, Google Sheet, 라이선스·quota 같은 검증된 핵심 엔진은 복제하지 않고 경계를 통해 재사용한다.
4. 빠른 글 작성은 `바로 생성`, `원고 폴더`, `원고 붙여넣기` 입력 방식을 계속 고려한다.
5. 예약 발행은 Queue가 예약 시각까지 기다리는 기능이 아니라, 처리 시점에 플랫폼으로 원고를 올리고 미래 공개 시각을 등록하는 글감별 실행 방식이다.

## 예상 단계

1. 상태·소유권 계약과 독립 `블로그 Beta` shell
2. `바로 생성 → 글감 저장/대기열 추가 → 최소 목록 확인` vertical slice
3. Queue 조회·수정·재시도와 글감별 발행 계획 관리
4. 한 건씩 처리하는 연속 발행 runner
5. 원고 폴더·원고 붙여넣기 입력 방식의 안전한 편입
6. Trends/RSS source와 통합 검증 및 기존 화면 대체 판단

단계와 범위는 각 vertical slice의 사용 결과에 따라 조정한다.

## 완료 기준

- 빠른 글 등록부터 연속 발행까지 단일한 사용자 흐름으로 이해할 수 있다.
- 글감별 발행 계획과 전역 실행 정책의 소유권이 겹치지 않는다.
- 기존 `블로그` 메뉴의 주요 회귀 테스트가 유지된다.
- 새 UI가 legacy DOM controller에 직접 의존하지 않는다.
- Development에서 공개·임시 저장·예약 등록의 단건 수동 검증을 거친 뒤 대체 여부를 판단한다.

## 후속 위험

- 여러 PC가 같은 Topics Sheet의 같은 글을 동시에 claim하지 않도록 단일 활성 실행기 또는 lease 계약이 필요하다.
- 플랫폼 예약 시각이 처리 시점에 지났거나 너무 가까우면 즉시 발행하지 않고 확인이 필요하다.
