# Release v0.7.0 Preparation

- Branch: `release/v0.7.0`
- Start date: 2026-10-21
- Base/parent branch: `dev` (`512679a6`)
- Status: `0.7.0-dev7` candidate prepared after fixing a release packaging CI failure; focused verification passed and the requested commit/tag publication is in progress.

## User goal

Prepare BlogGenius 0.7.0 as a releasable candidate from the completed work integrated into `dev`, including the user's requested KIE model support expansion and the product improvements accumulated during this release cycle.

## Scope

- Review changes since 0.6.1 and include only user-visible outcomes in `CHANGELOG.md`.
- Keep application and lockfile version metadata consistently at the user-selected prerelease version.
- Verify release inputs and the final candidate diff; reuse successful tests where implementation has not changed and run focused checks for release-only edits.
- Keep packaging and publication separate from branch/tag push; these actions require explicit user direction.

## Explicit non-goals

- Add new product features during release stabilization without the user's direction.
- Apply database changes or publish a stable release.
- List internal refactors, catalog SQL, test infrastructure, or architecture work as standalone release notes.

## Agreed release themes

- Plugin settings show the built-in feature areas and their available operations, giving users a clearer view of what BlogGenius provides without presenting internal refactoring as a product benefit.
- Telegram supports the expanded topic, publishing queue, manuscript generation, follow-up options, confirmation, and result workflow.
- MCP clients support the same BlogGenius actions and can continue through missing-option questions, approval, long-running status checks, and final results.
- KIE.ai supports the selected new text and image models, including Claude models, Gemini 4 Argon, GPT-6.1 Sol, Nano Banana 2.1, and Seedream 5.0 Flash Image; model lists are ordered by family and relative priority.
- Focus Clock and update progress have clearer presentation, and publishing/update completion uses randomized celebration effects.
- Blog Beta makes manuscript generation and editing safer through clearer progress, interaction locking during active work, cursor-based paste insertion, and Naver link-card handling with URL-text fallback.
- Settings clarify Naver connection state and remove unused example-plugin and running-job details.

Release-note wording is shaped around these user-visible outcomes. Each item is intended to describe a change observable in the released app.
