## 사용자 필요와 목표

원고 작성 중 이미지 블록 하나 안에서 제목과 프롬프트를 확인·수정하고, 이미지 결과를 보며 이미지 생성·선택 작업을
이어갈 수 있도록 레이아웃을 정리한다. 이미지에 쓰는 시간을 줄이되 글쓰기 흐름과 기존 이미지 작업 안정성을 유지한다.

## 범위

- 이미지 미리보기를 왼쪽, 제목·프롬프트 입력을 오른쪽에 배치
- 블록 이동·삭제 컨트롤을 상단에 모으고, 이미지/프롬프트 작업을 하단에 모음
- 이미지 유무와 진행 상태에 맞춰 기존 이미지 작업 버튼 문구와 동작을 유지
- 원고 맥락·현재 제목/프롬프트·선택적 추가 요청을 활용한 title/prompt 생성
- 세로형 좁은 화면에서 미리보기와 입력 영역을 세로로 쌓음
- Blog Beta의 공통 원고 편집기(바로 생성·원고 폴더·원고 붙여넣기)에 적용

## 비범위

- AI 모델 선택 UI 및 설정 저장
- 원고 이미지 모델 선택 정책 변경
- 기존 이미지 생성·선택·중지·삭제 비즈니스 로직 교체
- 기존 `블로그` surface 변경
- 전체 이미지 생성·선택 비즈니스 로직 교체

## 결정과 설계 원칙

- 사용자는 이미지 미리보기를 왼쪽, 텍스트 입력을 오른쪽에 두는 레이아웃과 상단 구조 조작·하단 작업 버튼 배치에
  대체로 합의했다.
- 모델 이름은 화면을 복잡하게 만들지 않도록 기본 편집 화면에 별도 선택 컨트롤을 과도하게 노출하지 않는다. 실제
  프롬프트 생성에는 설정된 글쓰기 모델을 사용하며 이미지 모델은 기존 이미지 생성 기능에 그대로 사용한다.
- 생성 시점의 원고 상태만 사용한다. 의미 요약 AI 호출 없이 대상 블록 앞뒤의 가까운 문단과 섹션 제목을 결정적으로
  선택하고 길이를 제한한다. 이전 생성 결과 이력은 누적하지 않는다.
- 현재 제목·프롬프트와 선택적 추가 요청도 같은 요청에 전달한다. 성공 전 기존 입력은 바꾸지 않으며 실패 시 유지한다.
- 일반적인 동작 안내는 상시 메시지로 표시하지 않는다. 상태 영역은 진행 상태·오류가 있을 때만 노출하는 방향을
  후속 구현과 함께 정리한다.
- 이미지 생성·선택 기능의 사용자-visible 계약과 기존 이미지 상태 동작을 보존한다.

## 제안 구현 단계

1. 기존 이미지 NodeView의 DOM 구조를 좌우 분할 편집 레이아웃으로 정리한다.
2. 구조 조작 버튼과 이미지 작업 버튼을 상단/하단으로 각각 그룹화한다.
3. 기존 CSS와 UI contract/browser regression을 갱신한다.
4. 프롬프트 생성 API·AI 글쓰기 모델 호출을 연결하고 진행/오류 상태를 제공한다.
5. 좁은 화면 반응형, 이미지 없음/있음/진행 상태를 검증한다.

## 검증

- 변경된 NodeView 및 스타일 계약에 대한 focused 검증
- 편집기 bundle 빌드
- reviewable UI slice 완료 시 관련 Blog Beta browser regression
- 시각적 수용과 탐색 테스트는 사용자가 hands-on 확인

## 진행과 결과

- NodeView를 상단 구조 조작, 왼쪽 미리보기·오른쪽 텍스트 필드, 하단 프롬프트 지시/생성 진입점과 이미지 작업
  버튼으로 재배치했다.
- 좁은 화면에서는 이미지 미리보기를 위에, 제목·프롬프트를 아래에 두도록 반응형으로 전환한다.
- 이미지 유무에 따라 기존 AI 생성/재생성, 내 이미지 선택/교체, 이미지 제거 버튼 문구와 노출을 유지한다.
- 위·아래 이동은 원고 내 첫/마지막 위치와 이미지 작업 중 상태에서 비활성화한다.
- 일반 안내 메시지를 추가하지 않았다. 기존 이미지 작업 진행 상태는 미리보기 영역에서 유지한다.
- 프롬프트 생성 API를 Blog Beta 원고 블록 편집기에 연결했다. AI 글쓰기 모델이 호출 중일 때 버튼·입력을 잠그고
  진행을 표시하며, 실패하면 기존 필드 값을 유지하고 오류만 표시한다.
- API는 현재 원고의 대상 이미지 블록 주변 제목/문단만 결정적으로 선택(약 2천 자 이내)하고, 당시 제목·프롬프트와
  선택적 추가 요청을 함께 전달한다. 이전 생성 이력은 저장하거나 누적하지 않는다.
- `npm run build:manuscript-editor`를 실행해 편집기 bundle을 재생성했다.
- 사용자가 로컬 이미지를 고른 뒤 WordPress 발행에서 이미지가 누락되고 프롬프트 원문이 노출되는 사례를 보고했다.
  원인은 WordPress 발행 파서가 새 이미지 블록의 `id:` 줄 및 빈 title을 허용하지 않는 포맷 불일치였다. 새/기존
  포맷과 빈 title/prompt를 인식하도록 파서를 수정했다. 사용자가 실제 WordPress 이미지 발행이 정상임을 확인했다.
- 사용자 hands-on 확인에서 생성 결과 title만 보이고 prompt가 입력되지 않는 문제가 발견됐다. 원인은 제목 반영
  트랜잭션의 NodeView 갱신이 아직 반영하지 않은 prompt 입력값을 덮어쓰는 순서 문제였다. 두 속성을 단일 트랜잭션으로
  반영하도록 수정하고, 민감한 입력 내용 대신 요청 문맥별 문자 수와 응답 title/prompt 문자 수를 로그로 추가했다.
- 사용자가 재테스트해 title과 prompt가 모두 표시되는 것을 확인했고, WordPress 이미지 발행도 정상 동작한다고 확인했다.
- 원고 draft 단위 테스트 43개와 이미지·원고 계약 테스트 26개가 통과했다. 전체 browser smoke는 이미지 블록 UI 확인
  이후 기존 slash 메뉴 재검증 단계에서 실패했다. 전용 slash 브라우저 스크립트는 시스템 Chrome 프로세스 abort로
  실행되지 않았으며, 해당 정적 계약 테스트 3개는 통과했다. browser 검증 제한은 parent `dev` 통합 전 재확인한다.

## 남은 위험과 후속 단계

- 좁은 화면 반응형과 기존 이미지 생성 진행/중지 오버레이의 시각적 수용은 추가 확인 여지가 있다.
- 입력 문맥의 관련성과 출력 품질은 사용자의 실제 편집 시나리오에서 확인해야 한다. 현재는 근접 문단 선택과 글자 수
  제한을 사용하며, 의미 요약은 추가 단계로 두었다.
