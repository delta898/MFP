## User need and goal

Prepare the next BlogGenius release on a dedicated stabilization branch. Begin with a development prerelease version so release checks and any final fixes can be reviewed before assigning the final `0.4.0` version.

## Initial scope

- Create `release/v0.4.0` from the current `dev` integration state.
- Update the desktop app version and lockfile metadata together to `0.4.0-dev1`.
- Verify version consistency and record subsequent stabilization work here.

## Non-goals for this step

- Do not tag, push, package, publish or deploy.
- Do not assign the final `0.4.0` version yet.
- Do not change independently versioned tools, plugins or hosted services.
- Do not rewrite release notes before reviewing the complete release scope.

## Release checklist

- [x] Development prerelease version is consistent across app metadata.
- [ ] `CHANGELOG.md` describes the release from the user's perspective.
- [ ] Relevant automated tests and build inputs pass.
- [ ] Final Git diff and version consistency are reviewed.
- [ ] Final version assignment, tag, push, packaging and publication are separately approved.
