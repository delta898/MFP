# v0.4.0 설치 실행 hotfix 개발 기록

## Branch

- Branch: `codex/hotfix/v0.4.0-install-launch`
- Base/parent branch: `release/v0.4.0`
- Start date: 2026-09-03
- Status: v0.4.1-rc1 로컬 검증 완료, Kuzu 복구는 backlog로 이관

## 사용자 필요와 목표

v0.4.0 Windows x64 installer의 CSS·JavaScript 로딩 장애와 macOS Apple Silicon의 첫 실행 main-process crash를 함께 수정한다. 공개된 v0.4.0과 동일한 release branch를 기준으로 두 플랫폼의 신규 설치 경로를 복구하고 자동 검증해 재발을 막는다.

## 범위

- UI HTTP 요청 경로를 운영체제 파일 경로와 분리해 플랫폼 중립적으로 정규화
- Windows에서 `/styles.css`와 `/app.js`가 합성된 결과를 반환하도록 복구
- `path.win32` 기반 회귀 테스트
- macOS App Translocation이나 `.app` 단독 이동에서도 사용할 수 있는 앱 내장 기본 설정
- 외부 설정이 없는 첫 실행에서 writable `userData/config` 초기화
- 기본 설정 누락이 main process crash로 이어지지 않는 회귀 테스트
- 관련 focused unit/contract 검증
- Windows Kuzu native module에 필요한 x64 VC++ runtime의 앱 로컬 포함
- installer와 portable/self-update ZIP에서 동일한 Windows runtime 제공
- Windows Kuzu/Electron 제약 진단과 후속 backlog 기록
- Node 24 기반 GitHub Release upload action 적용
- 배포 패키지의 실제 첫 실행을 검증할 수 있는 후속 release gate 요구사항 기록

## 확인된 원인과 결정

- Windows에서 Node `path.normalize('/styles.css')`는 `\\styles.css`를 반환한다.
- 기존 sanitizer는 선행 `/`만 제거해 Windows 선행 `\\`를 남긴다.
- UI 서버는 요청 경로가 정확히 `styles.css` 또는 `app.js`일 때만 모듈 manifest를 합성하므로 Windows에서는 주석뿐인 원본 manifest가 응답된다.
- URL 경로는 OS 파일 경로가 아니므로 `/` 기준의 canonical relative path로 정규화하고, 실제 파일 결합 단계에서만 주입된 OS `path` 구현을 사용한다.
- 경로 이탈 방지는 기존 root prefix 검사와 함께 유지하고 `.`·`..` segment를 sanitizer에서 정리한다.
- macOS 오류 경로의 `AppTranslocation`과 `config-loader.js:410`을 통해 앱 바깥의 `config/config.json.sample`이 보이지 않아 기본 설정이 `{}`가 된 것을 확인했다.
- 사용자 설정이나 라이선스가 앱에 포함되지 않도록 외부 `config/` 전체를 패키징하지 않고, 배포 가능한 기본 설정만 앱 내부의 읽기 전용 자산으로 둔다.
- quarantine 우회 안내는 이번 hotfix에서 유지하며, 우회 여부와 무관하게 기본 설정 누락 때문에 main process가 종료되지 않게 한다.
- Windows 실행 로그에서 Kuzu native module 파일은 존재하지만 `MSVCP140.dll`, `VCRUNTIME140.dll`, `VCRUNTIME140_1.dll` 의존성을 찾지 못해 AgentMemory가 비활성화되는 별도 문제를 확인했다.
- 설치 경로와 `PrivilegesRequired=lowest` 정책은 유지한다. installer뿐 아니라 portable ZIP과 self update에도 적용되도록 공식 MSVC x64 CRT 파일을 실행 파일 옆에 앱 로컬 배치한다.
- 앱 로컬 runtime은 중앙 Redistributable처럼 독립적으로 서비스되지 않으므로 Windows release build 때 설치된 최신 배포 가능 CRT를 매번 새로 포함하고 필수 파일을 검증한다.
- 사용자는 설치 장애 hotfix를 `v0.4.1-dev1`로 먼저 검증하고, 기존 Dashboard 후속 작업의 목표 버전은 `v0.4.2`로 조정하기로 결정했다.
- `v0.4.1-dev1` installer에는 VC++ DLL 10개와 Kuzu binary가 실제 포함됐지만 AgentMemory load는 계속 실패했다. Kuzu 0.11.3 Windows prebuilt가 `node.exe`를 즉시 import하고 Electron용 delay-load hook을 포함하지 않는 것이 남은 원인이다.
- 기존 CI smoke는 `ELECTRON_RUN_AS_NODE`와 `-e` 실행에서 성공 marker가 출력되지 않아도 exit code 0만 확인해 false positive가 됐다. 철회된 dev2에서는 일반 Electron main process gate로 교체했지만 source build와 함께 release 경로에서 제거했다.
- Kuzu 전체 C++ 소스를 Windows release마다 빌드하는 dev2 시도는 한 시간 이상 실행되어 Actions quota를 소진했고 완료되지 않았다. hotfix의 핵심인 Windows UI와 macOS 첫 실행은 dev1 installer에서 확인됐으므로 Kuzu 복구를 v0.4.1 출시 조건에서 제외한다.
- Windows에서는 Kuzu load 실패 시 기존 fallback으로 내려가며 Dashboard와 작성·발행 기능은 계속 제공한다. 제한 사항은 CHANGELOG에 공개하고, 검증된 binary 재사용 또는 유지되는 저장소로의 교체는 `docs/backlog.md`에서 별도 설계한다.

## 구현 단계

1. Windows 요청 경로를 재현하는 focused test 추가
2. platform-neutral pathname sanitizer 구현
3. CSS·JavaScript 합성 응답 회귀 검증
4. macOS 앱 내부 기본 설정과 writable 첫 실행 초기화 구현
5. App Translocation 형태의 외부 설정 부재 회귀 검증
6. Windows VC++ runtime 앱 로컬 패키징 및 Kuzu load gate 추가
7. 장시간 Kuzu source build 시도를 철회하고 Windows fallback을 알려진 제한으로 명시
8. GitHub Release upload action을 Node 24 기반 v3로 갱신
9. 관련 unit 및 diff 검증

## 진행 기록

- 2026-09-03: Windows installer 실행 사진에서 Electron과 로컬 UI 서버는 시작되지만 CSS와 JavaScript가 적용되지 않는 상태를 확인했다.
- 2026-09-03: `path.win32` 재현으로 `/styles.css`와 `/app.js`가 각각 `\\styles.css`, `\\app.js`가 되어 합성 분기를 우회함을 확인했다.
- 2026-09-03: URL pathname을 `/` 기준 canonical relative path로 정규화하고 `.`·`..` segment를 UI root 안에서 해석하도록 수정했다.
- 2026-09-03: Windows 경로 구현을 주입한 HTTP server test에서 query string이 있는 CSS·JavaScript 요청이 각각 합성 본문과 올바른 MIME type을 반환하는지 검증했다.
- 2026-09-03: macOS 오류 사진에서 `AppTranslocation` 실행과 외부 기본 설정 누락에 따른 `structuredConfig.platforms.naver` crash를 확인하고 hotfix 범위를 두 플랫폼 설치 실행으로 확장했다.
- 2026-09-03: 배포 가능한 `config.json.sample`과 기본 이미지만 Electron Resources에 포함하고, 외부 설정이 없으면 writable runtime config에 누락 자산을 초기화하도록 구현했다. 기존 사용자 설정과 이미지는 덮어쓰지 않는다.
- 2026-09-03: Apple Silicon 임시 `.app`을 실제 패키징한 뒤 외부 config 없이 실행해 config 생성, 기본 이미지 복사, UI 서버 시작까지 확인했다.
- 2026-09-03: Windows 로그와 Kuzu PE import table을 대조해 x64 MSVC runtime 3종 누락을 확인했다. 화면 자산 장애의 직접 원인은 아니지만 AgentMemory가 fallback으로 내려가는 신규 설치 장애이므로 같은 hotfix에 포함하기로 승인받았다.
- 2026-09-03: Windows CI와 `build.bat`가 공유하는 VC++ runtime 복사 스크립트를 추가했다. Visual Studio 설치 위치를 탐색해 배포 가능한 x64 CRT DLL을 실행 파일 옆에 복사하며, 필수 3종 누락 시 build를 실패시킨다.
- 2026-09-03: Windows CI가 패키지의 Kuzu module을 Electron의 Node mode에서 실제 load하도록 release gate를 추가했다. 설치 위치는 `%LOCALAPPDATA%\\Programs\\BlogGenius`, 권한은 `lowest`로 유지했다.
- 2026-09-03: 사용자 승인에 따라 앱과 lockfile 버전을 `0.4.1-dev1`로 맞추고 Windows·macOS 신규 설치 복구 내용을 CHANGELOG에 정리했다. 브랜치 push와 prerelease tag push도 이번 승인 범위에 포함했다.
- 2026-09-03: 실제 `v0.4.1-dev1` installer에서 화면 자산은 복구됐지만 Kuzu load 실패가 계속됨을 확인했다. 배포 ZIP과 Inno 로그에서 필수 DLL 포함을 검증했고, PE import table과 Electron Windows native-module 계약을 대조해 delay-load hook 누락으로 진단을 수정했다.
- 2026-09-03: Kuzu 0.11.3의 CMake.js 입력을 Electron 40.6.1 header·node.lib·Windows delay-load hook으로 교체하는 Windows build step을 추가했다. 패키지 검증은 일반 Electron main process의 전용 인자로 Kuzu를 require하며 성공 marker와 exit code를 모두 요구한다.
- 2026-09-03: 후속 후보 버전을 `0.4.1-dev2`로 변경하고 dev1 CHANGELOG는 실제 제공 범위인 VC++ 실행 구성 요소 포함으로 바로잡았다.
- 2026-09-03: dev2 Windows source build가 한 시간 이상 완료되지 않아 Actions quota 제한으로 중단됐다. 사용자 결정에 따라 release마다 native source build하는 방식과 그 전용 gate를 제거하고 Kuzu 복구를 P2 backlog로 이관했다.
- 2026-09-03: Windows UI와 macOS 첫 실행 복구를 `0.4.1-rc1` 후보로 정리하고 Windows AgentMemory 제한을 CHANGELOG에 명시했다. Release upload action 9곳은 Node 24 기반 `softprops/action-gh-release@v3`로 갱신했다.

## 최종 결과 및 검증

- Windows와 POSIX 모두 `/styles.css`, `/app.js`, 하위 정적 자산 경로를 동일한 canonical relative path로 해석한다.
- Windows UI 서버가 주석뿐인 manifest 원본 대신 합성된 CSS와 JavaScript를 반환한다.
- 경로 정규화는 선행 slash/backslash와 `.`·`..` segment를 제거하면서 기존 UI root prefix 방어를 유지한다.
- macOS 패키지는 사용자 비밀 설정을 제외한 기본 sample과 기본 이미지만 `Contents/Resources`에 내장한다.
- App Translocation처럼 `.app` 외부 파일을 볼 수 없는 실행에서도 내장 sample을 사용해 writable config를 생성하고 main process가 정상적으로 UI 서버를 시작한다.
- 기존 사용자 config와 같은 이름의 사용자 이미지는 첫 실행 초기화가 덮어쓰지 않는다.
- Windows installer와 portable/self-update ZIP에는 Kuzu가 요구하는 x64 VC++ runtime이 앱 로컬 파일로 함께 들어간다.
- Windows release build는 `MSVCP140.dll`, `VCRUNTIME140.dll`, `VCRUNTIME140_1.dll` 존재를 검증한다. Kuzu native module load 복구는 이번 출시 범위가 아니다.
- 로컬 `build.bat`도 Kuzu를 ASAR 밖으로 unpack하고 동일한 VC++ runtime bundler를 사용한다.
- Focused UI runtime: `node --test src/ui-runtime/http-utils.test.js src/ui-runtime/http-server-runtime.test.js src/ui-runtime/css-composition-runtime.test.js src/ui-runtime/js-composition-runtime.test.js src/ui-runtime/html-composition-runtime.test.js` — 10 tests passed.
- Focused packaging/config: `node --test src/config/packaged-default-assets.test.js scripts/packaged-default-assets-contract.test.js src/ui-runtime/http-utils.test.js src/ui-runtime/http-server-runtime.test.js` — 8 tests passed.
- Focused Windows packaging: `node --test scripts/windows-vc-runtime-packaging-contract.test.js scripts/packaged-default-assets-contract.test.js src/config/packaged-default-assets.test.js src/ui-runtime/http-utils.test.js src/ui-runtime/http-server-runtime.test.js` — 10 tests passed.
- Browser regression: `npm run test:ui-browser` — assertions passed (161 fixture requests). 성공 출력 후 runner가 종료되지 않아 수동 중단했으며 별도 test teardown 문제로 남긴다.
- Full unit suite: `npm run test:unit` — 1,251 tests passed.
- Version/release metadata: 앱과 lockfile `0.4.1-dev1` 일치, version contract와 `release-details.js` 출력 검증 통과.
- 철회된 dev2 시도에서는 focused 17개와 full unit 1,256개가 통과했지만, Windows native build가 Actions quota 안에 완료되지 않아 release 경로에서는 제거했다.
