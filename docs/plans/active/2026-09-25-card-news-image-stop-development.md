# 카드뉴스 이미지 생성 중지 개발 기록

- 브랜치: `codex/feature/card-news-image-stop`
- 시작일: 2026-09-25
- 기준/부모 브랜치: `codex/feature/ai-generation-cancellation`
- 상태: 이미지 중지 1차 커밋 완료; 카드 구성 중지 구현 완료, 수동 확인 대기

## 사용자 필요와 목표

카드뉴스 생성 결과를 카드별로 순차 표시하는 작업이 parent에 커밋되었다. 이제 카드뉴스 이미지 생성 중에도 작업을 중지할 수 있도록 한다. 일괄 생성과 개별 카드 생성 모두 카드뉴스 이미지 영역에서 중지 상태를 알리고, 이미 완성된 카드는 보존한다.

## 범위와 비범위

- 카드뉴스 생성 화면의 일괄 이미지 생성, 빈 이미지 일괄 생성, 개별 이미지 생성 중지.
- 카드뉴스 텍스트 구성 생성 중지. “이미지까지 만들기”의 구성 단계에도 동일하게 적용한다.
- 기존 AI 작업 중지의 2단계 확인/계속 진행 패턴을 재사용한다.
- 작업 ID와 서버 측 취소 수명주기를 두어 브라우저 요청만 끊고 서버 AI 작업이 계속되는 문제를 방지한다.
- 취소되기 전에 완성된 이미지를 보존하고, 현재 미완성 및 이후 카드는 재시도 가능한 상태로 남긴다.
- KIE 작업은 로컬 폴링을 멈춰도 원격 이미지 작업이나 비용이 계속될 수 있음을 기존 안내 계약과 일치시킨다.

비범위:

- 외부 공급자의 원격 작업 강제 종료 또는 과금 취소 보장.
- 전체 `dev` 병합, 배포 및 유료 실모델 테스트.

## 제안 설계와 영향 경계

- `src/ui-api/services/card-news.service.js`에서 공유 AI operation manager에 카드뉴스 전용 lease를 제공하고, 비동기 시작/조회/중지 경로를 카드뉴스 API에 연결한다.
- `src/card-news/generation-service.js`는 `AbortSignal`을 이미지 transport에 전달하고 이미지 단위 경계에서 취소를 확인한다. 이미 manifest에 커밋된 이미지는 보존한다.
- `ui/scripts/features/card-news/source-preview.js`는 이미지 확인 영역에서 operation 상태를 반영한다. 일괄 동작 버튼과 개별 카드 버튼은 작업 중 정지/확인/계속 상태로 전환하고, 기존 카드별 진행 표시를 유지한다.
- 카드 구성 텍스트 호출에도 동일한 operation lifecycle을 재사용한다. 구성 AI 응답과 카드 구조 검증 뒤 저장을 시작하는 시점에 `beginCommit()`을 호출해 그 전까지만 취소를 허용한다. 이미지까지 만들기 흐름은 구성 operation을 완료한 뒤 별도의 이미지 operation으로 전환한다.
- 모델별 로직이 아니라 기존 공통 AI 취소/operation 경계를 재사용할 수 있는지 먼저 확인한다. 별도 operation 소유자를 추가하더라도 다른 surface로의 확장을 막지 않도록 카드뉴스 업무 규칙은 카드뉴스 서비스 경계에 둔다.

## 단계

1. 공유 operation manager와 transport 취소 경계 조사, API 계약 확정.
2. 서버 이미지 작업의 비동기 시작/조회/중지 및 취소 시 manifest 안정성 구현.
3. 카드뉴스 영역의 확인/계속/중지 UI 연결과 일괄/개별 처리.
4. 서비스·라우트·브라우저 회귀 검사, 사용자의 수동 검증.

## 결정 및 트레이드오프

- 2026-09-25: 점진 표시 작업은 `e0e932ec`로 parent에 커밋했다. 사용자는 순차 표시를 확인하고 카드뉴스 중지를 다음 단계로 진행하기로 했다.
- 2026-09-25: 이미지 생성 중지 1차 단계는 `4e304f8e`로 커밋했다. 후속 범위로 카드 구성 중지를 더하고, 구성 단계에서는 취소 가능, 결과 확정 이후에는 중지 불가로 하며, 이미지 작업 진입 뒤에는 이미지 중지만 가능하게 한다. 사용자 요청에 따라 안내 카피와 Buffer 설정 안내는 이번 단계에서 제외한다.
- 중지는 클라이언트 `fetch`만 abort하는 방식으로 끝내지 않는다. 서버 작업이 계속되지 않게 신호가 이미지 transport까지 전달되어야 한다.
- KIE 취소는 로컬 추적 중지와 원격 작업 취소/비용 환급을 구분해서 표현한다.
- 개별 중지에도 일괄 중지와 같은 2단계 확인/계속 진행을 사용한다. `confirmingStop`은 UI state에 두어 상태 폴링이나 카드 재렌더링이 확인 단계를 지우지 않게 한다.
- 구성 중지에도 동일한 2단계 확인/계속 진행 affordance를 생성 버튼 자리에서 사용한다. 텍스트 transport에 `AbortSignal`을 전달하고, 취소 시 결과 확정 전이므로 새 generation manifest를 만들지 않아 이전 유효 결과와 로컬 목록을 보존한다.

## 진행 및 검증

- 시작 시점 확인: parent `codex/feature/ai-generation-cancellation`의 working tree는 깨끗했고, 마지막 커밋은 `e0e932ec`였다.
- `src/card-news/generation-service.js` 이미지 처리에 `AbortSignal`을 전달하고, 각 카드 단위에서 중지를 확인한다. 취소 시 현재/이후 카드는 실패로 표시하지 않으며 이미 manifest에 저장된 카드는 보존한다. KIE 등 외부 작업은 로컬 대기 중지가 원격 작업이나 비용을 취소하지 않을 수 있음을 안내한다.
- 카드뉴스 서비스가 공유 AI operation manager를 사용해 비동기 시작/상태 조회/중지 API를 제공한다. 카드뉴스 service 경계에 한 번에 하나의 구성 또는 이미지 작업만 허용하는 lease를 두어 동시 manifest 쓰기를 막는다.
- 일괄/빈 이미지 생성은 공통 영역의 버튼이 중지 UI로 바뀌고, 개별 생성은 해당 카드 버튼이 중지 UI로 바뀐다. 둘 다 2단계 확인 및 계속 진행을 지원하며, 확인 상태는 폴링 중 유지된다. 중지 후 완료된 이미지는 보존된다.
- 사용자 재확인에서 개별 카드의 중지/계속 진행 버튼이 스크린샷에 보이지 않는 결함이 확인됐다. 진행 오버레이가 카드별 AI 버튼을 덮는 것이 원인이었다. 중지 control은 별도 오버레이 action bar 대신 원래 AI 버튼의 action slot을 이어받도록 변경하고, 폴링 이후에도 활성 카드의 action row가 노출되게 했다. 브라우저 smoke에 개별 중지의 2단계 확인/계속/중지 검증을 추가했다.
- 사용자 UI 피드백을 반영해 개별 중지 control을 시작 버튼과 같은 높이로 두고, 단일·일괄 중지 모두 compact ghost danger 위계로 낮췄다. 넓은 배경/테두리 바는 제거했다.
- 후속 디자인 검토에서 카드 내 중지 버튼의 넓은 action bar가 위압적으로 보인다는 피드백을 받았다. Carbon/Primer의 danger 위계와 WCAG hover/focus 원칙을 참고해 중지를 낮은 강조의 ghost danger action으로 정의하고, hover-only는 idle 보조 action에만 허용하며 진행 중 stop은 계속 노출하는 규칙을 디자인 가이드에 반영했다. Blog Beta와 Card News의 개별 이미지 중지 UI를 같은 action slot/compact variant로 맞췄다.
- 집중 검증 통과: 카드뉴스 서버·서비스·라우트 및 셸 단위 테스트 57/57, 추가 Blog Beta·Card News UI 계약 테스트 54/54, UI 파일과 smoke 스크립트의 `node --check`, `git diff --check`.
- 후속 구성 중지 검증 통과: 카드뉴스 generation/service/controller/routes 및 UI shell 테스트 61/61. AbortSignal 전달, 취소 시 불완전 산출물 미생성, 공유 operation 취소, 결과 확정 이후 `canCancel=false`/`too_late`를 확인했다. browser smoke는 카드 구성 중지 확인/계속/중지와 “이미지까지 만들기”의 구성 단계에서 중지 버튼 노출을 통과했다. 공용 smoke는 이후 기존 Blog Beta UI에서 비결정적으로 실패했다(제목 분석 로딩 상태 확인 `:3213`, 또는 워드프레스 대상 선택 `:3604`). 추가로 구성 중지 확인/계속 버튼의 DOM 인접성과 같은 행 정렬, 확인 취소 후 원래 결과 작업 영역으로 복귀를 검증한다.
- 카드뉴스 생성·이미지 작업 상태/결과/안내 문구는 결과 제목 오른쪽의 공통 상태 영역에 모으고, 생성 설정 아래에 있던 별도 안내 위치는 제거했다. 결과가 아직 없을 때 생성이 실패해도 상태 안내가 보이도록 결과 패널에 오류 상태를 유지한다. 좁은 화면에서는 상태 문구를 제목 아래 왼쪽 정렬로 쌓는다.
- 중지 2단계 확인 문구는 진행 상태 문구와 별도 요소로 분리해, 폴링으로 진행 상태가 갱신돼도 사용자가 계속/중지를 선택할 때까지 유지한다. 비용 및 외부 작업 가능성은 중지 버튼/안내 툴팁의 보조 설명으로 둔다.
- 이 확인 상태의 유지 동작은 셸 계약 및 browser smoke에서 카드 구성/일괄 이미지 작업 각각 진행 메시지를 다시 갱신해도 확인 문구가 남는 것으로 검증했다. 전체 browser smoke는 카드뉴스 구간 뒤 기존 Blog Beta 워드프레스 대상 라디오 선택 검사(`scripts/test-ui-browser-smoke.js:3620`)에서 실패했다.
- 사용자 일관성 피드백에 따라 Blog Beta 네이버 최종 제출 단계의 비활성 중지 버튼 라벨도 실패처럼 읽히는 “중지할 수 없음” 대신 카드뉴스와 같은 “마무리 중…”으로 맞춘다. 구체적인 중지 불가 사유는 기존 보조 안내와 접근성 이름으로 유지한다.
- Buffer 발행 안내의 실제 원인을 설정 API와 서비스 조건으로 확인했다. 런타임에는 Buffer API Key와 작업 공간이 있지만 선택·저장된 채널은 0개였다. `SNS_PUBLISH_ENABLED=false`는 카드뉴스 수동 발행의 선행 조건이 아니므로 경고 원인이 아니다. 예전 “Buffer 연결을 먼저 완료” 문구는 연결 자체가 안 된 것으로 오해시키므로 “설정 > 부가 서비스 > SNS 배포에서 사용할 Buffer 채널을 선택하고 저장해 주세요. 자동 SNS 배포를 켤 필요는 없습니다.”로 구체화하고, 안내를 “카드 이미지를 준비했습니다” 상태 영역 아래에 배치한다. 서버 설정 응답에서도 API Key, 작업 공간, 선택 채널 유무를 별도 상태로 구분한다.
- Buffer 연결 확인 결과는 이전까지 설정 화면 메모리에만 있었고, 재실행 시 무조건 “확인 필요”로 되돌아갔다. 공용 연결 검증 저장소를 재사용해 Buffer 자격 증명(비밀값은 해시 서명으로만 식별)별 확인 상태와 시각을 로컬 연결 검증 파일에 저장한다. 결과는 24시간 동안 최근 확인으로 표시하고, API Key 또는 작업 공간이 달라지면 일치하는 검증이 없어 다시 확인하도록 한다. 실패 확인도 기억해 “확인 실패”와 확인 시각을 표시한다.
- 연결 상태 영속성 집중 검증: Buffer/일반 연결 검증, 부가 설정 서비스, Settings Beta UI 계약 및 Card News 셸 테스트 48/48 통과. 브라우저 smoke에서 재시작을 가정한 저장 연결 확인 상태 표시까지 통과했고, 이후 기존 Blog Beta 워드프레스 대상 클릭 assertion(`scripts/test-ui-browser-smoke.js:3634`)에서 실패했다.
- `npm run test:ui-browser`는 카드뉴스 점진 표시와 일괄 및 개별 중지(2단계 확인/계속/중지, compact danger 스타일, 시작 버튼과 같은 높이) 시나리오를 통과했다. 전체 smoke는 이후 기존 블로그 발행 대상 검사(`scripts/test-ui-browser-smoke.js:3544`)에서 실패했다(워드프레스 대상 라디오 선택이 반영되지 않음). 이 실패는 본 UI 변경과 무관한 기존 회귀 이슈로 분리한다.
- Card News의 Buffer 발행 대상도 SNS 수동 발행과 같은 선택 흐름을 갖도록 확장한다. 카드뉴스 발행 패널 안에서 작업 공간을 고르면 해당 공간의 채널만 표시하며, 선택 작업 공간은 `card_news_buffer_organization_id_v1`에 별도 기억해 SNS 수동 발행/블로그 자동 공유 선택과 분리한다. API는 매 발행 요청에서 해당 공간의 채널을 다시 조회해 채널 ID 소속을 검증한다. 공간별 조회·검증, 발행 컨트롤러 인자 전달, 화면 계약 단위 테스트는 통과했다. 전체 UI smoke는 카드뉴스 구간을 지난 뒤 기존 Blog Beta 워드프레스 target assertion(`scripts/test-ui-browser-smoke.js:3642`)에서 실패했다.
- 릴리스 준비 전 마지막 화면 조정으로 앱 푸터의 위아래 여백과 외부 링크 아이콘 크기를 컴팩트하게 줄여, 본문 client view가 더 넓고 시원하게 보이도록 한다. 전역 shell 규칙으로 적용하고 좁은 화면도 같은 밀도로 줄인다.
- 푸터 밀도 회귀 계약 테스트 1/1 통과, `git diff --check` 통과. 함께 실행한 기존 UI CSS 구조 테스트는 이번 푸터 변경과 무관하게 현재 브랜치에 이미 추가된 `grid-spacer.css` manifest 등록 누락 및 `blog-next-image-spin` keyframes 기대값 차이로 2건 실패했다.
- 전체 unit suite(`npm run test:unit`, 363개 테스트 파일)도 실행했으나 현재 브랜치의 기존 UI 계약 불일치 7건으로 실패했다. sandbox 제한으로 실패했던 로컬 listen 테스트 2건은 권한을 높여 재실행해 해소했다. 남은 실패는 Blog Beta/Buffer 안내 기대값, CSS/JS manifest 및 파일 크기 경계, spinner/로딩 구조 관련이며 푸터 변경 범위와 무관하다.
- 위 7건을 하나씩 재검토해 오래된 계약 기대값은 현재 UI 도움말/안내와 일치시키고, CSS/JS manifest는 실제 구성과 동기화했다. Blog Beta 원고 이미지 편집·생성 스크립트(406줄)를 `draft-images.js`로 분리해 800줄 모듈 경계를 회복하고, 이미지 동작 계약은 두 스크립트를 함께 검사하도록 고쳤다. 중복 spinner keyframes를 제거해 공통 회전 애니메이션을 사용한다. 전체 suite 통과: 363개 파일, 1,969 tests 중 1,968 통과, 1 skip, 0 실패. UI 브라우저 smoke는 시작했지만 3분 이상 출력 없이 대기해 중단했으며, 브라우저 smoke 검증은 완료되지 않았다.
- 후속 요청으로 파일 크기 예외 두 곳을 해소했다. Blog Beta의 글감 작성/저장(333줄)과 대기열 관리(478줄)를 각각 `quick-queue.js`와 `queue-management.js`로 분리하고, Card News의 소스 미리보기(614줄)와 구성·이미지 생성 흐름(594줄)을 각각 `source-preview.js`와 `generation-workflow.js`로 분리했다. JS manifest와 계약 테스트의 모듈 조합을 갱신하고, 모듈 상한을 모든 비레거시 UI 스크립트에 800줄로 되돌렸다. 관련 계약 132/132 통과, 전체 단위 테스트 1,968 통과/1 skip/0 실패. 브라우저 smoke 재시도 역시 3분간 출력 없이 대기해 중단했다. 최종 브라우저 상호작용 검증은 남아 있다.
- 새 카드/만든 카드 목록은 생성 이력으로 분리한다. 생성 기록이 없는 RSS 원문만 `새 카드뉴스`에 남기고, 구성 생성부터 발행 완료까지 생성 결과는 `만든 카드뉴스`에 둔다. 두 작업 탭에 전체 목록 개수를 표시하고, 만든 카드 상세 원문에서 “이 원문으로 새 카드뉴스 만들기”를 선택하면 별도 프로젝트를 만들어 이전 결과와 이미지를 보존한다. 관리대장도 원문당 단일 행의 generation ID를 덮어쓰지 않고 생성 버전별 행을 추가해 과거 발행 상태와 링크를 유지한다.
- 새 카드/만든 카드 분류 및 새 버전 집중 검증: 관리대장 버전 보존, Card News 셸 계약, ledger sync 및 상태 파생 테스트 32/32 통과. Browser smoke에서 카드뉴스 구간(탭 카운트, 생성된 원문 숨김, 생성 직후 카운트 갱신, 만든 카드에서 새 버전 진입, 기존 프로젝트 보존)을 통과했으나, 이후 기존 Blog Beta 워드프레스 대상 클릭 검사(`scripts/test-ui-browser-smoke.js:3698`)에서 실패했다.
- 만든 카드뉴스의 상태 필터(전체, 작업 중, 발행 대기, 발행 완료, 확인 필요)에 각 상태의 전체 항목 수를 작은 공유 count badge로 표시한다. 개수는 현재 선택 필터와 무관하게 관리 목록 전체에서 계산해 탭 전환 후에도 각 상태 규모가 보인다.
- SNS 수동 발행과 카드뉴스 발행의 설정 위계를 `작업 공간 → 전체 채널 선택 → 개별 채널`로 맞춘다. 두 화면 모두 채널 선택 개수를 최대 채널 수와 함께 표시하며, 카드뉴스 전체 선택은 호환 가능한 채널 중 최대 3개까지만 선택한다. 두 화면의 선택 UI browser smoke 구간은 통과했으나 전체 smoke는 기존 Blog Beta 워드프레스 target assertion(`scripts/test-ui-browser-smoke.js:3648`)에서 실패했다.
- SNS와 카드뉴스 발행의 작업 공간 행을 같은 `선택 목록 + 다시 불러오기` 패턴으로 맞추고, 카드뉴스에도 선택 공간을 유지한 채 작업 공간 및 해당 채널을 재조회하는 버튼을 추가했다. Buffer 도움말은 카드뉴스 발행 제목 옆에서 채널 선택 헤더 옆으로 옮겨 SNS 화면의 정보 위계와 맞춘다. 관련 계약 및 서버/컨트롤러 테스트는 47/47 통과했다. 브라우저 smoke는 이 변경의 시나리오에 도달하기 전 기존 개별 이미지 중지 버튼 정렬 assertion(`scripts/test-ui-browser-smoke.js:2544`)에서 실패해 refresh 상호작용 검증은 보류다.
- Card News와 Blog Beta의 이미지 그리드 마지막 줄에서 실제 카드가 차지하지 않는 나머지 칸만 비활성 장식 셀로 채운다. 별도의 빈 작업 카드나 생성 버튼은 추가하지 않으며, 실제 카드 수와 반응형 열 수에 따라 여백 셀을 동기화한다. 셀은 `aria-hidden`/`inert` 및 포인터 비활성으로 작업 대상이 아님을 보장한다.
- SNS 수동 작성 화면을 `내용 → 이미지 → 작업 공간/발행 채널 → 발행` 순서로 재배치하고 소개 문구도 사용자 작업 순서에 맞췄다. 채널 선택 제한과 도움말은 발행 대상 영역에 유지한다. SNS 디자인 계약 테스트에서 구조 순서를 확인한다.
- 두 발행 화면의 외형만 복사해 생긴 크기 차이를 수정한다. 작업 공간 필드/새로고침, 전체 채널 선택과 선택 수의 반복 구조·동작을 `BufferPublishingControls` 공유 UI 모듈과 패턴 스타일로 추출하고 SNS 및 카드뉴스가 같은 구현을 사용한다. 카드뉴스의 작업 공간 선택은 공유 컨트롤 높이와 패딩을 적용해 SNS와 일치시키고, 채널 선택 도움말·설명 헤더도 동일한 구조로 맞춘다.
- 상태 영역 위치 변경 검증: Card News 브라우저 smoke에서 생성 중 상태가 결과 제목 행에 표시되고 생성 설정 영역에는 남지 않는 것을 통과했다. 이번 전체 smoke는 이후 Blog Beta 발행 대상 검사(`scripts/test-ui-browser-smoke.js:3614`)에서 실패했다(워드프레스 대상 라디오 선택). 카드뉴스 계약 테스트 및 smoke 해당 구간은 통과.
- 실 AI 호출을 사용한 수동 검증은 미실행. 사용자는 카드뉴스 이미지 영역에서 전체/빈 이미지/개별 이미지 생성 각각에 대해 중지 확인, 계속 진행, 실제 중지를 확인해야 한다. 특히 KIE 사용 시 이미 접수된 요청과 비용은 계속될 수 있다.
