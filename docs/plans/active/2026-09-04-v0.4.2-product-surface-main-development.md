# v0.4.2 제품 화면 승격 메인 개발 기록

## Branch

- Branch: `codex/feat/v0.4.2-product-surface-main`
- Base/parent branch: `dev`
- Start date: 2026-09-04
- Status: 진행 중

## 사용자 필요와 목표

새 대시보드와 Blog Beta를 다음 정식 릴리즈의 기본 제품 화면으로 승격한다. 기존 구현은 참고 가능하도록 유지하되 사용자가 낡은 화면으로 잘못 이동하지 않게 하고, 새 화면임을 메뉴에서 명확히 알린다.

## 범위

- Dashboard `새로운 발견`의 소재 적용 목적지를 새 블로그 빠른 글 작성으로 교정
- 기존 블로그 메뉴만 숨기고 화면과 코드는 보존
- Blog Beta의 사용자 노출 명칭을 `블로그`로 승격하고 `new` 표시 유지
- 현재 대시보드에 `new` 표시 추가
- 사용자에게 노출되는 관련 이동 경로와 명칭의 일관성 점검
- 사용자 UI 승인 후 v0.4.2 릴리즈 준비로 인계

## 명시적 비범위

- `blog-next`, `dashboard-beta` 등 내부 view ID와 모듈명 변경
- 기존 블로그 코드 삭제
- 이 feature branch에서 버전 변경, 태그, push 또는 배포
- 기존 블로그의 기능 개선

## 설계

- 사용자 노출 명칭과 내부 기술 식별자를 분리한다. 메뉴와 제목은 정식 명칭으로 바꾸되 안정된 내부 라우팅 ID는 유지한다.
- 기존 블로그 메뉴는 기존 대시보드 메뉴와 같은 접근 불가 상태로 숨긴다.
- 추천의 `blog.quick` presentation은 호환 가능한 도메인 의미로 유지하면서 새 블로그의 quick 화면과 입력 필드로 연결한다.
- 메뉴 외 사용자 진입 경로와 모바일 기본 진입도 새 블로그를 가리키도록 정리한다.

## 구현 단계

1. sub-FB에서 추천 이동 버그와 제품 화면 승격 UI를 구현한다.
2. focused contract와 browser smoke를 통과시키고 사용자 UI 확인을 받는다.
3. 승인된 sub-FB를 본 parent에 병합한다.
4. parent 완료 후 `dev`에 병합하고 별도 release branch에서 v0.4.2 준비를 진행한다.

## 사용자와 결정한 사항

- 기존 블로그는 코드 삭제 없이 UI에서만 숨긴다.
- Blog Beta는 `블로그`로 승격하되 `new` 표시를 둔다.
- 현재 대시보드에도 `new` 표시를 둔다.
- 내부 ID는 유지해 회귀 위험을 줄인다.
- 정식 릴리즈 버전은 현재 계획상 v0.4.2다.

## 남은 위험 및 후속 작업

- 기존 `blog` 화면으로 직접 이동하는 사용자 진입 경로가 남아 있으면 숨긴 메뉴와 무관하게 구 화면이 노출될 수 있다.
- 새 블로그가 제공하지 않는 legacy 전용 하위 탭은 기계적으로 매핑하지 않고 실제 사용자 경로별로 판단해야 한다.
- `new` 표시는 후속 릴리즈에서 제거 시점을 결정한다.
