# Blog Writing Strategy Plan

## Goal

블로그 플랫폼과 관계없이 AI가 생성하는 글의 목적을 다음 두 가지 중 하나로 선택할 수 있게 한다.

- `검색 중심`: 검색 의도와 핵심어를 명확히 충족하는 정보형 글
- `발견 중심 (피드)`: 피드에서 우연히 글을 만난 독자의 관심과 읽기 흐름을 고려한 글

이 기능은 특정 플랫폼의 노출을 보장하는 기능이 아니다. 사용자가 글의 목적을 명확히 선택하고, 같은 입력으로도 제목·도입부·본문 전개의 우선순위를 조정하는 작성 전략이다.

## Product Principles

1. Simple is the best: 사용자가 이해할 선택지는 두 개만 제공한다.
2. 플랫폼 중립: 네이버와 워드프레스에 동일하게 적용한다.
3. 안전한 기본값: 기존 동작과 가장 가까운 `검색 중심`을 기본값으로 사용한다.
4. 명확한 상속: 개별 글의 `기본 설정 사용`은 값을 복사하지 않고 전역 설정을 동적으로 따른다.
5. 명시적 선택 우선: 개별 글의 참고/지시사항이 전략 지침과 충돌하면 사용자의 명시적 지시를 우선한다.

## Scope

### Included

- 설정 > 블로그에 전역 기본 작성 전략 추가
- 빠른 포스팅의 `바로 생성`에 개별 전략 선택 추가
- 일괄 포스팅의 글감 편집 팝업에 개별 전략 선택 추가
- 공통 AI 글 생성 프롬프트에 전략별 오버레이 적용
- 전역 및 개별 설정의 저장·복원·검증

### Inheritance Only

- 자동 글감 및 자동 포스팅으로 생성한 글감은 별도 제어 없이 전역 기본값을 따른다.
- 자동 생성된 글감도 일괄 포스팅 편집 팝업에서 개별 전략을 지정할 수 있다.

### Excluded

- 원고 폴더와 원고 붙여넣기: 이미 작성된 원고를 다시 생성하지 않으므로 적용하지 않는다.
- 쇼핑커넥트 글: 이번 범위에서 제외한다.
- 플랫폼별 별도 전략, 노출 점수, 성과 예측 또는 노출 보장

## UX Contract

### Global Setting

- 위치: 설정 > 블로그
- 라벨: `글 작성 전략`
- 선택:
  - `검색 중심`
  - `발견 중심 (피드)`
- 기본값: `검색 중심`

도움말은 다음 차이를 설명한다.

- 검색 중심: 검색 의도와 핵심어를 분명히 다루고, 필요한 정보를 쉽게 찾도록 구성한다.
- 발견 중심 (피드): 피드에서 우연히 만난 독자가 관심을 갖고 계속 읽도록 제목·도입부·전개를 구성한다.
- 어떤 선택도 검색 또는 피드 노출을 보장하지 않는다.

### Per-post Override

빠른 포스팅과 글감 편집 팝업은 다음 세 가지 선택을 제공한다.

- `기본 설정 사용 (현재: 검색 중심)` 또는 `기본 설정 사용 (현재: 발견 중심)`
- `검색 중심`
- `발견 중심 (피드)`

개별 선택은 전역 설정을 변경하지 않는다.

## Data Model

### Global

```json
{
  "content": {
    "blog": {
      "writing_strategy": "search"
    }
  }
}
```

허용값은 `search`, `discovery`이며 누락되거나 잘못된 값은 `search`로 정규화한다.

### Per-post

글감의 `options` JSON에는 개별 지정이 있을 때만 아래 값을 저장한다.

```json
{
  "writing_strategy": "discovery"
}
```

`기본 설정 사용`은 `writing_strategy`를 삭제한다. 따라서 전역 기본값 변경이 아직 생성되지 않은 상속 글감에 즉시 반영된다.

### Resolution Order

1. 개별 글의 명시적 `writing_strategy`
2. 전역 `content.blog.writing_strategy`
3. 안전 기본값 `search`

프롬프트 내부의 충돌 우선순위는 다음과 같다.

1. 사용자가 입력한 참고/지시사항
2. 해석된 글 작성 전략
3. 공통 블로그 작성 규칙과 전역 문체

## Prompt Architecture

공통 생성 프롬프트는 다음 레이어를 조합한다.

1. 공통 블로그 생성 규칙
2. 전역 문체 규칙
3. 검색/발견 작성 전략 오버레이
4. 주제, 키워드, 참고 자료와 사용자 지시

### Search Overlay

- 독자의 검색 의도와 질문에 직접 답한다.
- 핵심 주제와 키워드를 제목·도입부·소제목에 자연스럽게 반영한다.
- 구체적인 정보와 구조를 우선하되 키워드를 반복해서 채우지 않는다.

### Discovery Overlay

- 피드에서 맥락 없이 처음 접한 독자도 관심을 가질 제목과 도입부를 만든다.
- 구체적인 상황, 변화, 의외성 또는 독자가 공감할 문제를 활용한다.
- 핵심을 전부 숨기거나 과장하지 않고 본문과 제목의 약속을 일치시킨다.
- 경험, 수치, 최상급 표현, 긴급성을 사실 없이 만들어내지 않는다.
- 글의 핵심 주제와 자연스러운 검색어는 유지한다.

## Architecture

- `src/content/writing-strategy.js`: 정규화, 상속 해석, 설명, 프롬프트 생성의 단일 출처
- `src/config-loader.js`: 전역 설정을 `CONFIG.BLOG_WRITING_STRATEGY`로 해석
- settings service/server: 전역 설정 저장 및 런타임 반영
- `src/content/publish-sheet-options.js`: 개별 오버라이드 저장·복원
- `src/core.js`: 플랫폼 분기 전 공통 전략 해석 및 프롬프트 결합
- UI: 전역 선택과 두 개의 개별 선택 지점만 제공

## Research Boundary

네이버 공식 도움말은 블로그 홈 추천에 이웃 관계와 활동, 읽은 글 여부, 이웃의 인기·조회 글, 유사 사용자가 본 글 등의 신호가 사용된다고 설명한다. 연령별 추천에는 인기·반응·무작위 요소도 언급한다. 이는 `발견 중심 (피드)`이라는 작성 목적을 뒷받침하지만, 특정 제목 형식이나 이른바 클릭 유도 문구가 노출을 보장한다는 근거는 아니다.

- [네이버 블로그 연령별 추천 도움말](https://help.naver.com/service/5593/contents/22517)

## Validation

- 전략 정규화, 상속 및 프롬프트 단위 테스트
- 글감 options의 저장·삭제·복원 테스트
- 빠른 포스팅 요청에서 개별 전략 전달 테스트
- 설정 저장 후 런타임 전역값 반영 테스트
- 기존 설정이 없는 상태에서 `search` 기본값 유지 회귀 테스트
- 전체 단위 테스트 실행
