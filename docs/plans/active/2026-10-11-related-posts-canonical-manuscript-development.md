# 원고 기준 연관글 확정 개발 기록

- Branch: `codex/related-posts-manuscript-truth`
- Start date: 2026-10-11
- Base/parent branch: `release/v0.6.0`
- Status: 통합 원고 편집기 동기화 수정 및 집중 검증 완료, 사용자 수동 확인 대기

## 사용자 필요와 목표

연관글은 원고에 한 번만 들어가야 한다. 편집 화면에서 보이는 Markdown이 실제 발행 내용이어야 하며, 사용자가 연관글을 수정하거나 삭제하면 그 결정이 발행과 재시도에도 유지되어야 한다. 자동 발행처럼 편집 화면이 열리지 않는 흐름도 같은 원고 확정 규칙을 적용해야 한다.

## 범위와 비범위

포함:

- AI 생성, 붙여넣기, 폴더 원고에서 연관글을 발행 대상과 무관하게 확정
- 사이트 호스팅을 포함한 Blog Beta 발행 경로와 자동 발행 대기열 적용
- 기존 연관글 섹션을 중복 생성하지 않고, 사용자의 편집/삭제를 Draft 상태로 기억
- 편집 원고, 미리보기, 발행 payload 간 내용 일치 보장
- 집중 단위/서비스 테스트와 관련 UI 회귀 테스트

비포함:

- 사이트 호스팅의 기존 게시물을 연관글 후보 소스로 추가
- 레거시 블로그 화면/발행 경로의 동작 변경
- 별도 연관글 후보 정책 변경(현행 네이버·WordPress 통합 후보와 최대 3개 규칙 유지)
- full unit suite 및 dev merge (부모 브랜치 병합 단계에서 별도 승인 필요)

## 설계

- Draft의 Markdown을 연관글과 게시 본문을 포함하는 단일 canonical 원고로 둔다.
- 신규 원고 준비 시 한 번만 연관글을 확정한다. 기존 섹션이 있으면 그대로 보존하고 재삽입하지 않는다.
- Draft manifest는 자동 확정, 사용자 제공/편집, 사용자 삭제, 수집 실패/후보 없음 상태를 구별한다. 발행 설정 변경이나 재시도는 사용자 삭제 상태를 되살리지 않는다.
- 편집 가능한 Markdown 업데이트는 현재 원고와 비교해 사용자의 제거 의도를 상태로 저장한다. 최종 발행은 동일 revision의 저장 Markdown을 사용한다.
- 편집기 없는 자동 발행 대기열도 동일한 Draft 서비스 확정 API를 호출하고 그 결과 Draft revision을 발행한다.
- 후보는 기존처럼 연결된 네이버/WordPress 피드에서 수집한다. 사이트 게시물 자체를 후보화하는 일은 별도 설계로 둔다.

## 결정과 트레이드오프

- 사용자가 화면에서 보는 내용과 게시되는 내용의 일치를 우선한다.
- 연관글을 Markdown 안의 일반 본문으로 확정하면 플랫폼별 변환은 가능하지만, 게시 대상 고유한 표시 차이는 어댑터 책임으로 남는다.
- 사용자가 삭제한 섹션은 자동 복구보다 사용자 의도를 우선한다. 다시 추가하려면 명시적인 사용자 동작이 필요하지만, 이번 범위에서 재생성 UI를 추가할지는 기존 UI 계약을 조사해 최소 범위로 결정한다.

## 진행 및 검증

- 2026-10-11: 기존 Draft 생성/갱신, Site Hosting 제외 조건, 자동 발행 queue 경로를 조사했다. 작업 트리는 깨끗했고 `release/v0.6.0`에서 이 브랜치를 시작했다.
- 2026-10-11: related heading 감지와 링크 수 계산을 공통 원고 도메인 모듈에 추가했다. 기존 연관글 섹션은 유지하고, 반복 실행은 자동 확정 상태로 한 번만 처리하게 했다.
- 2026-10-11: Draft manifest에 `pending`, `automatic`, `user_managed`, `user_removed` 결정을 기록한다. Markdown 수정에서 삭제 의도를 감지하고 설정 변경·발행 재시도 후에도 자동 복구하지 않는다. 이전 Draft의 `included` 상태에서 섹션이 이미 사라진 경우도 사용자 삭제로 보수적으로 처리한다.
- 2026-10-11: Site Hosting을 연관글 확정 제외 대상에서 제거했다. Site Hosting 자동 발행용 AI 작성은 기존 `generateAiManuscriptDraft()` 경로가 최종화하므로 queue wrapper에서 중복 호출하지 않도록 검증했다.
- 2026-10-11: 처음 `node --test`를 실행할 때 `BLOGGENIUS_ENV`가 없어 테스트 모듈 로딩 전에 실패했다. `BLOGGENIUS_ENV=local`로 재실행해 통과했다. 다섯 개의 집중 테스트 파일에서 70개 테스트 통과, `git diff --check` 및 변경 JavaScript 구문 검사를 통과했다.
- 2026-10-11: 사용자의 실제 테스트에서 통합 `미리보기 · 원고 입력` 편집기에 연관글이 보이지 않는 문제가 확인됐다. 조사 결과, 서버는 관련글이 추가된 원고를 반환했지만 UI의 `ai` 경로가 그 canonical Markdown을 편집기와 동기화하지 않았다. 기존 `folder`/`paste` 경로에만 있던 동기화 동작을 공통 병합 함수로 만들고, 통합 편집기도 사용하도록 수정했다. 요청 처리 중 편집된 본문은 보존하고, 사용자가 이미 보이는 섹션을 삭제한 변경은 응답 도착 시 되살리지 않도록 했다.
- 2026-10-11: 통합 quick-flow 계약 테스트에 실제 병합 함수의 초기 자동 추가, 요청 중 본문 수정, 사용자 삭제 보존, 기존 사용자 섹션 보존 사례를 추가했다. 변경 후 68개 집중 테스트 통과.

## 최종 결과와 남은 작업

구현 결과: 통합 `미리보기 · 원고 입력` 편집기와 Draft canonical Markdown이 같은 원고를 사용하도록 동기화한다. 연관글이 이미 있으면 다시 수집·추가하지 않고, 자동 확정한 연관글의 사용자 편집은 보존하며 삭제는 Draft 결정으로 저장한다. 사이트 호스팅 즉시 게시와 자동 대기열은 기존 AI Draft 생성 확정 경로를 공유한다.

사용자 수동 확인:

- 통합 `미리보기 · 원고 입력` 편집기에 붙여넣은 Markdown에서 연관글이 편집기와 미리보기 양쪽에 보이고, 게시 본문에도 한 번만 들어가는지 확인
- AI/폴더 입력에서 편집기와 미리보기, 게시 본문이 같은지 확인
- 섹션과 링크를 직접 수정한 뒤 미리보기·발행 결과가 그대로인지 확인
- 섹션을 지운 뒤 발행 설정을 바꾸거나 미리보기를 다시 열어도 복구되지 않는지 확인
- 사이트 호스팅 즉시 게시와 사이트 호스팅 대기열 게시 결과 확인
- 자동 수집 실패 또는 후보 없음 안내 확인

아직 브랜치 리뷰·commit·merge는 하지 않았다. 부모 feature branch를 `dev`에 병합하기 전 full unit suite와 전체 diff review가 필요하며, 그 전에 명시적 승인을 받는다.
