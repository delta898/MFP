# 확인 결정 소유권 검증

- 브랜치: `fix/agent-confirmation-ownership`; 기준: `main` (a1c46fb9); 시작: 2026-11-10
- 상태: 구현 중, 독립 리뷰·QA 및 병합 전.
- 목표: 공통 확인 결정에서 채널·사용자·대화 소유권과 결정값을 검증하고 최근 요청 선택도 동일 경계로 제한한다.
- 범위: Runtime 및 관련 회귀 테스트. 비목표: 저장 내구성, 재시작 복구, Telegram 그룹 개인별 식별, 외부 발행.
- 설계: 저장된 소유자와 호출 컨텍스트를 비교해 불일치와 식별자 누락을 차단한다. 기존 채널 기본값 telegram을 유지한다. 최근 요청은 같은 경계의 항목만 선택한다.
- 검증: 소유권 필드별 승인/거절, 정상 및 잘못된 결정, 만료·중복·동시 실행 및 기존 호출자 테스트를 집중 실행한다. 전체 suite는 별도 승인 전 실행하지 않는다.

## 결과 및 검증
- Runtime에서 소유자 세 필드 비교와 비어 있는 사용자·대화 차단, 승인/거절 외 입력 거부를 추가했다. 기존 컨텍스트 계약의 채널 기본값 `telegram`은 유지한다. 최근 승인·거절은 같은 채널과 대화의 대기 항목에서 선택한다.
- 수정 전 타 채널 승인 차단 테스트는 실패했고 수정 후 관련 Runtime·최근 요청·MCP·Telegram·저장소 테스트 25개가 통과했다. MCP 및 Telegram은 실제 Runtime을 모의 전송·모의 실행과 연결해 검사했다. 만료 시각 및 실행 중 동시 승인도 검사했다.
- 기존 저장소의 장시간 실행 만료, 저장 실패·재시작 복구와 Telegram 그룹 개인별 권한은 이 범위에서 변경하거나 검증하지 않았다. 외부 서비스 발행 및 전체 suite는 실행하지 않았다. 독립 리뷰·QA와 병합은 남아 있다.

## 독립 리뷰 후 계획 대체 경계 수정
- 계획 대체 직전에 기존 확인의 채널·사용자·대화 소유권 및 pending 상태를 검사한다. 대상이 없거나 조건이 맞지 않으면 새 확인을 만들지 않고 오류를 반환한다. 기존 telegram 채널 기본값은 호환성을 위해 유지하며 채널을 명시적으로 요구하지 않는다.
- 수정 전 타 소유자 및 accepted/executed 항목의 상태가 rejected로 덮이는 것을 회귀 테스트로 재현했다. 수정 후 소유자 각 필드와 누락 ID, 처리 중·완료, 정상 대체를 포함한 관련 Runtime·최근 요청·Telegram·MCP·저장소 집중 테스트 34개 및 `git diff --check`가 통과했다.
- 단일 프로세스 모의 검증이며 다중 프로세스 경합, 실제 외부 발행, 전체 suite 및 저장 실패·재시작 복구는 검증하지 않았다. 독립 재리뷰·QA 및 병합 전이다.

## 만료 경계 재리뷰 후 수정
- 조회와 상태 전환 사이에 시계를 만료 시각으로 이동시키는 Runtime 승인·거절·대체와 추천 실행 승인·거절의 다섯 경로에서 수정 전 결함을 재현했다.
- 저장소는 만료 정리 후 pending일 때만 승인·거절한다. Runtime과 추천 실행 서비스는 전환 실패를 처리하며 작업이나 성공 이벤트를 진행하지 않는다. 계획 대체는 기존 실패 분기를 사용한다.
- 관련 Runtime·최근 요청·Telegram·MCP·저장소·추천 서비스 집중 테스트 50개 및 `git diff --check` 통과. 모의 시계와 모의 작업 기반이며 실제 외부 발행 및 전체 suite는 실행하지 않았다.
- 단일 저장소 인스턴스에서 동기 전환을 보장할 뿐, 별도 프로세스나 별도 인스턴스 간 원자성·저장 내구성은 보장하지 않는다. 독립 재리뷰·QA 및 병합 전이다.

## MCP 승인 응답 경계 수정
- Runtime의 선택적 승인 전환 통지를 MCP가 수신한 뒤에만 접수 응답한다. 전환 전 만료 등 실패는 Runtime 결과를 전달하고, 실행 완료는 기다리지 않는다. 다른 Runtime 호출자는 기존 반환 계약을 유지한다.
- MCP 첫 조회 후 Runtime 조회 또는 저장소 승인 전환에서 만료되는 경우와 실제 Runtime을 연결한 장시간 실행·동시 중복·소유자 차단 및 승인 후 실행 실패를 회귀 검증한다. 단일 저장소 인스턴스와 모의 작업 기준이며 다중 인스턴스·실제 외부 발행·전체 suite는 미검증이다. 독립 리뷰·QA 전이다.


## 승인 저장 및 추천 실패 경계 (독립 검증 대기)
- 저장 경로가 지정된 경우 임시 파일 기록·파일 동기화·이름 교체·디렉터리 동기화를 거치며 오류를 전파한다. 읽기 오류나 유효하지 않은 파일도 닫힌 상태로 실패한다. 메모리 전용 구성은 영속성 보장이 없다.
- 승인 저장 오류 시 MCP 승인 통지와 외부 작업 전 실행이 중단된다. 부분 임시 쓰기 오류와 교체 후 오류를 주입하여 재생성 시 각각 pending과 accepted를 확인했다. 두 경우 모두 승인 호출은 실패하고, 교체 후 결과는 불확실하므로 실행하지 않는다.
- 추천 시작 거부는 실행 전 확정 실패로 기록한다. capability 호출 이후의 오류·실패 응답은 부작용 유무가 불확실하여 진행 상태를 유지하고 새 실행을 차단한다. 이 정책은 확인 없는 추천 실행에도 적용되며 기존 실패 후 재시도 동작을 변경한다.
- 관련 7개 파일의 집중 테스트 62개 및 `git diff --check` 통과. 본 저장소에는 의존성이 없어 원본 worktree의 기존 node_modules를 NODE_PATH로 사용했다. 전체 suite, 실제 외부 작업, 다중 프로세스, 실제 전원 장애 및 Windows 디렉터리 동기화는 미검증이다. 저장 매체·파일시스템·OS의 내구성, 추천 상태 저장소의 재시작 복구와 별도 확인 생성에 대한 중복 방지는 이 fixture만으로 보장하지 않는다. 독립 리뷰·QA 전이며 병합하지 않았다.

## 추천 재시도 호환성 후속 (독립 검증 대기)
- registry의 실행 직전 재검증이 명시적으로 거부된 경우에만 실행 미호출 증거를 내부 표식으로 전달한다. 추천을 action_failed로 기록해 새 요청으로 재시도할 수 있고, 승인 경로는 이전 확인을 failed로 기록한 뒤 새 확인을 요구한다. 내부 capability 호출에서 전파된 동일 표식은 불확실한 외부 호출 결과로 취급한다.
- capability 실행 이후 예외와 unsuccessful 응답은 여전히 불확실하므로 자동 재실행하지 않는다. `action_in_progress` 또는 `accepted`가 남으면 외부 결과를 운영자가 확인해야 하며, 이 변경은 수동 상태 복구 UI나 복구 API를 제공하지 않는다. 실행 전 검증 자체의 부작용이 없다는 기존 capability 계약을 전제로 한다.
- 실패 상태 저장이 오류를 반환하면 성공·안전한 복구라고 주장하지 않는다. 실패 기록 저장 결과가 불확실할 때 실제 복원 상태는 저장소 구현에 좌우된다. 기존 저장 실패·재시작 fixture는 confirmation 저장소 객체 재생성이지 실제 강제 종료·전원 장애가 아니다.
- registry·추천·MCP·Telegram·Runtime·confirmation 저장소 8개 테스트 파일 73개 통과. 실제 외부 발행, 전체 suite, 다중 프로세스 및 실제 장애 복구는 미검증. 독립 리뷰·QA 및 병합 전이다.
