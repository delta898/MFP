# v0.4.3 Electron 44 Upgrade Development Record

## Branch
- Branch: `codex/fix/v0.4.3-electron-44-upgrade`
- Base/parent branch: `release/v0.4.3`
- Start date: 2026-09-05
- Status: implementation complete; committed on feature branch

## User Need
A Windows user experienced an application window whose content did not appear. The exact cause could not be confirmed because follow-up logs and reproduction results were unavailable. Independently, the current Electron 40 runtime has reached end of support, so the user wants to upgrade Electron during v0.4.3 preparation and validate the application before considering GPU-specific changes.

## Goal
Upgrade the desktop runtime from Electron 40 to the current supported Electron 44 line while preserving existing behavior and validating startup, UI loading, packaging contracts, and native dependency boundaries.

## Scope
- Update the Electron development dependency and lockfile to the supported Electron 44 line.
- Review Electron 41–44 breaking changes that affect the current application.
- Run focused runtime, launcher, UI, and packaging contract tests.
- Run broader release verification after focused checks pass.
- Record manual Windows and macOS packaged-app checks still required.

## Explicit Non-goals
- Do not disable GPU acceleration or add a GPU compatibility mode in this stage.
- Do not claim that the Electron upgrade resolves the unconfirmed Windows blank-window report.
- Do not add unrelated UI, feature, release publication, tag, or deployment work.

## Proposed Design
Keep Chromium's default hardware acceleration behavior unchanged. Upgrade only the Electron runtime and treat the Windows blank-window report as a separate diagnostic concern until it can be reproduced or supported by logs.

The application does not directly rely on WebGL or a dedicated GPU API. Chromium may still use GPU acceleration internally for compositing, CSS effects, and image rendering.

## Affected Boundaries
- `package.json` and `package-lock.json`
- Electron main-process startup and BrowserWindow creation
- development and production launchers
- macOS and Windows packaging contracts
- optional Kuzu native-module loading and fallback

## Decisions and Tradeoffs
- Upgrade during v0.4.3 preparation because the release is not urgent and can absorb compatibility testing.
- Keep GPU acceleration enabled by default; there is not enough evidence to apply a global workaround.
- Use a short-lived feature branch based on `release/v0.4.3` so the runtime change can be reviewed and merged independently.
- The user explicitly approved Electron 44 and macOS 13+ as the v0.4.3 compatibility baseline. Electron 43 is no longer the target.

- Electron 44 requires macOS 13 or later; this is now an explicitly approved v0.4.3 requirement and is documented for users.
