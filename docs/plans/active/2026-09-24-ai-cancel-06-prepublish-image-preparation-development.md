## 사용자 필요와 목표

`블로그 Beta`의 바로 생성·원고 폴더·붙여넣기는 현재 발행 요청 안에서 비어 있는 이미지 프롬프트를 자동 생성할 수 있다. 사용자는 이미지의 처리 방식을 미리보기에서 결정하고, 포스팅 시작 뒤에는 AI 이미지 생성이나 업로드 없이 블로그 반영만 진행하기를 원한다. 이미지 프롬프트 자리표시자를 유지한 임시저장은 유효한 선택이다.

## 범위와 비범위

- 첫 단계는 `바로 생성`만 대상으로 이미지 슬롯을 미리보기에서 AI 생성·파일 선택·프롬프트 유지·제외 중 하나로 정리한 뒤 포스팅한다.
- `바로 생성`은 임시저장 시 프롬프트를 유지할 수 있고, 발행 요청 안에서 AI 이미지 생성을 하지 않는다.
- 프롬프트만 남은 `바로 생성` 원고는 임시저장만 허용한다. 모든 이미지가 처리되면 즉시·예약 발행을 허용한다.
- 원고 폴더·붙여넣기는 현재 동작을 유지하고, 후속 단계에서 별도로 통일한다.
- 원고 생성 취소 UI의 상단 통합, 이미지 준비 중 취소 기능, 블로그 반영 중 취소는 이번 브랜치에서 구현하지 않는다. 현재 parent의 다른 입력 방식이나 기존 `블로그`·쇼핑커넥트·카드뉴스로 범위를 넓히지 않는다.

## 설계·단계

1. `바로 생성`의 발행 경계를 수정해 발행 요청 안에서 이미지 생성이 일어나지 않도록 한다.
2. UI에서 미해결 프롬프트가 있으면 임시저장만 선택할 수 있게 하고, 해결 후 즉시·예약 발행을 허용한다.
3. 관련 단위·계약 검사와 Blog Beta 브라우저 smoke로 확인하며 단계별로 커밋한다. 유료 AI 호출과 실제 포스팅은 자동 검증에서 제외한다.
4. 이후 원고 폴더·붙여넣기에 같은 흐름을 적용한다.

## 결정과 대안

- 사용자가 확정한 원칙: `포스팅` 단계에 들어선 뒤 이미지 작업은 없어야 한다. 프롬프트 자리표시자를 가진 임시저장은 허용한다.
- 사용자가 확정한 진행 방식: 먼저 `바로 생성`에서 동작을 확정하고, 이후 원고 폴더·붙여넣기를 이어서 맞춘다. 과도한 sub-feature 분리 없이 단계별 커밋으로 구분한다.
- 미리보기의 기존 `AI로 만들기`, `내 이미지 선택`, `사용 안 함`, `빈 이미지 모두 만들기`를 우선 활용한다. 포스팅 버튼 옆에 중복 이미지 생성 버튼을 먼저 추가하지 않는다.
- 이미지가 없으면 무조건 발행을 막는 단일 규칙은 채택하지 않는다. 임시저장과 최종 발행은 목적이 다르다.
- 즉시·예약 발행에 프롬프트가 남은 경우 기존 서버 안전장치가 임시저장으로 전환한다. `바로 생성` UI에서는 처음부터 임시저장 외 선택을 비활성화한다.

## 진행·검증·후속

- 2026-09-24: 상태·메시지 sub-feature를 parent에 병합하고 전체 unit suite 1,932개 통과·1개 건너뜀을 확인한 뒤 이 브랜치를 생성했다. parent의 기존 미커밋 문서 수정은 이 브랜치에서도 보존한다.
- 코드 검토 결과 `preparePublishPayload()`가 세 입력 유형 모두에 대해 발행 전 이미지를 자동 생성하고 있었다. `바로 생성`만 이 경로에서 제외하고, 폴더·붙여넣기는 이번 단계에서 그대로 둔다.
- 서버 변경: AI 원고는 발행 준비 시 자동 이미지 생성을 생략한다. 미해결 프롬프트는 payload에 유지되며, 요청 상태가 즉시·예약 발행이어도 기존 안전 규칙에 따라 임시저장으로 전환된다.
- 검증: `node --test src/content/manuscript-draft-service.test.js` 통과 (22/22). 폴더/붙여넣기 자동 생성 동작 테스트도 그대로 통과했다.
- 수동 확인 필요: 네이버·워드프레스 임시저장 결과의 이미지 프롬프트 표시 및 이미지를 모두 결정한 뒤 발행되는 흐름.
- 남은 위험: 두 플랫폼에서 프롬프트 자리표시자 표현이 다를 수 있다. 실제 포스팅과 유료 AI 이미지는 별도 승인 없이 테스트하지 않는다.
