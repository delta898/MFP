## 사용자 필요와 목표

`블로그 Beta`의 바로 생성·원고 폴더·붙여넣기는 현재 발행 요청 안에서 비어 있는 이미지 프롬프트를 자동 생성할 수 있다. 사용자는 이미지의 처리 방식을 미리보기에서 결정하고, 포스팅 시작 뒤에는 AI 이미지 생성이나 업로드 없이 블로그 반영만 진행하기를 원한다. 이미지 프롬프트 자리표시자를 유지한 임시저장은 유효한 선택이다.

## 범위와 비범위

- 첫 단계는 `바로 생성`만 대상으로 이미지 슬롯을 미리보기에서 AI 생성·파일 선택·프롬프트 유지·제외 중 하나로 정리한 뒤 포스팅한다.
- `바로 생성`은 임시저장 시 프롬프트를 유지할 수 있고, 발행 요청 안에서 AI 이미지 생성을 하지 않는다.
- 프롬프트만 남은 `바로 생성` 원고는 임시저장만 허용한다. 모든 이미지가 처리되면 즉시·예약 발행을 허용한다.
- 원고 폴더·붙여넣기는 현재 동작을 유지하고, 후속 단계에서 별도로 통일한다.
- AI 생성 제어 문구는 사용자에게 `중지`로 표현하고 내부 API/state 명칭은 유지한다.
- 네이버 브라우저 자동화 포스팅은 최종 저장·발행 요청 직전까지 중지를 허용한다. 최종 요청 직후부터는 외부 반영 여부가 불확실하거나 이미 완료됐을 수 있으므로 중지 버튼을 제공하지 않는다.
- 워드프레스 API 발행, 기존 `블로그`·쇼핑커넥트·카드뉴스에는 이번 중지 제어를 적용하지 않는다.
- 입력 재료와 결과 원고는 별개다. 주제·키워드·글쓰기 옵션을 바꿔도 현재 미리보기 원고는 유지되며, 미리보기를 다시 실행해 성공할 때만 결과 원고가 교체된다. 따라서 재료만 바꾸고 미리보기를 실행하지 않았다면 현재 원고를 포스팅한다.
- 중복 발행 기준은 `원고 결과 버전 + 발행 플랫폼`이다. 원고 결과는 글과 이미지를 포함하며, 이미지 변경은 새 원고 버전이다. 발행 방식·예약 시간·카테고리 변경만으로는 같은 플랫폼에 재발행할 수 없다. 발행 대상은 단일 라디오이며, 같은 원고를 다른 플랫폼에 발행하는 것은 허용한다.
- AI 생성·이미지 작업·포스팅이 진행 중일 때는 입력과 실행 관련 컨트롤을 잠근다. 작업이 끝나면 입력 재료는 다시 편집할 수 있으며, 현재 결과 원고에는 자동 반영하지 않는다.

## 설계·단계

1. `바로 생성`의 발행 경계를 수정해 발행 요청 안에서 이미지 생성이 일어나지 않도록 한다.
2. UI에서 미해결 프롬프트가 있으면 임시저장만 선택할 수 있게 하고, 해결 후 즉시·예약 발행을 허용한다.
3. 관련 단위·계약 검사와 Blog Beta 브라우저 smoke로 확인하며 단계별로 커밋한다. 유료 AI 호출과 실제 포스팅은 자동 검증에서 제외한다.
4. 이후 원고 폴더·붙여넣기에 같은 흐름을 적용한다.
5. 공유 실행 상태/API 중지 신호를 네이버 발행 자동화까지 전달하고, 발행 UI에서 중지 가능 구간만 노출한다.
6. 작업 중 입력/실행 컨트롤을 잠그고 완료 시 복구한다. 결과 원고는 마지막 미리보기 성공본으로 유지한다.
7. 원고 결과 버전을 글·이미지 내용으로 식별하고 플랫폼별 발행 이력을 기록해 동일 조합만 중복 차단한다. 발행 설정만 바뀐 경우는 같은 조합이다.

## 결정과 대안

- 사용자가 확정한 원칙: `포스팅` 단계에 들어선 뒤 이미지 작업은 없어야 한다. 프롬프트 자리표시자를 가진 임시저장은 허용한다.
- 사용자가 확정한 진행 방식: 먼저 `바로 생성`에서 동작을 확정하고, 이후 원고 폴더·붙여넣기를 이어서 맞춘다. 과도한 sub-feature 분리 없이 단계별 커밋으로 구분한다.
- 미리보기의 기존 `AI로 만들기`, `내 이미지 선택`, `사용 안 함`, `빈 이미지 모두 만들기`를 우선 활용한다. 포스팅 버튼 옆에 중복 이미지 생성 버튼을 먼저 추가하지 않는다.
- 이미지가 없으면 무조건 발행을 막는 단일 규칙은 채택하지 않는다. 임시저장과 최종 발행은 목적이 다르다.
- 즉시·예약 발행에 프롬프트가 남은 경우 기존 서버 안전장치가 임시저장으로 전환한다. `바로 생성` UI에서는 처음부터 임시저장 외 선택을 비활성화한다.
- 사용자가 동의한 용어 원칙: AI·네이버 실행 중 작업을 멈추는 버튼은 `중지`로 부른다. `취소`가 비용·저장 결과까지 원상복구한다는 인상을 줄 수 있고, `정지`보다 작업 제어 문맥에 자연스럽다.
- 사용자가 확정한 동작 모델: 재료 → 명시적 미리보기 실행 → 원고 결과 → 발행 재료 → 포스팅 → 발행물. 재료 변경은 현재 원고를 무효화하지 않고 새 미리보기 성공만 결과를 바꾼다.
- 사용자가 확정한 중복 방지 규칙: `(원고 결과 버전, 발행 플랫폼)` 쌍으로 이미 처리된 조합은 재발행하지 않는다. 동일 원고의 다른 플랫폼 발행은 허용한다. 이미지가 바뀌면 원고 결과 버전이 달라지지만, 발행 방식·예약 시각·카테고리 변경은 버전을 바꾸지 않는다.
- 네이버 포스팅 중지는 앱의 브라우저 자동화를 종료하는 뜻이며, 먼저 완료된 네이버 저장·발행 결과를 되돌리는 기능은 아니다. WordPress 요청은 전송 뒤 확실한 회수가 불가능하므로 대상에서 제외한다.
