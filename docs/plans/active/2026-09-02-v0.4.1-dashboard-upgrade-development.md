## 사용자 필요와 목표

Dashboard를 여러 기능과 외부 콘텐츠가 나열된 화면에서 BlogGenius의 현재 운영 상태를 빠르게 이해하고 다음 행동으로 이동할 수 있는 관제 화면으로 재설계한다. Blog Beta의 연속 발행 상태와 대기열을 중심에 두고, 신뢰할 수 있는 발행 통계와 최근 결과를 단계적으로 추가한다. 제작자의 블로그와 SNS 콘텐츠는 사용자 데이터와 구분된 `BlogGenius 활용 팁`으로 선별 노출한다.

## 범위

1. Blog Beta 연속 발행·대기열을 위한 Dashboard 전용 read model
2. 현재 실행, 다음 발행, 대기/보관 글감 중심의 운영 UI
3. 플랫폼별 성공 결과를 근거로 한 처리 완료·공개 발행 통계
4. 오늘, 이번 주, 최종적으로 최근 30일 기간 집계
5. 최근 발행 결과와 후속 행동
6. 기존 Dashboard 정보 계층, 로딩, 고정 외부 피드 정리
7. 기존 Supabase surface content를 이용한 제작자 콘텐츠 선별 노출

## 명시적 비범위

- 네이버·WordPress 조회수, 방문자, 검색 순위 등 외부 분석 API가 필요한 통계
- 실제 발행 결과를 추정하거나 실패를 성공으로 계산하는 통계
- 사용자의 설정 채널과 제작자의 홍보 채널을 같은 콘텐츠로 취급하는 UI
- 버전 변경, release, push 및 배포

## 사용자와 결정한 사항

- Dashboard의 최우선 목적은 Blog Beta 발행 운영 현황이다.
- `처리 완료`와 `공개 발행`을 함께 제공한다. 임시 저장 중심 사용자도 자신의 사용 성향을 이해할 수 있어야 한다.
- 두 통계는 글감 행이 아니라 성공한 플랫폼 결과를 센다. 네이버와 WordPress가 모두 성공하면 2건이다.
- `처리 완료`는 공개 발행, 예약 등록, 임시 저장의 성공 결과를 포함한다.
- `공개 발행`은 BlogGenius가 실제 공개 발행까지 성공한 결과만 포함한다. 이후 사용자가 플랫폼에서 직접 공개한 사실은 추정하지 않는다.
- 기간은 오늘, 이번 주(월요일 시작), 최종적으로 최근 30일을 제공한다.
- 제작자 블로그와 SNS는 제거하지 않고 `BlogGenius 활용 팁`으로 명확히 구분해 하루 한 건 수준으로 선별 노출한다.
- 구현은 쉬운 운영 현황 데이터부터 독립적인 sub-feature 단계로 진행한다.
