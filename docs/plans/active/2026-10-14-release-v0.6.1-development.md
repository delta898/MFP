# Release v0.6.1

- Branch: `release/v0.6.1`
- Start date: 2026-10-14
- Base/parent branch: `dev` (`3a94213e`)
- Status: 정식 `0.6.1` 후보 준비 중

## 사용자 목표

0.6.0 정식 버전 이후 누적된 사용자 관점의 개선을 정리해 0.6.1 후속 릴리스 후보를 준비한다. 이번 릴리스는 Telegram 자연어 대화 경로 단일화와 그 전까지 `dev`에 통합된 사용자 가치가 확인된 변경을 포함한다.

## 범위

- 0.6.0 이후 `dev` 변경 이력과 현재 제품 동작을 조사해 릴리스에 포함할 사용자 관점의 항목을 선별한다.
- `CHANGELOG.md`의 0.6.1 항목을 사용자 가치 중심으로 작성한다.
- 사용자가 정한 `0.6.1` 버전을 앱 버전 원본과 lockfile 메타데이터에 함께 반영한다.
- 릴리스 후보에 필요한 테스트, 정합성 점검, build input, 최종 diff를 확인한다.
- 릴리스 커밋, push, tag는 별도 명시 요청 전까지 수행하지 않는다.

## 명시적 비목표

- 0.7.0 core/plugin 구조 변경, capability 자동 등록·가용성 계약, Telegram 기능 고도화
- 이번 버전에 포함되지 않은 후속 기능을 릴리스 노트에 확정적으로 기재
- 사용자 요청 없는 push, tag, 패키지 공개 또는 배포

## 설계 및 진행

- 2026-10-14: 사용자는 `release/v0.6.1`을 `dev`에서 만들고 그 브랜치에서 작업하도록 지정했다. 릴리스 버전은 `0.6.1`로 명시 승인되었다.
- 0.6.0 이후 변경 이력을 검토해 Telegram Bot 페어링, Telegram 자연어 대화 경로, 원고 이미지 붙여넣기·끌어놓기, Markdown 전환 후 이미지 유지 개선을 선별했다. 숨겨져 있던 구 화면 제거와 내부 정리는 사용자 릴리스 노트에서 제외했다.
- `CHANGELOG.md`에 0.6.1 사용자 변경과 Telegram 대화의 현 제한을 기록했다. 글감 저장/발행 대기 구분과 일부 기능 안내는 후속 개선이 필요하다고 명시했다.
- `package.json` 및 `package-lock.json` 버전을 함께 `0.6.1`로 올렸다.
- 사용자 요청에 따라 버전을 `0.6.1-dev1`로 조정하고 CHANGELOG 항목도 해당 개발 태그로 표시했다.
- 2026-10-14: 사용자가 `0.6.1` 정식 버전 배포를 요청했다. 개발 버전 메타데이터와 CHANGELOG를 정식 버전으로 승격하고, 태그 기반 GitHub 릴리스 workflow를 실행한다.
- 기존 `docs/README.md`에서 archive 경로가 Active Work 아래 잘못 놓여 있던 Telegram 개발 기록을 archive 목록으로 옮기고, 이번 릴리스 준비 기록을 Active Work에 등록했다.
- 전체 단위 테스트 2,256 passed / 2 skipped / 0 failed, 설정·Blog 자동화 API smoke, UI E2E와 browser smoke는 같은 구현이 feature branch에 있을 때 성공했다. 그 뒤 코드 변경 없이 `dev`에 통합되어 이 릴리스 브랜치에서도 결과를 재사용한다.
- 버전 계약 검사 3/3 통과, `package.json`과 lockfile의 세 버전 필드 `0.6.1` 일치, `git diff --check` 통과.
- `0.6.1-dev1` 기준 버전 계약 검사 3/3 통과, 앱/lockfile 버전 동기화 및 `git diff --check` 통과.
- `build.sh`는 `src/config/secret.js`가 있어야 Production build를 진행한다. 해당 개인 Production 설정 파일은 Git에서 제외되며 릴리스 준비에서 생성하지 않았다. 패키징 빌드 검증은 사용자가 가진 유효한 Production 설정이 있는 환경에서 별도로 진행해야 한다.

## 검증 및 남은 작업

- 릴리스 후보의 최종 Git diff와 변경 파일 목록을 확인한다.
