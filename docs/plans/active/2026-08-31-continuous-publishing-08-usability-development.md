# 연속 발행 Stage 8: 기능 사용성 완결

## 사용자 필요

연속 발행의 핵심 실행 기능은 동작하지만, 저장된 글감과 발행 대기열의 의미가 화면에서 혼동되고
Queue 수정·제거 뒤 작업 문맥이 바뀐다. 기존 빠른 포스팅의 추천 기능도 Blog Beta 입력 흐름에서
아직 사용할 수 없다. Trends/RSS 입력원을 늘리기 전에 현재 기능 흐름을 명확하고 완결되게 만든다.

## 목표

- 저장된 글감과 발행 준비가 끝난 Queue 글감을 서로 다른 상태와 숫자로 표현한다.
- Queue 수정·제거 뒤 사용자가 작업하던 화면 문맥을 유지한다.
- 기존 글감·키워드·AI 제목 추천 기능을 복제하지 않고 Blog Beta 경계에서 재사용한다.
- 다음 실행 시각, 최근 실행 결과와 단일 활성 기기 원칙을 기능적으로 확인할 수 있게 한다.
- 기능 기본 검증을 먼저 끝내고 시각적 UI/UX 고도화는 후속 작업으로 분리한다.

## 명시적 비목표

- 이번 단계에서 Trends/RSS 글감을 자동 수집하거나 Queue로 승격하지 않는다.
- 기존 `블로그` 메뉴를 제거하거나 `블로그 Beta`로 교체하지 않는다.
- 새로운 추천 AI 호출 경로나 prompt를 별도로 만들지 않는다.
- 색상, 간격, 애니메이션 등 시각적 완성도 개선은 기능 검증 뒤에 진행한다.

## 승인된 결정

1. Stage 8은 기능 기본 검증을 우선하고 UI/UX 고도화는 그 이후에 한다.
2. `대기`와 `발행 준비 완료`의 사용자 표현과 집계를 분리한다.
3. 수정·제거 작업은 Queue 문맥을 유지한다.
4. 추천 기능은 기존 검증된 기능을 재사용하며 새 구현으로 복제하지 않는다.
5. 사용자 용어는 `글감 저장` 대신 `글감 보관`으로 통일하고, `보관한 글감`과 `발행 대기열`을 별도 목록으로 제공한다.
6. 보관한 글감은 같은 행에서 계속 작성하거나 삭제할 수 있다.
7. 등록 뒤에는 내용만 비우고 설정은 유지하며, 최근 설정은 비밀정보 없이 기기별 기본값으로 기억한다.
8. 기기별 기본값은 별도 설명이나 초기화 버튼을 노출하지 않고, 사용자가 다음 등록에서 설정을 바꾸면 자연스럽게 갱신한다.
9. 상위 탭은 `글감 관리`로 부르고, 내부에서 `발행 대기열`과 `보관한 글감`을 sub-tab으로 구분한다.
10. 목록 동작은 `지금 실행·수정·빼기·삭제`, 팝업 동작은 `저장·보관·대기열 추가·취소`처럼 맥락에 맞게 짧게 표시한다.
11. 수정은 넓은 팝업에서 수행하고, 변경 후 닫을 때만 폐기 확인을 한다.
12. `지금 실행`은 선택한 준비 글감을 기존 포스팅 계획 그대로 처리한다. 순서 변경은 후속 단계로 분리한다.

## 구현 계획

1. Blog Beta shell, API와 상태 집계 구조를 조사하고 기능 계약을 보강한다.
2. Queue mutation 뒤 화면 문맥 유지와 명확한 상태 집계를 구현한다.
3. 기존 추천 모달·API를 Blog Beta 입력에 안전하게 연결한다.
4. 자동 실행 상태 정보를 기능 중심으로 보완한다.
5. 단위·계약·브라우저 회귀 테스트를 수행하고 사용자 수동 확인 항목을 정리한다.

## 완료 기준

- 보관한 글감과 발행 Queue가 별도 목록과 수로 구분된다.
- 보관한 글감을 조회·계속 작성·삭제할 수 있다.
