## 사용자 필요와 목표

AI 모델의 응답 지연과 재시도로 생성이 수분간 끝나지 않을 수 있다. 사용자는 기다리는 동안 현재 작업을 취소하고 다른 모델로 다시 시도하고 싶지만, 지금은 생성 요청을 중단하거나 실행 잠금을 안전하게 해제할 방법이 없다. KIE 이미지는 비동기 작업을 제출한 뒤 상태를 조회하므로, 일반 HTTP 요청 취소와 의미가 다르다.

목표는 `블로그 Beta`의 AI 원고 생성에서 사용자가 진행 중인 시도를 중단하고 다시 시작할 수 있게 하는 것이다. 취소 이후 늦게 도착한 결과가 새 작업이나 마지막 유효 원고를 덮어쓰지 않게 하며, 재시도·폴링·후속 단계를 멈추고 상태와 잠금을 일관되게 정리한다.

## 범위와 비범위

- 1차 제품 범위: `블로그 Beta`의 AI 원고 생성과 그 과정에서 호출되는 텍스트·이미지 모델.
- 생성 작업 단위의 ID, 상태, 취소 요청, 서버 측 중단 신호, 후속 결과 적용 방지.
- 공통 모델 호출 경계에서 Gemini, OpenAI 호환 텍스트 호출 및 이미지 호출에 중단 신호 전달. 모델별 UI/취소 구현이 아니라 transport별 구현으로 유지한다.
- KIE 이미지의 제출·폴링·결과 다운로드 각 단계에서 가능한 중단과, 이미 제출된 원격 작업의 처리 상태를 명확히 구분한다.
- UI에 진행 상태와 취소 동작을 제공하고, 취소·실패·재시도 이후 입력과 마지막 유효 결과를 보존한다.
- 결정적으로 재현 가능한 단위·계약·브라우저 회귀 검사.

이번 범위에 넣지 않을 것:

- 기존 `블로그` 화면, discovery, 댓글, 발행, Telegram 등 다른 작업의 UI 취소.
- 제공업체가 지원하지 않는 원격 작업의 강제 종료나 이미 발생한 과금의 취소 보장.
- 앱 재시작 후 작업 재개·취소, 여러 프로세스 간 작업 공유 등 영속 작업 큐 구축.
- 타임아웃·재시도 횟수 자체의 정책 변경. 취소 기능과 별도 판단한다.

## 현재 구조와 영향 경계

- 클라이언트 `ui/scripts/features/blog-next/draft-execution.js`는 AI draft 요청을 기다리며, 공통 `postJson`은 현재 중단 신호를 받지 않는다.
- 서버 `src/ui-api/services/content.service.js`는 원고 실행 lease를 획득하고 `finally`에서 해제한다. 요청 연결만 끊는 것은 서버 실행을 멈추는 계약이 아니다.
- `src/utils.js`의 텍스트·이미지 호출에는 재시도와 대기 단계가 있다. 취소되면 추가 재시도를 하지 않고 대기도 즉시 끝나야 한다.
- KIE 텍스트는 일반 HTTP 호출이다. KIE 이미지는 `src/ai/kie-market-image.js`와 `src/ai/async-job-runner.js`에서 원격 작업 ID를 받아 폴링한다. 로컬 폴링 중단과 원격 작업 취소는 별개로 표시해야 한다.
- 기존 생성 결과·작업공간 임시 자산·실행 잠금은 취소 시점과 늦은 응답에 따라 오염되지 않아야 한다.

## 단계와 제안 sub-feature 경계

### 0. 취소 계약 확정 — parent에서 설계

- 성공, 실패, 취소 요청 중, 취소 완료, 원격 작업 지속 가능 상태의 의미를 정의한다.
- 생성 단계별 부작용과 안전한 중단 지점을 목록화한다. KIE의 공식 원격 작업 취소 API 지원 여부를 확인한다.
- 작업 ID·취소 endpoint·중단 신호의 소유권, 단일 실행 잠금 해제 시점, 모델 선택 snapshot, 늦은 응답 무시 규칙을 결정한다.
- 취소가 새 작업 시작을 허용하는 시점은 **서버가 현재 작업 종료를 확인한 뒤**로 정한다. 단순히 브라우저 요청이 끊겼다는 이유로 허용하지 않는다.
- 코드 조사 결과를 반영한 상세 계약은 위 설계 결정 초안에 기록했다. 다음 sub-feature를 시작하기 전 비동기 시작 API와 KIE 제출 중 취소 UX를 사용자와 확정한다.

### 1. 작업 수명주기와 서버 취소 계약 — sub-feature 1

- 작업 ID와 상태 조회·취소 요청을 생성 coordinator에 연결한다. 동일 작업의 중복 취소는 안전해야 한다.
- 서버 실행 흐름에 중단 신호를 전달하고 단계 사이에 검사한다. 종료·오류·취소 모두 잠금과 임시 상태가 정리되게 한다.
- 늦은 결과가 취소된 작업의 Draft를 만들거나 기존 유효 결과를 덮어쓰지 못하게 한다.
- 이 단계의 계약·서비스 테스트를 작성한다.

### 2. 텍스트 transport 취소 — sub-feature 2

- Gemini, OpenAI 호환 경로(OpenAI·Anthropic 호환·KIE 텍스트 포함)에 같은 신호를 전달한다.
- HTTP 요청과 재시도 대기를 중단하고, 취소를 일반 실패나 재시도 대상으로 취급하지 않는다.
- provider별 취소·타임아웃·일반 실패를 분리해 검증한다.

### 3. 이미지 transport와 KIE 작업 취소 — sub-feature 3

- Gemini·OpenAI 이미지 요청 및 재시도 대기에 중단 신호를 적용한다.
- KIE 이미지의 제출 전, 원격 ID 수신 후 폴링 중, 다운로드 중 취소를 각각 처리한다.
- KIE가 원격 취소를 제공하면 해당 adapter를 사용하고 응답을 기록한다. 제공하지 않으면 로컬 실행 중단과 원격 작업 지속 가능성을 사용자에게 정확히 알리며, 원격 과금 취소를 약속하지 않는다.
- 작업 저널과 임시 파일에 취소 상태·정리 정책을 반영하고 후속 결과 적용을 막는다.

### 4. `블로그 Beta` UI와 통합 — sub-feature 4

- 생성 중 취소 버튼, `취소 요청 중`/`취소 완료` 피드백, 작업 단계 안내를 기존 UI 패턴으로 제공한다.
- 취소 확인 전 중복 실행을 막고, 완료 후 모델을 바꿔 다시 시도할 수 있게 한다.
- 입력·마지막 유효 원고 보존, 이전 요청의 늦은 응답 무시, 실패 후 재시도, KIE 폴링 중 취소를 브라우저 검사로 검증한다.

각 sub-feature는 이 parent에서 시작하고 자체 개발 기록을 가진다. 구현·검증·사용자 승인 후 parent에 병합하며, 마지막에는 통합 회귀를 확인한다. 실제 경계는 0단계 조사 결과에 따라 조정할 수 있다.

## 결정, 대안, 트레이드오프

- 브라우저 `fetch`만 중단하는 방식은 서버 측 AI 호출과 재시도를 멈추지 못할 수 있어 채택하지 않는다. 클라이언트 취소와 서버 실행 취소를 분리된 계약으로 설계한다.
- 모델마다 별도 취소 코드를 두지 않는다. 현재 transport 경계를 재사용해 신규 모델 추가가 취소 기능을 다시 구현하게 만들지 않는다.
- KIE 비동기 작업은 로컬 결과 적용 중단만으로 원격 계산·과금이 끝났다고 표현하지 않는다.
- 전체 AI 기능을 한 번에 바꾸는 대신 사용자가 지적한 `블로그 Beta`의 생성 흐름부터 적용한다. 공통 취소 계약은 이후 다른 기능으로 확장 가능하게 둔다.
- UI에서 모델 변경은 취소 완료 후 새 작업으로 처리한다. 실행 도중 설정을 바꿔 기존 호출이 다른 모델로 전환되는 동작은 제공하지 않는다.

## 결과, 검증 및 남은 확인

- 현재 결과: 서버 작업 계약, 텍스트·이미지 transport 단계가 parent에 병합 완료. UI 연결이 남았다.
- 자동 검증: 3단계 관련 집중 검사 63개 통과. UI 연결 단계가 끝나면 관련 browser smoke를 실행한다. parent의 `dev` 병합 전 전체 unit suite는 사용자 승인을 받아 실행한다.
- 수동 확인 필요: 실제 제공업체의 긴 응답 중 취소, KIE 이미지 작업 제출 후 취소 안내, 모델 변경 후 재실행, 마지막 유효 원고 보존.
- 남은 위험: 제공업체별 원격 취소 지원·과금 정책은 별도 확인이 필요하다. 유료 모델을 호출하는 검사는 사용자 승인 없이 실행하지 않는다.
