# Blog Beta 원고 생성 상태 개선 개발 기록

- 브랜치: `codex/fix/blog-next-generation-state`
- 시작일: 2026-09-20
- 기준 브랜치: `dev`
- 상태: 후속 이미지 모드 계약 구현 및 사용자 UI 확인 완료

## 사용자 필요와 목표

Blog Beta의 `바로 생성`에서 AI 오류가 난 뒤 다시 원고 생성을 시도하면 이전 오류 안내가 생성 중에도 남는다. 생성 중에는 원본을 지우는 동작을 막고, `내용 지우기`와 다음 구분선 사이의 시각적 간격도 바로잡는다.

목표는 새 생성 시도의 상태 전환을 명확하게 만들고, 비동기 생성 중 입력을 실수로 제거하지 못하게 하며, 기존 액션 배치의 간격을 디자인 토큰에 맞추는 것이다.

후속 확인에서 `이미지 사용 안 함`이 AI Draft 요청 조합 중 `prompt_only`로 덮어써져 이미지 블록과 발행 전 자동 생성 대상이 생기는 문제를 발견했다. 사용자의 이미지 처리 선택을 생성 경계부터 Draft 가져오기까지 보존하는 것도 이 브랜치의 목표에 포함한다.

## 범위

- 새 AI 원고 생성이 시작될 때 이전 생성 오류 안내 초기화
- AI 원고 생성 중 `내용 지우기`와 `되돌리기` 비활성화
- 복구 액션과 다음 액션 행의 구분선 사이 여백 추가
- 관련 정적 계약 및 브라우저 회귀 검사 보강
- `이미지 사용 안 함`을 AI 생성 요청까지 보존
- `none` 결과를 Draft로 가져올 때 이미지 블록과 이미지 파일을 방어적으로 제외
- 이미지 없는 원고에서 이미지 작업공간과 자동 생성 안내가 나타나지 않는지 검증

## 비범위

- 기존 Blog 화면 변경
- AI 요청·할당량 처리 정책 변경
- 입력 필드 전체 잠금 또는 생성 취소 기능 추가
- 원고 미리보기와 마지막 유효 결과 보존 정책 변경
- 원고 폴더·붙여넣기의 기존 이미지 슬롯 정책 변경

## 설계와 영향 경계

1. `draft-execution`의 생성 시작 경계에서 topic 결과와 draft validation을 함께 초기화한다. 기존 preview state는 지우지 않는다.
2. `quick-flow-ui`의 공통 action availability 계산에 복구 액션을 포함해 생성·제출 중 동일한 busy 상태를 사용한다.
3. `blog-next-quick-flow` 스타일에서 홈 화면의 복구 액션 슬롯 아래에 토큰 기반 간격을 둔다.
4. 실패 후 재시도 중 상태를 브라우저 검사로 재현해 stale 오류, clear 잠금, 완료 후 복구를 검증한다.
5. AI 생성 payload에서는 공통 Draft 설정이 사용자가 선택한 `imageMode`를 덮어쓰지 못하게 한다.
6. 서버 진입점에서 이미지 모드를 정규화하고 `none`이면 transient preview의 이미지 블록과 자산을 Draft에 포함하지 않는다.

## 결정과 트레이드오프

- 사용자가 새 생성 시도를 시작한 순간 이전 오류는 현재 상태가 아니므로 숨긴다.
- 실패가 발생해도 마지막 유효 preview는 유지한다. 오류 UI만 초기화해 기존 복구 정책을 보존한다.
- `내용 지우기`와 같은 슬롯의 `되돌리기`도 생성 중 잠근다. 두 동작 모두 생성 입력을 바꾸기 때문이다.
- 입력 필드 전체 잠금은 이번 사용자 요청보다 범위가 크므로 다루지 않는다.
- 이미지 없는 상태를 UI에서 임의로 감추지 않는다. Draft의 실제 이미지 슬롯 수가 0이 되게 해 기존 미리보기·안전 안내 로직이 자연스럽게 숨겨지도록 한다.

- 2026-09-20: 새 생성 시도 직후 topic result와 draft validation을 함께 초기화했다. AI readiness 확인에서 새 오류가 발생하면 그 오류를 다시 표시하며, 기존 preview state는 유지한다.
- 2026-09-20: 공통 busy 상태로 `내용 지우기`와 `되돌리기`를 잠그고, 완료·실패 후 기존 availability 동기화로 다시 활성화되게 했다.
- 2026-09-20: 복구 액션 슬롯 아래에 `--ui-space-3` 여백을 추가하고 브라우저에서 실제 양수 간격을 확인했다.
- 2026-09-20: 브라우저 fixture에 AI 한도 오류 후 재시도 시나리오를 추가했다. 재시도 중 오류 숨김, clear 잠금, 성공 후 재활성화를 검증한다.

- 2026-09-20: AI Draft payload에서 공통 발행 설정을 유지하되 `imageMode`만 생성 입력의 명시값으로 복원해 `none`이 서버까지 전달되게 했다.
- 2026-09-20: 서버에서 이미지 모드를 정규화해 generation adapter에 같은 값을 전달하고, `none` 결과를 Draft로 반입할 때 이미지 블록과 이미지 자산을 방어적으로 제외했다.
