# Blog Beta 원고 생성 상태 개선 개발 기록

- 브랜치: `codex/fix/blog-next-generation-state`
- 시작일: 2026-09-20
- 기준 브랜치: `dev`
- 상태: 구현 및 사용자 UI 확인 완료

## 사용자 필요와 목표

Blog Beta의 `바로 생성`에서 AI 오류가 난 뒤 다시 원고 생성을 시도하면 이전 오류 안내가 생성 중에도 남는다. 생성 중에는 원본을 지우는 동작을 막고, `내용 지우기`와 다음 구분선 사이의 시각적 간격도 바로잡는다.

목표는 새 생성 시도의 상태 전환을 명확하게 만들고, 비동기 생성 중 입력을 실수로 제거하지 못하게 하며, 기존 액션 배치의 간격을 디자인 토큰에 맞추는 것이다.

## 범위

- 새 AI 원고 생성이 시작될 때 이전 생성 오류 안내 초기화
- AI 원고 생성 중 `내용 지우기`와 `되돌리기` 비활성화
- 복구 액션과 다음 액션 행의 구분선 사이 여백 추가
- 관련 정적 계약 및 브라우저 회귀 검사 보강

## 비범위

- 기존 Blog 화면 변경
- AI 요청·할당량 처리 정책 변경
- 입력 필드 전체 잠금 또는 생성 취소 기능 추가
- 원고 미리보기와 마지막 유효 결과 보존 정책 변경

## 설계와 영향 경계

1. `draft-execution`의 생성 시작 경계에서 topic 결과와 draft validation을 함께 초기화한다. 기존 preview state는 지우지 않는다.
2. `quick-flow-ui`의 공통 action availability 계산에 복구 액션을 포함해 생성·제출 중 동일한 busy 상태를 사용한다.
3. `blog-next-quick-flow` 스타일에서 홈 화면의 복구 액션 슬롯 아래에 토큰 기반 간격을 둔다.
4. 실패 후 재시도 중 상태를 브라우저 검사로 재현해 stale 오류, clear 잠금, 완료 후 복구를 검증한다.

## 결정과 트레이드오프

- 사용자가 새 생성 시도를 시작한 순간 이전 오류는 현재 상태가 아니므로 숨긴다.
- 실패가 발생해도 마지막 유효 preview는 유지한다. 오류 UI만 초기화해 기존 복구 정책을 보존한다.
- `내용 지우기`와 같은 슬롯의 `되돌리기`도 생성 중 잠근다. 두 동작 모두 생성 입력을 바꾸기 때문이다.
- 입력 필드 전체 잠금은 이번 사용자 요청보다 범위가 크므로 다루지 않는다.
