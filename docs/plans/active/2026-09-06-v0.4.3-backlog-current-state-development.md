# v0.4.3 Backlog Current-state Documentation Record

## Branch

- Branch: `codex/docs/v0.4.3-backlog-current-state`
- Base/parent branch: `dev`
- Start date: 2026-09-06
- Status: implementation complete; review and commit pending

## User Need

The repository documentation still describes several capabilities as active backlog work even though they were
implemented, verified, and released through v0.4.3. Completed development records also remain under
`docs/plans/active/`, making it difficult to distinguish current work from historical implementation context.

## Goal

Bring the maintained documentation in line with the v0.4.3 release state so the next development item can be
selected from a small, accurate backlog.

## Scope

- Move completed or superseded development records from `docs/plans/active/` to `docs/plans/archive/`.
- Finalize stale plan status text where it conflicts with completed implementation or release evidence.
- Rebuild the `docs/README.md` Active Work section from genuinely open plans.
- Record the decision not to treat Naver OAuth2 as a replacement for the browser session required for blog publishing.
- Rewrite `docs/backlog.md` around the remaining work after v0.4.3.

## Explicit Non-goals

- Product code, runtime behavior, database schema, deployment, or credential changes
- Starting any remaining backlog implementation
- Version changes, release preparation, commit, push, merge, or branch deletion
- Reconstructing completed plan history beyond the corrections required to identify its final state

## Proposed Approach

1. Compare active plans with archived sub-feature records, canonical documentation, release notes, and Git history.
2. Preserve genuinely open production operations and future product work as explicit backlog items.
3. Archive completed records without rewriting their historical decisions.
4. Keep long-lived current truth in architecture, feature, and decision documents rather than active plans.
5. Verify links, document indexes, backlog headings, and the final Git diff.

## Decisions and Tradeoffs

- Environment separation is treated as complete; new-PC bootstrap and Production migration-history reconciliation
  remain separate follow-up work.
- Runtime credential restructuring is complete through Development. Production legacy-row removal and credential
  rotation remain an explicit, approval-gated closeout.
- Dashboard enhancement, continuous publishing, Electron 44, first-run guidance, and the macOS packaged-config fix
  are completed capabilities rather than active backlog themes.
- Naver OAuth2 may support account identity, but it does not replace the browser-authenticated publishing session;
  no OAuth2 publishing migration remains in the backlog.
