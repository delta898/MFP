## User Need

The `cardnews` Sheet needs to become a reliable management ledger: incoming public articles must be registered once, users must be able to distinguish work and publishing states, and later stages must be able to attach local generation IDs and public channel links.

## Goal

Implement a focused Google Sheets gateway and ledger store that can list rows, upsert source candidates by stable identity, and safely update the limited state fields. No user interface, RSS scheduler, or generation/publishing wiring is included yet.

## Scope

- Introduce a Card News Sheets gateway using the established strict-preparation, read, append, and batch-cell-update contract.
- Derive stable `entry_key` values from feed item keys/GUIDs or normalized canonical URLs.
- Register source candidates idempotently with default workflow status `후보` and publishing status `미발행`.
- Read ledger rows and update only supported management fields, validating workflow and publishing states independently.
- Preserve extra user columns and never overwrite source identity fields during status updates.
- Add fixture-based tests for deduplication, upsert, state validation, and user-column preservation.

## Explicit Non-goals

- No direct UI filters or Card News view changes.
- No automatic RSS polling or backfilling of existing posts.
- No generation, image, ZIP, Buffer, or channel-result synchronization.
- No scheduling execution or remote spreadsheet mutation in automated verification.

## Design

- The store owns only the canonical ledger fields from stage 09. It reads arbitrary additional columns but does not write them.
- `entry_key` uses a SHA-256 hash of `feed_item` identity (RSS item key/GUID first) or normalized canonical URL. For later manual sources, a deterministic source fingerprint will be introduced with their registration flow.
- Upsert means append when an `entry_key` is absent; existing rows are returned unchanged. This avoids silently replacing a user-selected state, scheduled time, or attached generation.
- Supported mutable fields in this stage: workflow status, publishing status, generation ID, card count, channel summary, post-link summary, schedule time, processed time, and last error.
- State validation is structural only in this stage. Cross-field transition rules and side effects belong to later scheduling/publishing stages.
