# Site Hosting 삭제 확인 안전성
- 브랜치: `fix/site-hosting-delete-safety`, 기준: `main` (a1c46fb9), 시작: 2026-11-10
- 상태: 구현 중. 기존 사용자 변경과 다른 worktree를 분리해 보존한다.
- 목표: 삭제 계획의 archive 경로를 확인 화면에 표시하고 취소, 단계별 실패와 재계획을 모의 검증한다.
- 범위 외: 실제 원격 삭제·배포, 실패 복구 정책 변경, 병합.
- 설계: 기존 확인 UI와 삭제 계획 계약을 재사용하고, 모의 fixture로 외부 부작용 없이 순차 실행 및 실패를 검증한다.
- 구현: 서버 계획의 archive 단계 label을 기존 텍스트 확인 대화상자에 표시하고 누락 시 삭제를 막는다. 단계 실행 정책은 변경하지 않았다.
- 검증: 삭제 집중 테스트 6개, UI 계약 10개, 사이트 route 10개 통과. 도메인·Worker·archive 실패를 부작용 전 모의하고 이후 단계 중단, 기존 계획 소진, 남은 상태에 따른 재계획을 확인했다.
- UI smoke: Homebrew Node 26과 원본 node_modules를 참조한 headless fixture 실행 통과(552 요청). 첫 실행은 취소 후 추가 계획 요청을 전체 요청 기대값에 반영하지 않아 실패했고 기대값 수정 후 통과했다. 확인 함수는 모의되므로 대화상자 렌더링 자체는 별도 확인이 필요하다.
- 한계: 원격 측이 작업을 수행한 뒤 오류를 반환하거나 상태 확인이 실패하는 부분 성공, 실제 외부 서비스·삭제, 전체 단위 suite, 수동 시각 검증은 미검증. 독립 리뷰·QA 대기, 미커밋·미병합.
- 독립 QA 후속: archive 단계 누락, 빈 문자열, 공백 문자열에 대해 브라우저 fixture에서 오류 표시와 확인 호출·삭제 요청 차단을 검사한다. 관련 서비스·라우트·UI 계약 48개 및 변경된 headless smoke (551 fixture 요청, 외부 글꼴 요청 2건 차단) 통과.
- QA의 실제 대화상자 포함 메모리 변형 스모크는 이전에 계정·소셜 탭 위치 비교 176 != 87로 실패했으나 동일 변형을 단독 재실행하여 전체 통과(563 요청). 실패 원인은 확정하지 못했다. 기존 QA 당시 두 브라우저 스모크가 겹쳐 실행됐으나 인과관계는 미확인이다. 실제 대화상자 확인은 제품 파일이 아닌 메모리 변형으로 실행했다.
- 부작용 발생 후 응답 실패·상태 조회 실패 복구는 여전히 미검증이며 실제 삭제·배포는 수행하지 않았다. 추가 테스트 변경은 독립 재검토·QA 필요, 병합하지 않음.
