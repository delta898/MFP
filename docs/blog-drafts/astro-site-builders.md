# Astro Site Builder란 무엇일까? 내 사이트를 만들고, 편집하고, 코드로 가져오는 도구 4가지

Astro로 사이트를 만들기로 마음먹으면 곧 이런 질문을 만나게 됩니다.

> “디자인은 내 취향대로 만들고 싶은데, Astro 코드를 처음부터 전부 작성해야 할까?”

Astro는 페이지와 컴포넌트를 코드로 조립하는 웹 프레임워크입니다. 개발자에게는 구조와 성능을 세밀하게 제어할 수 있다는 장점이 있지만, 코드가 익숙하지 않은 사람에게는 템플릿의 문구나 색상, 섹션 순서를 조금 바꾸는 일도 쉽지 않을 수 있습니다.

이 간격을 줄여주는 도구가 **Astro Site Builder**입니다. 다만 모든 시각 편집 도구가 같은 것은 아닙니다. 어떤 도구는 기존 Astro 프로젝트 파일을 직접 고치고, 어떤 도구는 온라인에서 사이트를 만들고 관리하며, 어떤 도구는 제공된 테마를 편집한 뒤 Astro 프로젝트로 내보냅니다.

이 글에서는 사이트의 게시물만 관리하는 CMS가 아니라, **사이트의 페이지와 디자인을 만들고 편집하는 Astro Site Builder** 네 가지를 살펴봅니다.

## Astro Site Builder와 CMS는 어떻게 다를까?

CMS(Content Management System)는 보통 글, 이미지, 상품 정보처럼 사이트에 들어갈 콘텐츠를 작성하고 관리하는 도구입니다. Astro 사이트는 그 콘텐츠를 읽어 화면에 보여줍니다. 예를 들어 블로그 글을 Markdown으로 작성하고, Astro가 글 목록과 상세 페이지를 만들어주는 구조가 여기에 해당합니다.

Site Builder는 사이트의 **모양과 구조**를 만드는 데 더 초점을 둡니다.

- 페이지와 섹션을 구성하고 순서를 바꿉니다.
- 글자, 이미지, 색상, 간격, 레이아웃을 편집합니다.
- 템플릿을 출발점으로 삼거나 새 사이트를 만듭니다.
- 도구에 따라 Astro 소스 코드를 직접 만들거나 내보냅니다.

실제 제품은 CMS와 Site Builder 기능을 함께 제공하기도 합니다. 이 글에서는 게시물 입력 기능이 아니라, 편집 결과가 **Astro 사이트 프로젝트로 이어지는지**를 중심으로 비교합니다.

## 비교할 때 확인할 기준

Astro Site Builder를 고를 때는 화면을 얼마나 쉽게 꾸밀 수 있는지만 보면 부족합니다. 다음 질문을 함께 확인해야 합니다.

1. 기존 Astro 프로젝트를 열어 수정할 수 있나요?
2. 새 사이트나 새 페이지를 처음부터 만들 수 있나요?
3. 결과물이 실제 `.astro` 파일을 포함한 프로젝트인가요?
4. 완성한 프로젝트를 다운로드하거나 내 저장소로 가져올 수 있나요?
5. 빌더를 그만 사용해도 사이트를 계속 빌드하고 배포할 수 있나요?

특히 “Astro를 지원한다”는 문구가 곧 “어떤 Astro 프로젝트든 열어 편집할 수 있다”는 뜻은 아닙니다. 새 Astro 코드를 생성하는 것, 특정 테마를 편집하는 것, 임의의 기존 Astro 프로젝트를 불러오는 것은 서로 다른 기능입니다.

## 1. Stacki: 이미 있는 Astro 프로젝트를 데스크톱에서 시각 편집

[Stacki](https://stacki.build/)는 컴퓨터에 있는 Astro 프로젝트를 열어 페이지를 시각적으로 편집하는 데스크톱 앱입니다. 프로젝트의 개발 서버를 실행하고 미리보기를 보여주면서 페이지, 레이아웃, 컴포넌트, 스타일, 콘텐츠 컬렉션과 이미지 자산을 다룹니다.

Stacki의 특징은 별도의 프로젝트 형식이나 온라인 계정에 사이트를 저장하지 않는다는 점입니다. 편집 내용은 원래 프로젝트 파일에 기록되므로, 그 파일을 Git으로 관리하거나 Astro로 빌드할 수 있습니다. 지원하는 시각 모델이 처리하지 못하는 마크업은 코드 편집 화면으로 열립니다.

**잘 맞는 경우**

- 이미 Astro 템플릿이나 프로젝트가 있다.
- 로컬 파일과 코드 저장소를 직접 관리할 수 있다.
- 개발자가 아니더라도 스타일과 페이지 구조를 시각적으로 조정해보고 싶다.

**확인할 점**

- 웹에서 가입해 사이트를 만들고 바로 호스팅하는 SaaS가 아닙니다.
- Astro 프로젝트를 처음부터 AI로 완성해주는 서비스와는 성격이 다릅니다.
- 시각 편집이 지원되지 않는 코드 부분은 개발 지식이 필요할 수 있습니다.

Stacki는 **기존 템플릿을 내 컴퓨터에서 고쳐 쓰는 도구**로 이해하면 가장 정확합니다.

## 2. Sitereal: 새 프로젝트와 기존 Astro 프로젝트를 다루는 로컬 시각 빌더

[Sitereal](https://sitereal.app/)은 Astro 프로젝트를 캔버스에서 구성하고, 결과를 일반 Astro·CSS·JavaScript 파일로 저장한다고 안내합니다. 새 프로젝트를 시작하거나 기존 Astro 프로젝트 폴더를 열어 편집하는 흐름을 제공합니다. 페이지 구성, 반응형 미리보기, 스타일 패널, 디자인 시스템, 콘텐츠 유형 등을 한 앱에서 다루는 것이 목표입니다.

사이트가 빌더의 별도 런타임에 의존하지 않고 일반 Astro 코드로 남는다는 점이 핵심입니다. 앱을 제거해도 Astro 프로젝트 자체의 빌드와 배포는 계속할 수 있다고 제품 문서는 설명합니다. AI 개발 도구와 연결할 수 있도록 MCP 기능도 제공합니다.

**잘 맞는 경우**

- 새 Astro 프로젝트를 시각적으로 만들고 싶다.
- 기존 Astro 프로젝트를 열어 이어서 편집하고 싶다.
- 캔버스 편집과 직접 코드 편집을 함께 사용하고 싶다.

**확인할 점**

- 비교적 새로운 도구이므로 실제 사용 중인 Astro 버전, 템플릿 구조, 컴포넌트가 잘 호환되는지 작은 프로젝트로 먼저 확인하는 편이 좋습니다.
- “기존 프로젝트를 연다”와 “모든 기존 코드를 완벽히 시각 편집한다”는 같은 말이 아닙니다. 프로젝트별 지원 범위와 편집 가능한 구조를 직접 살펴야 합니다.
- 데스크톱 앱 중심이며 사이트 호스팅 서비스는 아닙니다. 편집 후 빌드와 배포는 별도 환경에서 진행합니다.

Stacki와 비교하면 Sitereal은 **새 프로젝트 구성까지 포함하는 시각 빌더**를 지향하고, Stacki는 기존 Astro 파일을 안전하게 편집하는 데 초점을 둡니다.

## 3. Pagesmith: AI로 만들고, 온라인에서 편집하고, 게시하는 Astro 서비스

[Pagesmith](https://pagesmith.ai/astro-website-builder/)는 사이트 설명이나 기존 사이트 URL을 바탕으로 Astro 사이트를 생성하고, 온라인 편집기에서 수정·게시하는 서비스입니다. 제품 설명에 따르면 페이지, 레이아웃, 컴포넌트, 콘텐츠 컬렉션과 스타일을 포함한 표준 Astro 프로젝트를 생성합니다. 자체 호스팅을 제공하며 사용자 도메인 연결도 지원합니다.

사이트 생성과 편집, 게시를 한 서비스에서 처리할 수 있다는 점은 편리합니다. 반면 사용자가 Astro 소스 코드를 내려받아 외부 환경에서 계속 사용하는 기능은 요금제에 따라 달라집니다. 2026년 10월 가격 안내 기준 무료 플랜에는 Pagesmith 하위 도메인 게시가 포함되고, Astro 소스 다운로드와 사용자 도메인 기능은 유료 플랜에 포함되어 있습니다. 요금과 기능은 바뀔 수 있으므로 가입 전에 [최신 요금 페이지](https://pagesmith.ai/pricing/)를 확인해야 합니다.

**잘 맞는 경우**

- 설명이나 참고 사이트로 빠르게 초안을 만들고 싶다.
- 온라인에서 시각 편집과 게시를 한 번에 하고 싶다.
- 사이트 운영 편의성을 우선하고, 필요하면 유료 플랜으로 Astro 코드를 가져오고 싶다.

**확인할 점**

- 무료로 사이트를 만들고 게시할 수 있어도 Astro 소스 다운로드는 유료일 수 있습니다.
- 자체 호스팅, 도메인, 폼, 데이터베이스 같은 관리 기능은 서비스 요금과 정책에 영향을 받습니다.
- 코드를 내보낸 뒤에도 외부 서비스 기능을 계속 쓰려면 별도 설정이나 대체 서비스가 필요할 수 있습니다.

Pagesmith는 **온라인 제작·편집·호스팅을 한 번에 원하는 사용자**에게 가깝고, 프로젝트 파일을 직접 다루는 로컬 편집기와는 운영 방식이 다릅니다.

## 4. AeroLaunch Visual Builder: 테마를 골라 수정하고 Astro 프로젝트로 내보내기

[AeroLaunch](https://www.aerolaunch.app/)는 제공하는 Astro 테마를 고른 뒤 브라우저에서 문구, 이미지, 색상, 섹션과 페이지를 조정하고 Astro 프로젝트로 내보내는 방식을 제공합니다. 내보낸 프로젝트를 원하는 호스팅에 배포할 수 있다고 안내합니다.

이미 준비된 테마에서 출발하기 때문에 빈 화면에서 사이트 전체를 설계하는 부담을 줄일 수 있습니다. 일부 편집 기능은 AeroLaunch 테마에 맞춰 제공됩니다. 사용자가 가진 다른 Astro 테마를 편집기에 연결하는 서비스도 있지만, 업체가 해당 테마를 편집 가능하도록 설정하는 유료 작업으로 소개되어 있습니다.

**잘 맞는 경우**

- 제공된 테마 중 하나를 기반으로 사이트를 빠르게 꾸미고 싶다.
- 디자인 편집은 온라인에서 하고, 결과 코드는 직접 보유하고 싶다.
- 완전히 자유로운 페이지 구성보다 정돈된 테마 기반 편집이 편하다.

**확인할 점**

- 기본 경험은 AeroLaunch 테마 중심입니다. 임의의 외부 Astro 프로젝트를 자유롭게 가져와 편집하는 범위와는 차이가 있습니다.
- 사용자가 보유한 테마를 편집 가능하게 만드는 작업은 추가 비용이 들 수 있습니다.
- 편집 가능한 테마 수와 가격은 바뀔 수 있으니 구매 전에 조건을 확인해야 합니다.

AeroLaunch는 **테마 기반 편집과 코드 소유권을 함께 원하는 사용자**에게 적합한 모델입니다.

## 네 도구를 한눈에 비교하기

| 도구 | 새 사이트 만들기 | 기존 Astro 프로젝트 편집 | Astro 프로젝트 소유·내보내기 | 운영 방식 |
|---|---|---|---|---|
| Stacki | 제한적 시작 기능 | 가능 | 로컬 프로젝트 파일을 직접 수정 | 데스크톱 앱 |
| Sitereal | 가능 | 가능하다고 안내; 프로젝트별 호환 확인 필요 | 일반 Astro 파일을 로컬에 기록 | 데스크톱/로컬 앱 |
| Pagesmith | 설명 또는 URL에서 생성 | 서비스 내 사이트를 편집 | 유료 플랜에서 소스 내보내기 | 온라인 제작·호스팅 SaaS |
| AeroLaunch | 제공 테마에서 시작 | 자사 테마 중심; 외부 테마는 별도 설정 서비스 | Astro 프로젝트 내보내기 제공 | 브라우저 기반 테마 빌더 |

각 도구가 말하는 “내보내기”의 의미도 살펴야 합니다. Stacki와 Sitereal은 로컬 프로젝트 파일을 직접 편집하는 방식이라 별도의 export 버튼이 핵심이 아닙니다. Pagesmith와 AeroLaunch는 온라인 편집 결과를 Astro 프로젝트로 가져오는 데 export 기능이 중요합니다.

## 어떤 도구가 내 상황에 맞을까?

### 우리 템플릿을 고쳐 나만의 사이트로 키우고 싶다면

현재 템플릿을 직접 열어 편집하는 Stacki나 Sitereal을 먼저 살펴볼 수 있습니다. 파일을 내가 보유하고, 글 발행과 배포를 별도로 운영할 수 있는 구조입니다. 온라인에서 관리와 게시까지 맡기고 싶다면 Pagesmith 방식도 비교 대상입니다.

### 새 사이트를 만들고 Astro 프로젝트를 가져오고 싶다면

Sitereal은 새 Astro 프로젝트 생성과 기존 프로젝트 편집을 함께 지향합니다. Pagesmith는 온라인에서 사이트를 생성·편집한 뒤 유료 플랜에서 프로젝트를 내보내는 흐름입니다. AeroLaunch는 제공 테마를 출발점으로 삼기 좋습니다. “Astro 코드 출력”만 보지 말고, 다운로드한 프로젝트가 로컬에서 빌드되는지 반드시 확인하세요.

### 코드보다 빠른 출발과 호스팅이 중요하다면

Pagesmith처럼 제작, 게시, 도메인 연결을 묶어 제공하는 서비스가 편리할 수 있습니다. 대신 소스 코드 접근 여부, export 조건, 외부 서비스 의존성을 미리 확인해야 합니다.

## BlogGenius 같은 서비스와 연결할 때 필요한 것

사용자가 만든 Astro 사이트를 다른 서비스에서 편집한 뒤 BlogGenius로 가져오려면, 단순히 ZIP 파일을 받는 것으로 끝나지 않습니다. 가져온 프로젝트가 다음 단계에 필요한 조건을 만족해야 합니다.

- BlogGenius가 기대하는 Astro 버전과 빌드 방식으로 실행되는가?
- 이미지와 폰트 등 자산 경로가 프로젝트 안에서 올바르게 연결되어 있는가?
- 사용자 도메인이나 환경별 값을 안전하게 설정할 수 있는가?
- 글 발행 시 필요한 콘텐츠 위치와 필드 규칙을 알 수 있는가?
- 템플릿 메타 정보와 빌드 설정을 추가해도 원래 디자인과 기능이 유지되는가?
- 빌드가 실패했을 때 원본 프로젝트와 사용자의 편집 결과를 보존할 수 있는가?

따라서 장기적으로는 어떤 편집 도구를 고르든, **Astro 프로젝트를 검사하고 BlogGenius의 발행·배포 규약을 추가하는 패키징 단계**가 중요합니다. 사용자는 자기 취향에 맞게 사이트를 편집하고, BlogGenius는 프로젝트가 발행과 호스팅에 적합한지 확인하는 구조가 될 수 있습니다.

## 마무리: 편집기보다 중요한 것은 결과물의 소유와 이동성

Astro Site Builder는 단순히 드래그 앤 드롭 화면을 제공하는 도구가 아닙니다. 어떤 프로젝트를 편집할 수 있는지, 결과가 실제 Astro 파일인지, 사이트를 다른 곳으로 옮겨도 계속 운영할 수 있는지까지 살펴야 합니다.

- **기존 로컬 Astro 프로젝트 편집**: Stacki
- **새 프로젝트와 기존 프로젝트의 로컬 시각 편집**: Sitereal
- **온라인 AI 제작·편집·호스팅**: Pagesmith
- **테마 선택 후 편집·Astro 내보내기**: AeroLaunch

가장 좋은 도구는 누구에게나 하나로 정해져 있지 않습니다. 다만 사용자가 사이트를 자기 것으로 발전시키기를 원한다면, **편집 결과를 표준 Astro 프로젝트로 보유하고 필요할 때 다른 도구와 호스팅으로 옮길 수 있는지**를 우선 기준으로 삼는 것이 좋습니다.
