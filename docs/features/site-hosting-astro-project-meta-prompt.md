# BlogGenius Astro Project ZIP 메타 프롬프트 (PoC)

이 문서는 사용자가 Codex, Claude 등 AI 도구에 붙여 넣어 Astro 프로젝트 ZIP을 만들 때 쓰는 프롬프트입니다. 현재 구현은 선언된 공통 설정을 ZIP 분석·설정 화면·미리보기·사이트 생성·설정 저장에 연결합니다. 선언이 없거나 기본 파일/연동 모듈을 확인하지 못하면 해당 설정 항목은 읽기 전용으로 처리합니다.

## 사용 방법

아래 프롬프트를 복사한 다음 가장 위의 `사용자가 원하는 사이트` 항목을 자신의 상황에 맞게 고쳐 AI에게 전달합니다. 각 항목의 예시를 지우고 바꾸거나, 예시 뒤에 설명을 덧붙이면 됩니다. 해당 없는 항목은 `없음`, 정해지지 않은 항목은 `AI가 제안`이라고 적어도 됩니다. `추가 요청`에는 나머지 항목에 없는 요구를 적습니다. 대괄호로 표시한 안내는 작성용 주석이며, AI는 사이트 요구사항으로 취급하지 말고 무시하도록 프롬프트에 명시되어 있습니다. AI가 ZIP까지 만들 수 없다면 프로젝트 파일을 만들고 루트 폴더를 ZIP으로 압축해 달라고 요청합니다.

## 복사할 프롬프트

````text
## 사용자가 원하는 사이트

<!-- 사용자 안내: 아래 예시를 지우거나 수정해 원하는 사이트를 설명하세요. 이 HTML 주석은 작성용 안내이므로 사이트 요구사항으로 취급하지 마세요. -->
- 사이트 종류와 목적: 개인 기록을 차분하게 모아 두는 블로그
- 주로 방문할 사람: 글쓴이와 글을 읽으러 온 사람
- 사이트 이름 또는 이름의 느낌: 담백한 기록처럼 짧고 편안한 이름
- 분위기와 디자인: 따뜻하고 단정하게, 종이 노트처럼 여백이 넉넉한 느낌
- 언어: 한국어
- 필요한 페이지와 메뉴: 홈, 뉴스, 소개
- 홈 화면에서 가장 먼저 보여줄 내용: 사이트를 소개하는 문장과 최근 글 몇 개
- 기록/콘텐츠의 종류: 일상에서 배운 점과 읽은 내용을 정리한 글
- 원하는 기능: 글 목록과 글 상세 보기, 모바일에서도 편하게 읽기
- 참고할 색상·사이트·이미지: 크림색 배경과 짙은 갈색 글자, 참고 링크가 있으면 여기에 기입
- 추가 요청: 위 항목에 없는 요구사항을 적습니다. 없으면 `없음`이라고 적습니다.

## 제작 지시

너는 Astro 기반 정적 웹사이트를 설계하고 구현하는 웹 개발자다. 위의 `사용자가 원하는 사이트` 항목에 적힌 내용만 실제 사이트 요구사항으로 해석하라. 그 아래의 `기본 제작 원칙`, 설정 규격, 구현 방법은 프로젝트 제작 지시다. HTML 주석(`<!-- ... -->`) 안의 문장은 사용자를 위한 작성 안내이므로 사이트 콘텐츠나 기능 요구사항으로 해석하지 말고 무시하라. 아래 요구사항을 충족하는, 바로 빌드할 수 있는 완성된 Astro 프로젝트를 만들어라. 코드 예시나 설명만 답하지 말고 프로젝트 파일을 실제로 만들고 마지막에는 ZIP 파일로 제공하라.

## 기본 제작 원칙

- Astro의 정적 사이트 출력에 맞춰 구현한다. 서버 런타임이나 외부 데이터베이스를 요구하지 않는다.
- 사용자의 설명을 바탕으로 적절한 이름, 설명, 메뉴, 페이지를 구성한다. 필요한 정보가 없으면 질문으로 멈추지 말고 과장 없는 합리적인 기본값을 사용한다.
- 완성도 있는 시각 디자인과 반응형 레이아웃을 만든다. 단순하더라도 여백, 글자 크기, 색상, 콘텐츠 폭의 균형을 갖춘다.
- 시맨틱 HTML, 키보드 탐색, 충분한 색상 대비, 이미지 대체 텍스트를 적용한다.
- 사용자가 제공하지 않은 실존 인물 정보, 회사 연혁, 고객 후기, 통계, 수상 경력, 연락처를 사실처럼 만들어내지 않는다. 예시가 필요하면 예시임을 분명히 표시한다.
- 필요한 이미지와 아이콘은 프로젝트 안에 포함한다. 외부 URL이 끊겨도 핵심 화면이 무너지지 않게 한다.
- 실제 사용자 사이트의 설명, 메뉴, 브랜딩을 코드 여러 곳에 중복해서 하드코딩하지 않는다. 아래 공통 설정 파일을 단일 원천으로 사용한다.

## BlogGenius 공통 설정 파일

프로젝트 루트에 `site-data/site.json`을 만든다. 기본 파일은 유효한 JSON이어야 하며 다음 구조를 따른다.

```json
{
  "displayName": "사이트 이름",
  "seoDescription": "검색 및 공유에 사용할 사이트 설명",
  "searchEngineIndexing": true,
  "navigation": [
    { "id": "home", "label": "홈", "path": "/" },
    { "id": "posts", "label": "기록", "path": "/blog/" },
    { "id": "about", "label": "소개", "path": "/about/" }
  ],
  "logo": "",
  "shareImage": "",
  "favicon": "",
  "project": {
    "tagline": "사이트의 분위기를 설명하는 짧은 문장",
    "introduction": "홈 화면에 표시할 소개"
  }
}
```

### 필드 소유권

- BlogGenius가 설정 화면에서 관리할 공통 필드는 `displayName`, `seoDescription`, `searchEngineIndexing`, `navigation`, `logo`, `shareImage`, `favicon`이다.
- `project`와 그 안의 필드는 프로젝트가 소유한다. 사이트의 콘텐츠나 디자인에 필요한 값을 여기에 추가할 수 있다.
- BlogGenius가 공통 필드를 갱신해도 `project`를 포함한 미지정 필드와 콘텐츠를 삭제하거나 덮어쓰지 않는 것을 전제로 한다.
- `navigation`의 항목은 `id`, `label`, `path`를 사용한다. `id`는 안정적인 식별자로 유지하고 화면에 표시할 이름이나 주소가 바뀌어도 임의로 바꾸지 않는다.
- `path`는 `/`로 시작하고 끝나는 사이트 내부 경로로 작성한다. 외부 링크는 메뉴 후보에 넣지 않는다.
- `logo`, `shareImage`, `favicon`은 프로젝트 루트 기준 공개 경로 또는 빈 문자열이다. 기본값은 빈 문자열로 둔다. 프로젝트는 로고가 비어 있을 때 사이트 이름을 텍스트로 표시한다.
- 블로그 글 목록을 메뉴로 제공할 때는 사용자가 정한 메뉴 이름(예: `뉴스`, `기록`, `소식`)과 관계없이 해당 항목의 안정적인 ID를 반드시 `posts`로 지정한다. 기본 경로는 `/blog/`로 둔다. `posts` ID가 BlogGenius의 글 목록 연결 기준이며, 메뉴 이름만 `뉴스` 또는 `기록`으로 적는다고 자동으로 글 목록 메뉴가 되지는 않는다. 글 상세 경로는 선택된 글 목록 경로 아래에 생성한다. 예를 들어 글 목록 경로가 `/blog/`이면 상세 경로는 `/blog/{slug}/`이다.

## 설정을 Astro 화면에 연결하는 방법

- Astro 코드에서 `site-data/site.json`을 읽는 공통 모듈을 하나 만들고 레이아웃과 페이지가 그 모듈을 사용하게 한다.
- 사이트 이름, 설명, 검색엔진 색인 허용 여부는 각 페이지의 `<title>`, description 및 robots 메타 정보에 일관되게 반영한다.
- 메뉴는 `navigation` 배열을 순서대로 렌더링한다. 메뉴의 표시 이름은 `label`, 링크는 `path`를 사용한다. 메뉴를 추가하거나 이름·경로·순서를 바꾸어도 코드의 별도 메뉴 상수와 불일치하지 않게 한다.
- `/`는 홈 화면으로 유지한다. `/`가 아닌 각 내부 메뉴 경로에 대응하는 페이지를 정적 빌드로 생성한다. 설정에서 경로가 바뀌면 다음 빌드에서 페이지 경로와 메뉴 링크가 함께 바뀌어야 한다.
- `id`가 `posts`인 메뉴는 글 목록 페이지를 표시한다. 메뉴 이름은 사용자가 원하는 이름으로 정하되, 글 목록 연결 기능을 위해 `id: "posts"`를 유지한다. 글 상세 경로도 현재 해당 메뉴의 `path`를 기준으로 생성한다.
- 로고는 `logo` 경로를 사용한다. 값이 비어 있으면 `displayName` 텍스트를 사용한다. 이미지에는 사이트 이름에 맞는 대체 텍스트를 제공한다.
- `favicon`과 `shareImage`는 값이 있을 때 해당 공개 경로를 사용하고, 비어 있으면 프로젝트에 포함한 기본 아이콘/이미지를 사용할 수 있다. 해당 이미지가 BlogGenius 설정에서 교체된 경우 새 경로가 적용되도록 값에 직접 연결한다.
- `site-data/site.json`이 없거나 선택 필드가 비어 있어도 개발 서버와 빌드가 실패하지 않도록 안전한 기본값을 둔다. JSON이 존재하면 위 필드 구조를 따른다.
- 빌드 시 설정 파일을 수정하거나 생성 결과를 덮어쓰는 별도 스크립트를 두지 않는다.

## 프로젝트 정보 및 기능별 연동 선언

프로젝트 루트에 `bloggenius/project.json`을 만든다. 이 파일은 프로젝트가 어떤 BlogGenius 설정을 실제 Astro 화면에서 읽고 반영하는지 설명한다. BlogGenius가 지원하지 않거나 프로젝트가 구현하지 않은 기능을 지원한다고 표시하지 않는다.

```json
{
  "format": "bloggenius-astro-project",
  "schema_version": 1,
  "settings_support": {
    "site_identity": true,
    "navigation": true,
    "logo": true,
    "favicon": true,
    "share_image": true
  }
}
```

- 각 기능의 `true`는 해당 설정 파일의 값이 바뀐 뒤 새로 빌드했을 때 실제 결과물에 반영된다는 뜻이다.
- `site_identity`는 사이트 이름, 설명, 검색엔진 노출 설정을 반영한다.
- `navigation`은 메뉴 이름, 순서, 경로를 반영하고 그 경로의 페이지도 생성한다.
- `logo`, `favicon`, `share_image`는 해당 이미지 경로를 화면 또는 HTML 메타 정보에 반영한다.
- 완전히 구현하고 직접 확인한 기능만 `true`로 둔다. 구현하지 못한 항목은 `false`로 쓰거나 항목을 생략한다.
- 이 선언은 BlogGenius 글 발행 연동을 의미하지 않는다. 글 발행 지원을 선언하거나 BlogGenius 전용 콘텐츠 모델을 임의로 만들지 않는다.

`bloggenius/project.json`은 ZIP 안의 프로젝트 설명 파일이다. BlogGenius가 사이트를 생성할 때 별도로 만드는 `.bloggenius/site.json`과 혼동하지 않는다. `.bloggenius/site.json`은 AI가 만들거나 ZIP에 넣지 않는다. ZIP 설정에서 바꾼 메뉴·이미지는 `site-data/site.json`과 프로젝트 루트의 `public/`에 반영되며, 미리보기 또는 빌드 때 Astro 코드가 이를 읽는다.

## 예시 콘텐츠와 경로

- 사용자의 요구에 맞는 홈과 내부 페이지를 만든다. 블로그가 요구되면 글 목록과 글 상세 화면을 포함한다.
- 블로그 글은 프로젝트 안의 로컬 콘텐츠 파일에서 불러온다. 글 상세 URL은 현재 `posts` 메뉴의 경로를 기준으로 조립한다.
- 글 목록이 비어 있어도 자연스러운 빈 상태를 보여준다. 임의의 게시물을 실제 사용자 글인 것처럼 섞지 않는다.
- 모든 내부 링크는 실제로 생성되는 경로를 가리킨다. 페이지를 만들지 못한 메뉴를 만들어 두지 않는다.
- 사용자가 메뉴 경로를 수정한 뒤에도 모든 메뉴 링크와 정적 페이지 경로가 서로 맞도록 구현한다.

## 빌드 및 ZIP 전달

- 루트 `package.json`에 Astro 의존성과 `build` 스크립트를 선언한다.
- `package-lock.json`을 포함하고 `package.json`과 일치시킨다.
- `npm ci` 후 `npm run build`가 성공하는지 확인한다. 오류가 있으면 수정 후 다시 빌드한다.
- ZIP 최상위에 프로젝트 루트 파일이 바로 오도록 압축한다. ZIP 안에 프로젝트 폴더 한 겹을 추가하지 않는다.
- ZIP에는 `package.json`, `package-lock.json`, Astro 설정, `src/`, 필요한 `public/` 자산, `site-data/site.json`, `bloggenius/project.json`을 포함한다.
- `node_modules/`, `.astro/`, `dist/`, `.git/`, OS 임시 파일은 ZIP에 넣지 않는다.
- 마지막 응답에는 ZIP 파일 링크와 함께 구현한 메뉴 경로, 공통 설정 연동 항목, 빌드 성공 여부를 간단히 정리한다. 확인하지 않은 기능을 성공했다고 말하지 않는다.
````

## 구현된 BlogGenius 연동 동작

- ZIP importer는 `bloggenius/project.json`과 `site-data/site.json`을 확인하고, `src/lib/site.ts`에서 설정 파일을 읽는 흔적을 확인합니다. 기능별 선언과 필수 설정 필드가 맞는 항목만 편집할 수 있게 합니다.
- 지원 항목은 사이트 이름·설명·검색 노출, 메뉴, 로고, Favicon, 사이트 대표 이미지입니다. 사용자 설정은 Astro 프로젝트의 `site-data/site.json`으로 반영하며 기존 `project` 데이터와 알 수 없는 필드는 보존합니다.
- 선택한 이미지는 Astro 프로젝트 루트의 `public/`에 저장하고 설정에는 공개 URL 경로를 기록합니다. 메뉴 ID를 유지해 `posts` 메뉴와 같이 프로젝트 내부에서 사용하는 식별자가 계속 동작하게 합니다.
- ZIP 미리보기는 설정을 임시 프로젝트 복사본에 먼저 반영한 다음 빌드합니다. 사이트 생성과 저장된 사이트의 설정 변경도 같은 적용 로직을 사용합니다.
- 선언이 없거나 형식/필수 파일이 맞지 않는 항목은 읽기 전용으로 처리합니다. 이 검사는 구조와 연동 모듈의 존재를 확인하는 수준이므로, 프로젝트 코드가 실제로 모든 선언을 완전히 구현했는지 정적으로 증명하지는 않습니다. 생성된 ZIP의 빌드와 화면은 실제 미리보기로 확인해야 합니다.
