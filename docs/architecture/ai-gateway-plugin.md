# AI Gateway Core Plugin

## Purpose and ownership

`packages/plugins/core/ai-gateway/` is a provider-neutral, in-process Core Plugin for the authoritative AI model catalog and text/image generation. Supabase is the only source of catalogued provider/model availability and metadata. The Gateway owns catalog refresh, TTL, in-flight coalescing, cache hydration/persistence coordination, last-known-good fallback, supported provider endpoints, authentication policy, and network transport. The Host supplies narrow Supabase RPC/local-cache ports and a credential/profile resolver.

BlogGenius product Applications do not call the Plugin Host or depend on Gateway operation IDs. They use the shared `src/services/ai/generation.js` contract and its provider-neutral `generateText` / `generateImage` methods. Settings requests model choices through the Gateway's `models.list` operation. The Host hydrates the same validated last-known-good snapshot for synchronous startup consumers. `src/adapters/plugins/ai-gateway.js` translates service requests to Host operations. `provider-transport.js` and `provider-endpoints.js` are shipped inside this Plugin package; the Host only resolves configured credentials and direct-model profiles.

The Gateway is not a REST service. Other Hosts can use the package by providing a credential/profile resolver and catalog port to `createPlugin`; they do not need to implement provider URLs or HTTP transport. Tests may replace the internal transport through a constructor override.

## Public operation contract

The package manifest declares four operations with Host-validated JSON Schema 2020-12 contracts:

- `models.list`: `{ forceRefresh? }` → normalized provider/model catalog and refresh status.
- `models.verify`: `{ kind, model: { provider, modelId, transport? }, profileRef? }` → metadata or provider-account connectivity result without generating content. `profileRef` is an opaque, short-lived Host reference, never a credential or endpoint.
- `text.generate`: `{ model: { provider, modelId }, messages, options? }` → normalized text, model identity, optional usage, and finish reason.
- `image.generate`: `{ model: { provider, modelId }, input: { prompt }, options? }` → one or more `{ mimeType, dataBase64 }` images and model identity.

The operation input does not contain an API key, endpoint, authorization header, or BlogGenius configuration. Verification accepts only an opaque profile reference, which the Host resolves in memory for that single call and releases afterward. Images are inline base64 with a 10 MiB decoded per-image limit. The Host validates output size and shape before returning results to the Application. A future Host-managed asset-reference contract can replace inline media when a concrete shared asset lifecycle exists.

`describeSupport()` reports implemented `kind + provider + transport` protocols. It contains no model ID allowlist. The Gateway catalog query filters Supabase entries through these protocol routes, and generation Applications consume that catalog snapshot without maintaining a second route/model intersection. Direct custom models remain a distinct Host-configured profile path. Option lists such as image ratios are documented hints, not runtime capability verdicts; only the Provider's response decides whether a model accepts an option. Catalog capability metadata may suppress an explicitly unsupported text option while unknown support remains best effort.

## Supported routes in this release

- Text: Google Gemini generateContent, OpenAI chat completions, Anthropic's OpenAI-compatible endpoint, KIE Responses/chat routes, and user-configured OpenAI-compatible direct endpoints. Supabase catalog entries can select an existing route without a model-ID allowlist; direct routes accept only model IDs supplied from Host-owned configured profiles.
- The Gateway maps shared generation options to each transport's request shape and forwards them for Provider validation. Applications may use documented Catalog/Gateway metadata as a hint when choosing optional modes, but an explicitly requested model option is not rejected solely by that metadata.
- Image: Google Gemini image generation, OpenAI image generation, KIE async image jobs, and user-configured direct OpenAI-compatible endpoints. Any Supabase model on an implemented route can be selected; request-shape-specific KIE models continue to use explicit Gateway mappings, with a generic shared task shape for newly catalogued IDs. Direct endpoints advertise no known ratio/size list by default: the Gateway makes a best-effort request using the requested ratio mapped to `size` dimensions and returns a normalized provider rejection if the endpoint does not accept it. Direct image results request inline base64.
- Image count defaults to one. OpenAI and direct routes allow up to four outputs; Google and KIE routes allow one under the current Gateway operation contract. The count ceiling and 10 MiB output bound are Gateway-owned execution limits, not claims about Provider model capabilities. `describeSupport()` may include documented ratio and size lists as discovery hints. The Gateway forwards Provider-native ratio and size options without rejecting them against those lists; Provider rejections are returned as `AI_GATEWAY_PROVIDER_REJECTED_REQUEST`. When the OpenAI-compatible adapter cannot map a requested ratio to a known pixel size, it forwards the raw ratio in best-effort form so the Provider can accept or reject it.
- JSON response mode is advertised as a discovery hint on routes with documented support, and an Application may enable it when the selected Catalog model also advertises structured output. If explicitly requested, the Gateway maps the option to the transport and returns any Provider rejection. The Application remains responsible for parsing and validating its business response shape.

## Credential and transport boundary

`provider-transport.js` resolves a generation profile through the Host-injected `getProviderProfile({ kind, provider, modelId })` port, adds provider authentication internally, fixes built-in provider endpoints from `provider-endpoints.js`, and applies operation-specific path allowlists. Verification resolves a supplied `profileRef` through a separate Host-injected resolver; the Host binds the reference to the requested model identity and releases it after the operation. No secret or Base URL enters the Plugin operation input, result, progress event, or error. A direct model request must match the Host-configured profile's model ID. Its Base URL cannot contain user info, query, or fragment; remote custom endpoints require HTTPS, while HTTP is allowed for local/private inference servers. Redirects are disabled. The API key is optional for keyless local endpoints and is used only inside the Plugin transport.

Image result downloads use HTTPS, reject literal/private destinations, check DNS results, disable redirects, require image content types, and enforce the 10 MiB limit. For failed upstream responses, the Plugin transport extracts bounded provider error code/message metadata, removes configured credentials and echoed request content, and returns it separately from the raw response body. The shared AI Generation service logs provider, model, transport, elapsed time, HTTP status, sanitized provider code/message, Gateway error code, and request ID without logging prompts or response bodies. Public failure messages remain stable and generic. This in-process Plugin boundary is not a sandbox against malicious Core code; future Community Plugin execution needs a separate trust and isolation design.

## Cancellation, progress, and errors

The Plugin receives the Host `AbortSignal`; progress is reported through the optional Host `reportProgress(event)` context function with the phases `submitted`, `waiting`, `generating`, and `downloading`. The Host adds the executing Plugin and operation IDs and validates every event.

KIE image generation submits once, polls the returned job, and downloads the completed result. The Gateway does not automatically retry generation submissions. It may make bounded retries for safe status reads and result downloads. Cancellation stops local polling/download work but does not claim that the remote KIE job stopped or that credits were refunded. Cancellation during submission can have an unknown remote outcome because the Host waits for the submission response to recover its job ID.

Public failures use stable `AI_GATEWAY_*` error codes, a retryability indicator where applicable, an optional provider request ID, and optional sanitized provider code/message metadata for diagnostic logging. Raw provider response bodies, prompts, keys, and authentication headers are not copied into logs or surfaced in the public error message.

## BlogGenius integration and migration boundary

`src/composition/blog-beta-runtime.js` is the Blog Beta composition root for the shared AI service and provides the Gateway with the Host storage port at `src/adapters/storage/ai-model-catalog/supabase-port.js`. The Plugin catalog registry validates and applies snapshots; model selection/configuration normalization is shared at `src/services/ai/model-configuration.js`. The Gateway owns refresh TTL, request coalescing, and stale-catalog fallback. `src/composition/ui-server.js` supplies existing product dependencies and passes composed services to UI runtimes. The shared Core runtime registers AI Gateway with the WordPress Publisher. Blog Writing, Card News, smart comments, keyword title generation, Agent content ideas, and Telegram text generation invoke AI through the shared AI Generation contract or a thin Application that delegates to it; they do not maintain Provider transports. Blog Beta AI manuscript generation routes text and every requested generated image through these operations regardless of image mode; manuscript draft image actions use the same image operation. Card News uses the same contract for its plan and per-card image requests, passes only model identity (never provider credentials), and preserves completed images if cancellation interrupts later work. It does not pre-reject image ratios from Gateway discovery metadata. Core no longer silently handles the combined AI manuscript path when image generation is enabled. The Plugin does not own BlogGenius prompts, licensing, manuscript state, or publication workflows.

Settings model checks use `models.verify`; the old Host-side provider checker and direct Provider text/image dispatch from `utils.js` have been removed. Provider-neutral cancellation helpers live in `src/utilities/async/cancellation.js`; AI provider request construction and transport parsing live in the Gateway Plugin. Focused tests use fake catalog/transport responses and verify dynamic catalog filtering, refresh/cache fallback, model verification, normalized text, KIE async polling/progress/cancellation, image limits, Host credential injection, and protocol route restrictions. No paid AI calls are part of the test suite.
