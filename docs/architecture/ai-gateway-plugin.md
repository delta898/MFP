# AI Gateway Core Plugin

## Purpose and ownership

`packages/plugins/core/ai-gateway/` is a provider-neutral, in-process Core Plugin for text and image generation. BlogGenius remains the Platform: its Model Catalog controls product-visible and selectable models, its Applications choose a model, and its Host owns provider credentials and network transport. The Gateway reports the routes and execution limits it implements, normalizes provider requests and responses, and owns provider-specific asynchronous job mechanics.

BlogGenius product Applications do not call the Plugin Host or depend on Gateway operation IDs. They use the shared `src/services/ai/generation.js` contract for Catalog/Gateway route intersection and provider-neutral `generateText` / `generateImage`. `src/adapters/plugins/ai-gateway.js` translates that contract to Host operations. `src/adapters/ai/gateway-transport.js` remains the Host-owned transport and credential boundary. This keeps provider credentials outside the Plugin request surface and lets Blog, Card News, and SNS share the same generation service.

The Gateway is not a REST service. Other Hosts can use the package by implementing the narrow transport dependency accepted by `createPlugin({ transport })`; that transport is not part of the public operation payload.

## Public operation contract

The package manifest declares two operations with Host-validated JSON Schema 2020-12 contracts:

- `text.generate`: `{ model: { provider, modelId }, messages, options? }` → normalized text, model identity, optional usage, and finish reason.
- `image.generate`: `{ model: { provider, modelId }, input: { prompt }, options? }` → one or more `{ mimeType, dataBase64 }` images and model identity.

The operation input does not contain an API key, endpoint, connection reference, authorization header, or BlogGenius configuration. Images are inline base64 with a 10 MiB decoded per-image limit. The Host validates output size and shape before returning results to the Application. A future Host-managed asset-reference contract can replace inline media when a concrete shared asset lifecycle exists.

`describeSupport()` is the Gateway-owned support inventory. The shared AI Generation service intersects its `kind + provider + transport + modelIds` routes with selectable entries from `getAiModelCatalog()` before dispatch. For provider `direct`, it instead intersects routes with a sanitized projection of Host-configured profiles; arbitrary caller-supplied model IDs are not accepted. It also exposes route-level option checks such as supported image aspect ratios so an Application can validate its request before starting generation. For text options with per-model Catalog flags, the shared service omits an option explicitly marked unsupported (for example, `temperature: false`) and preserves it when support is true or unknown. Blog, Card News, and SNS consume these inventories through provider-neutral contracts; none imports the concrete Gateway package. The Catalog describes BlogGenius product availability; it does not grant Gateway execution support. The Gateway inventory does not make a model selectable in BlogGenius.

## Supported routes in this release

- Text: Google Gemini generateContent, OpenAI chat completions, Anthropic's OpenAI-compatible endpoint, KIE Responses/chat routes, and user-configured OpenAI-compatible direct endpoints. KIE routes list their exact model IDs in `support.js`; standard provider routes accept Catalog IDs; direct routes accept only model IDs supplied from Host-owned configured profiles.
- The Gateway adapts shared generation options per provider. For example, it omits `temperature` from Anthropic OpenAI-compatible requests because current Claude models reject that deprecated parameter, while retaining the option for providers that accept it.
- Image: Google Gemini image generation for `gemini-nano-banana-2.1`, `gemini-3.1-flash-image`, and `gemini-3.1-flash-lite-image`; OpenAI image generation for GPT Image 2/2.5 Catalog IDs; KIE's eight catalogued async image job models; and user-configured direct OpenAI-compatible endpoints. Direct endpoints advertise no known ratio/size list by default: the Gateway makes a best-effort request using the requested ratio mapped to `size` dimensions and returns a normalized provider rejection if the endpoint does not accept it. Direct image results request inline base64.
- Image count defaults to one. OpenAI and direct routes allow up to four outputs; Google and KIE routes allow one. `describeSupport()` includes route aspect ratios when they are known, plus maximum image bytes and supported sizes per model. Google advertises `1:1`, `4:5`, and `9:16`; OpenAI advertises its supported ratios. KIE and direct endpoints accept a requested ratio without claiming a universal ratio list across model-specific APIs. A known unsupported ratio, count, or size fails with `AI_GATEWAY_UNSUPPORTED_CAPABILITY`; unknown direct ratio/size support is attempted, and an endpoint rejection is returned as `AI_GATEWAY_PROVIDER_REJECTED_REQUEST`.
- JSON response mode is advertised only on Google and OpenAI text routes, and an Application enables it only when the selected Catalog model also advertises structured output. The Application remains responsible for parsing and validating its business response shape.

## Credential and transport boundary

`src/adapters/ai/gateway-transport.js` is the BlogGenius Host adapter. It resolves configured keys and direct endpoint profiles from Host-owned `AI_MODEL_PROFILES` (with the active role configuration as fallback), adds provider authentication internally, and uses operation-specific path allowlists. No secret or Base URL enters the Plugin operation input, result, progress event, or error. A direct model request must match the configured profile's model ID. Its Base URL cannot contain user info, query, or fragment; remote custom endpoints require HTTPS, while HTTP is allowed for local/private inference servers. Redirects are disabled. The API key is optional for keyless local endpoints and is sent only by the Host transport to the configured upstream server.

Image result downloads use HTTPS, reject literal/private destinations, check DNS results, disable redirects, require image content types, and enforce the 10 MiB limit. For failed upstream responses, the Host transport extracts bounded provider error code/message metadata, removes configured credentials and echoed request content, and returns it separately from the raw response body. The shared AI Generation service logs provider, model, transport, elapsed time, HTTP status, sanitized provider code/message, Gateway error code, and request ID without logging prompts or response bodies. Public failure messages remain stable and generic. This in-process Plugin boundary is not a sandbox against malicious Core code; future Community Plugin execution needs a separate trust and isolation design.

## Cancellation, progress, and errors

The Plugin receives the Host `AbortSignal`; progress is reported through the optional Host `reportProgress(event)` context function with the phases `submitted`, `waiting`, `generating`, and `downloading`. The Host adds the executing Plugin and operation IDs and validates every event.

KIE image generation submits once, polls the returned job, and downloads the completed result. The Gateway does not automatically retry generation submissions. It may make bounded retries for safe status reads and result downloads. Cancellation stops local polling/download work but does not claim that the remote KIE job stopped or that credits were refunded. Cancellation during submission can have an unknown remote outcome because the Host waits for the submission response to recover its job ID.

Public failures use stable `AI_GATEWAY_*` error codes, a retryability indicator where applicable, an optional provider request ID, and optional sanitized provider code/message metadata for diagnostic logging. Raw provider response bodies, prompts, keys, and authentication headers are not copied into logs or surfaced in the public error message.

## BlogGenius integration and migration boundary

`src/composition/blog-beta-runtime.js` is the Blog Beta composition root for the shared AI service. `ui-server.js` supplies existing product dependencies and passes composed services to UI runtimes. The shared Core runtime registers AI Gateway with the WordPress Publisher. Blog Writing and Card News Applications invoke the Gateway for text/image generation through the shared service after resolving model identity against the Catalog/support intersection. Blog Beta AI manuscript generation routes text and every requested generated image through these operations regardless of image mode; manuscript draft image actions use the same image operation. Card News uses the same contract for its plan and per-card image requests, passes only model identity (never provider credentials), validates aspect ratio support before generation, and preserves completed images if cancellation interrupts later work. Core no longer silently handles the combined AI manuscript path when image generation is enabled. Other product entrypoints that compose text and images through `Utils`/`Core` remain migration follow-up; this Plugin does not move BlogGenius prompts, licensing, manuscript state, or publication workflows into the reusable package.

Focused tests use fake transport responses and verify model intersection, normalized text, KIE async polling/progress/cancellation, image limits, Host credential injection, and route restrictions. No paid AI calls are part of the test suite.
